## 四、部署后真机验收(★动钱逻辑必逐条验)

### 分项结算(P1,最关键)
- [ ] 跑通一场 coop 主题结算 → 查 `coop_settlement`:同 topic 有 5 类 `line_type`(PLATFORM/INITIATOR_GUARANTEE/INITIATOR_MARGIN/LEAD_FEE/MERCHANT_VERIFY);各行 amount 之和 == 总核销销售额(守恒)。
- [ ] **★发起人到账改 T+7**:结算当下发起人余额**不**即时增加(旧行为是即时);T+7 后 payout 才到账。确认没有"既即时又T+7"的双付。
- [ ] type1 俱乐部带队场:LEAD_FEE 行 merchant_id = 俱乐部主理人(非 club_id)→ T+7 → 主理人余额到账 + `ums_member_balance_detail` 明细。

### 客诉责任链(P3)
- [ ] 已支付玩家对该主题 `/api/coop/complaint/report` → 建工单;查 `coop_complaint` status=0;该主题 payout 被冻结不放款。
- [ ] 后台客服「垫付」→ 投诉玩家余额+;**对同一工单再点垫付应被拒**(不重复打款)。
- [ ] 「关闭」认定过错方+扣划 → 过错方余额-;工单 status=3;该主题 payout 解冻下轮放款。
- [ ] 越权验证:**非本主题/已退款用户** report → 应报"仅本主题已支付参与者可投诉",不能冻结。

### 运营权委托(P2)
- [ ] 承接给俱乐部的带领场:**承接俱乐部主理人**能发车/放行/核销;发起商家不能(领队=主理人)。
- [ ] 承接方运营编辑 `/api/clublead/edit-ops`:**领队(承接主理人)**能改集合时间/地点/结束时间/当日备注;**非领队改被拒**;票价/奖励/结算等核心字段不在白名单不受影响。

### 移交承接 + 双署名(P3,含前端)
- [ ] 发起人对自己主题 `/api/topic/transfer-to-club`(topicId+clubId)→ 生成一份**新草稿**(原主题不动),新草稿 member_id=发起人本人、club_id=承接俱乐部;由发起人配为城市定向(mode=1·有人带)后邀该俱乐部承接。
- [ ] 越权:**非主题创建者**调 transfer-to-club → 报"无权移交该主题",不产生复制。
- [ ] **★门禁**:选一个**与本人无合作关系**的俱乐部移交 → 报"需为该俱乐部主理人,或先获得该俱乐部的合作邀约通过"(防绕过 coop 门禁假挂他人俱乐部)。
- [ ] **前端**(小程序 topic 详情):**主题创建者**打开自己主题→署名区下方见「移交给俱乐部承接」按钮(`info.isOwner==1`);非创建者不可见。点→选承接俱乐部→确认→成功后引导去配置新草稿。
- [ ] **双署名**:承接俱乐部的主题详情署名区,「发起人」下多一行「{俱乐部名}·承接带队」(`info.clubName` 由后端 info-to-user 回填)。

### 其它
- [ ] 附近商家:后台录一条 merchant_lead(带电话+经纬度)→ 小程序 coop/nearby 定位查到 → 商家身份可拨号,玩家看不到电话。
- [ ] UGC门禁:发帖/评论带违规词→拦;带图→待审(status=0 仅作者可见)。
