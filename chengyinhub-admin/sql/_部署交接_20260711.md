# 部署交接清单(2026-07-11)

## ⚠️⚠️ 部署事故与解决(2026-07-11,务必先读)
**现象**:传新 jar 重启后全站 502 约 20 分钟,应用崩溃循环(宝塔守护每 6 秒重拉一次)。
**根因链**:
1. 本批 Gate A 安全硬化(commit `4a61fcc5`)新增了 bean `WithdrawalPiiProtector`,构造器 `@Value("${withdrawal.pii.key}")` → yml 映射 `${CHENGYIN_WITHDRAWAL_PII_KEY}` **无默认值**(fail-closed);该 bean 总是被实例化(注入 UmsMemberWithdrawalServiceImpl)。
2. 服务器没设这个环境变量(它是本批**新增的必填启动密钥**,旧 jar 从没有过)→ 占位符解析失败 → bean 建不出 → **整个应用启动失败**。
3. 宝塔"守护进程"用**旧启动命令原样重拉**,不会带上面板新加的环境变量 → 崩溃循环。
**解决**:在 jar 旁放外部配置覆盖(不依赖环境变量,守护重拉也能读到):
```bash
mkdir -p /www/wwwroot/bin/config
# /www/wwwroot/bin/config/application.yml:
# withdrawal:
#   pii:
#     key: "<base64 32字节AES密钥>"   # openssl rand -base64 32
```
放好后守护进程下次自动重拉即读到,`/prod-api` 返 200。**此 key 一旦有提现数据加密就不可更换,已备份于服务器该文件**。
**教训**:①本批引入了新的必填启动密钥,部署前应作为"新增环境变量"清单项显式处理;②`WithdrawalPiiProtector` 的 fail-closed 卡在**整个 app 启动**级别,而提现功能尚未上线→一个未上线功能 brick 全站,应改成"缺 key 时照常启动、仅在写提现资料时拒绝"(待重打 jar);③宝塔改环境变量后必须**面板停止→启动**重新生成启动命令,守护重拉不生效。

## 二、迁移(必须先于 jar,只跑 prod 里「未落」的)
先在 prod 逐项 `SHOW COLUMNS` / `SHOW TABLES` 确认,再决定跑不跑。**带 ⚠️ 的是非幂等或有陷阱,重复跑会报错。**

| 迁移文件 | 类型 | 幂等 | 跑的条件 |
|---|---|---|---|
| `migration_withdrawal_pii_encryption_20260710.sql` | ALTER ADD 9 列(*_enc/*_mask/pii_cipher_version)于 ums_member_withdrawal | ⚠️否 | 仅当这些列不存在时跑;已存在会 `Duplicate column` |
| `migration_coop_settlement.sql` | CREATE TABLE IF NOT EXISTS(含 verified_reg_ids) | 见陷阱 | ⚠️**陷阱**:文件只有 CREATE,没有独立 ALTER。若 coop_settlement 表**已存在**(早前 coop 若曾部分部署),`IF NOT EXISTS` 会跳过→verified_reg_ids **不会补上**→T9 代码 `Unknown column`。此时须手动 `ALTER TABLE coop_settlement ADD COLUMN verified_reg_ids TEXT NULL;` |
| 其余 coop 表族(coop_invite/coop_deposit/coop_order_perk_credit/coop_perk_template/coop_review/coop_deadline_sysjob) | 早前提交,可能从未上 prod | 多为 IF NOT EXISTS | jar 含全部 coop 代码;若 coop 从未部署,这些必须一并先落,否则 coop 接口全崩。逐个 SHOW TABLES 确认 |
| `migration_c1_per_member_limit.sql` | ALTER ADD sms_coupon.per_member_limit | ⚠️否 | 仅当列不存在时跑 |
| `migration_c3_reward_pending.sql` | CREATE TABLE IF NOT EXISTS reward_pending | 是 | 可直接跑 |
| `migration_r10_merchant_city_nodes_quota.sql` | 商家据点配额 | 核对 | 若 citynode 批未部署则需跑 |
