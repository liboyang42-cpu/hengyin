## 作者配置接口

现有主题创建/修改接口（含 V2）DTO 增加 `themeRuntimeConfig`，值为 JSON 字符串。编辑详情回读同名字段。`null`/不传保留已有值，空字符串清空草稿配置；发布后原编辑窗口限制仍适用。发布将草稿复制到 `published_theme_runtime_config_json`；开局再冻结版本、场景、剧情与节点玩法。旧局不读取新草稿。

完整可读示例见 `frost-solo.draft.json`，必须先按 `frost-bindings.json` 绑定真实城市节点、图片、状态键、玩法模板和人物。草稿允许缺图片/名称，正式发布不允许；不得把节点别名 1..7 或空图当成上线素材。

配置字段：

| 字段 | 说明 |
|---|---|
| schemaVersion | 当前固定 1 |
| capacity | 物品容量，启用目录时 1..999；无目录可省略 |
| hpName / luckName | 显示名称，复用原 sys.hp/sys.luck，最多 20 字 |
| items | 最多 200 项；id/name/image/kind；ITEM 再配 stat=HP/LUCK、delta=-999..999 非零、wear 和 mode=ONCE/HELD |
| grants | 来源 NODE/CHOICE/DRAW/ENDING；目录 itemId 和 quantity；可信节点、选项或实际随机结果绑定；可配 when |
| events | 条件广播，content、when、grants，以及注册剧情状态的 SET/INC 后果；每局一次 |
| scenes | id/name 与场景 grants/events/endings/journeyStory/nodeConfigs，未覆盖字段继承根配置 |
| rotation / currentScene | FIXED/ROUND_ROBIN/WEEKLY；ROUND_ROBIN 按该玩家同活动同主题的游玩次数，WEEKLY 按 UTC 周一与 rotationAnchor 毫秒锚点；开局冻结 |
| replayEnabled | 是否允许已结束当前局重玩 |
| actionLimit / actionSources | 预算与 NODE/CHOICE/DRAW 计数来源；不配置预算则不启用；寒冬草稿只数完成节点 |
| rescueLimit | 0..10，默认 0；恢复量复用 journeyRules.recovery.exhaustRestHp |
| endings | 条件、优先级、成功标志及 reasons；至少且仅一个 fallback；条件在终局发放前计算 |
| card | cover、fields、showUnlocks；字段允许 scene/ending/hp/luck/actions/medals/items/story/rescue |

`when` 是 AND 数组；支持 ITEM_HELD、ITEM_ACQUIRED、NODE_COMPLETED 与原 EQ/NE/GT/GTE/LT/LTE。剧情状态必须注册为 clue/relation/counter，事件不能任意修改 sys 属性。ENDING 发放可筛选 endingId、reasons、success；默认只在成功结束发放。终局发放属于结果结算阶段，不反向更改先前命中的故事结局；终局赠品的穿戴效果会反映在结算指标中。

MEDAL 只收藏，无使用/丢弃/穿戴效果。主题目录不能使用 `legacy_` 前缀；它用于旧通关章和实际名次奖牌映射。普通物品每次使用或丢弃一件；获得数量可配置。

## 玩家接口

均复用登录态与 AjaxResult，会员身份不接受客户端传入。客户端不能直接设置生命/幸运、库存或抽奖结果。

| 方法/地址 | 入参及返回 |
|---|---|
| GET /api/play/theme/state | topicId、activityId（自玩 0）、可选 sessionId；不传局 ID 恢复/建立当前局，传局 ID 读取本人指定局；返回 version、sessionId、playInstanceId、实际库存、pending、events、broadcasts、hp/luck、名称、状态和结果 |
| POST /api/play/theme/action | sessionId、expectedVersion、actionId、operation、contentId；operation=USE/DISCARD/RECEIVE/RESCUE/END；RECEIVE 的 contentId 取 pending 中已冻结来源 ID，USE/DISCARD 取目录 ID |
| POST /api/play/theme/replay | sessionId；仅本人当前已结束局，按已发布配置建新局；同旧局重复请求返回同一个新局，不连续开多局 |
| GET /api/play/theme/history | topicId、可选 beforeSessionId、limit（1..100）；按局 ID 倒序，用上一页末条 sessionId 继续取更早历史 |
| GET /api/play/theme/card | sessionId；只有本人已结束局；返回公开字段投影，不返回完整存档；本人全历史已解锁结局只显示 ID/标题；nextScene 是当前已发布安排，可能随安排变化，不属于旧局不可变结果 |

原有只传 topicId 的旧接口保留“该会员该主题最新局”的语义；新界面读取指定历史局应使用本节 sessionId 接口，不通过旧入口修改历史。

动作 version 过期返回 409，应读 state 再让玩家决定是否继续操作；同 actionId、同内容重试返回原回执，复用 actionId 换操作或内容拒绝。已结束局禁止使用/丢弃/领取/救援；重复 END 可读原结果。

有可用救援次数且生命归零时，state.awaitingRescue=true，允许 RESCUE 或 END；恢复不重置预算、库存或进度。次数耗尽则固定耗尽结果。完成路线而成功条件不足保存 ENDED 与 reason=COMPLETED，success=false，不计主题通关。结果数据冻结后不再次求值或发放。

既有高级玩法服务仍负责判题、选择与抽取，再把可信事实交给主题运行时。节点仅到达不发完成物资，必须有本局完成凭证。复用旧背包读接口时新增 theme 子对象，旧券、节点奖励字段继续保留。

## 穿戴与默认规则

实施暂采用以下简单默认值，属于本期可审阅默认实现，并非声称用户已逐条确认：物品每件占一格，穿戴也占格，勋章不占物品格；不同来源数量累加，同种持续效果按持有件数叠加；无实际数值变化时普通使用不消耗；关闭对应属性拒绝效果。待领取按整批领取，需整批容量足够；最终结果固定后不能再补领。

ONCE 在合法收进背包时改变一次数值，丢弃不撤回。HELD 将基础值、请求修正和实际受上下限影响的贡献存入本局；持有量不变时刷新不会重做加减。原生扣减继续作用当前值；丢弃时仅解除该件持有修正并钳制上下限，避免满值穿戴在受伤后自动补血。它不是定时回血或额外减耗比例；家的原减耗规则另接。

重玩沿用现有报名/资格验证；每局路线、进度、随机会话和去重独立。平台积分、券、成长值、平台徽章及排名奖牌不因重玩重复领取；主题局内普通收藏可以按新局条件再次获得。现有平台奖励的确认和商业重复领取政策尚未另行变更。

## 广播复用与恢复

人工俱乐部导演广播、队长置顶广播及其权限保持原入口。单人自动主题事件复用 IImService.sendSystemInNestedTransaction，不授予玩家人工广播权限。事件后果与待发送记录在同一事务；消息失败只更新 FAILED，读取本人 theme/state 时最多处理 20 条、每条自动重试最多 5 次。REACHED 表示站内消息已生成，不代表设备通知或玩家已读；本期未接订阅推送。事件记录即使消息失败仍可从本人局存档回看，不因重投重新执行物资或状态后果。
