## 1. 背景:这是什么产品、这页是什么角色

- 产品是**基于真实地点的 Citywalk / 景区解谜打卡游戏**。玩家在城市/景区里走,走到点位 → 解锁 → 玩一个小游戏 → 完成 → 拿奖励,一路被剧情串起来。
- **本页造的是一个"游戏(关卡)"** —— 一个可复用、地点无关的玩法单元。它之后会被放进某条"主题/路线"里,在那一层才绑定具体地点、坐标、所属商家/景区。
- 创建者主要是**商家 / 景区运营 / 平台运营**。
- ⚠️ **地点不在本页设计**:扫码内容、GPS 坐标、绑定哪个商家——都属于"主题/路线"层,不要在这页出现选地图/选点位。

---

## 2. 用户与使用场景

| 维度 | 说明(影响设计权重) |
|---|---|
| 谁用 | 商家/运营,非专业玩家;有一定耐心但怕复杂 |
| 主要场景 | ① 全新创建一个游戏;② **基于已有游戏复制后改几个字段再发布**(高频);③ 续编草稿 |
| 设备 | 微信小程序,竖屏手机,单手操作为主 |
| 频率 | 中低频、单次投入较重 → 需"能存草稿、能预览、不丢失" |

---

## 3. 重设计目标(设计师要解决的问题)

本页旧版被判定"体验差",需要重做。设计目标按优先级:

1. **把核心玩法表达清楚(最重要)。** 一个"游戏"的灵魂是"玩家怎么过关(完成方式)+ 完成给什么(奖励)"。旧版把它藏在浮层里、默认空配置,导致产出"空壳游戏"。新设计必须让"完成方式/奖励"**显眼、好懂、好配**。
2. **降低长表单的认知负担。** 字段多 + 模块多,需要清晰的分区、信息层级、可扫读。
3. **编辑友好。** 大量用于"改已有游戏的一两个字段",要好定位、好改、状态清楚。
4. **发布前必看预览。** 创作者要能看到"玩家会看到什么",再决定发布。
5. **统一、专业的视觉语言。** 命名统一为"游戏";必填/选填规则一致;错误提示清晰。

> 旧版的具体问题(供设计师理解痛点,不必照着改):核心机制藏浮层、标题显示两遍、分区导航失效、必填规则自相矛盾、错误一次只报一个、命名混用"游戏/活动/主题/模板"、无预览无草稿、布局会跳。

---

## 4. 信息架构(必须包含的内容区块及优先级)

> 以下是**内容结构与优先级**,不是布局规定。设计师可自由决定单页/分步/折叠/吸顶等形式。

```
A. 顶部:游戏封面图 + 游戏标题(标题全页仅一处)
   └ 编辑态额外:「N 人使用」只读信息
B. 区块导航(可选的辅助定位):基本信息 / 规则 / 模块
C. 基本信息(固定区)
D. 游戏规则(固定区)
E. 游戏模块(可加可删,核心区):
     完成方式 · 完成奖励 · 剧情故事 · 提示 · 语音讲解
F. 底部主操作:查看预览
G. 预览(玩家视角)→ 保存草稿 / 发布游戏
```

**优先级排序(视觉权重建议):** 完成方式/奖励(E,核心)≈ 标题/封面(A) > 基本信息(C) > 规则(D)、其余模块 > 区块导航(B)。

## 5. 完整内容清单(字段级)

> 说明:必填用 ●,选填用 ○。"数据来源=字典/接口"表示选项是后端动态返回的,**长度不固定**,设计需容纳变长。

### 5.1 顶部
| 内容 | 类型 | 必填 | 规则 / 文案 | 数据来源 |
|---|---|---|---|---|
| 游戏封面 | 图片上传(单张) | ○ | 点击上传/替换;未传时显示占位图 | 用户上传(OSS) |
| 游戏标题 | 单行输入 | ● | 入口页已预填,可改;非空 | 入口带入 |
| N 人使用 | 只读文本 | — | 仅编辑已有游戏时显示 | 接口 |

### 5.2 基本信息(固定区)
| 字段 | 类型 | 必填 | 规则 / 占位文案 | 数据来源 |
|---|---|---|---|---|
| 游戏描述 | 多行输入 | ● | **≤30 字 + 实时字数计数器**;占位「描述玩法、目标和特色…」 | — |
| 玩家人数 | 下拉选择 | ● | 占位即首项 | 字典 `app_template_players` |
| 游戏时长 | 下拉选择 | ● | 同上 | 字典 `app_template_duration` |
| 游戏难度 | 下拉选择 | ○ | 不强制 | 字典 `app_template_difficulty` |
| 适用场所 | 单行输入 | ○ | 占位「例如:咖啡馆」 | — |
| 所需材料 | 单行输入 | ○ | 占位「例如:游戏卡」 | — |
| 游戏类别 | 标签多选(跳选择页) | ● | 至少 1 个;已选项以可删除标签展示;入口「添加类别」 | 选择页 `biaoqian type=4` |

### 5.3 游戏规则(固定区)
| 字段 | 类型 | 必填 | 文案 |
|---|---|---|---|
| 规则说明 | 多行输入(自适应高度) | ○ | 占位「详细说明游戏规则、流程和注意事项…」 |

## 6. 游戏模块详规(核心区)

**模块机制:** 每个模块"可添加、可删除";未添加的出现在「添加模块」清单里;添加后成为一张可就地配置的卡片。每种模块**最多一个**。设计需覆盖:① 空(一个都没加)② 已加若干 ③ 「添加模块」选择态 ④ 删除确认(建议)。

### 6.1 完成方式(玩家如何过关)—— 核心
- 单选一种方式(分段/单选形态由设计定),选中后**就地展开**对应配置:

| 选项 | 选中后需要配置的内容 | 备注 |
|---|---|---|
| 文字问答 | 问题 + 正确答案(各一行输入) | |
| 选项问答 | 问题 + 2~4 个选项(可增删)+ 指定正确项 | |
| 拍照打卡 | 可选:拍照要求描述(≤50 字),占位「可选:拍照需包含的元素描述,例如『门牌+本人』」 | 玩家拍照即完成,后台可后置人工审核 |
| 扫码打卡 | 无(提示「扫码内容在主题/路线层绑定」) | |
| GPS 到达 | 无(提示「GPS 坐标在主题/路线层绑定」) | |
| 无需验证 | 无(提示「玩家到点即完成」) | |

### 6.2 完成奖励(完成后给什么)—— 核心
- 三类奖励,**可单独或组合**配置:

| 奖励类型 | 配置内容 | 数据来源 |
|---|---|---|
| 优惠券 | 从「我的优惠券」选一张(带搜索) | `/api/coupon/mypublishlist` |
| 文字反馈 | 一段完成文案 | — |
| 勋章 | 上传勋章图 + 勋章名称;可清除 | 用户上传 |

### 6.3 剧情故事(到达点位时的叙事)
| 内容 | 类型 | 规则 |
|---|---|---|
| 剧情文案 | 多行输入 | 建议 ≤300 字 + 计数器 |
| 剧情配图 | 图片上传(单张) | 可选、可清除 |

### 6.4 提示(防玩家卡住劝退)
| 内容 | 类型 | 规则 |
|---|---|---|
| 提示一 / 提示二 | 单行/多行输入 | 1~2 级,逐级解锁 |
| 兜底答案/解析 | 多行输入 | 可选,最后可看 |

### 6.5 语音讲解(景区边走边听)
| 内容 | 类型 | 规则 |
|---|---|---|
| 音频文件 | 文件上传 | 单个;显示已上传状态、可替换/清除 |
| 时长(秒) | 数字输入 | 可选,展示用 |

## 7. 状态清单(每个状态都要出设计)

| 状态 | 说明 |
|---|---|
| 空态(全新创建) | 标题已预填、其余为空、模块区只有「添加模块」入口 |
| 填写中 | 各字段有值 |
| 编辑已有 / 复制 | 全字段回填、模块按已有配置展开、显示「N 人使用」 |
| 草稿续编 | 同编辑态,但来源是草稿 |
| 校验错误 | **行内错误**(字段下方红字)+ 提交时滚动到首个错误;不要只用全局 toast 逐条报 |
| 上传中 | 封面/勋章/剧情图/音频上传的加载态 |
| 提交中 | 发布/存草稿按钮的 loading + 防重复点击 |
| 预览态 | 玩家视角(见 §8) |

## 8. 流程与预览

**入口来源:** 「创建游戏」起名页(带标题)/ 游戏详情(复制)/ 我的游戏(编辑/草稿)。

**主流程:** 编辑 →(点底部「查看预览」)→ **玩家视角预览** →「返回修改 / 保存草稿 / 发布游戏」。

**预览内容顺序(还原玩家体验):**
`封面 + 标题 → 剧情故事(若有)→ 语音讲解(若有)→ 挑战(完成方式)→ 提示入口 → 完成后奖励`

**质量软提示(不拦截):** 若没加「完成方式」,预览顶部提示「该游戏没有过关方式,玩家会直接通过——确定吗?」。

**校验时机:** 「发布」走全量校验;「保存草稿」仅校验标题非空。

## 10. 平台与技术约束(设计须知)

- **微信小程序**,非 Web。组件能力以小程序为准(`picker` 下拉、`textarea` 自适应、`switch`、原生上传/扫码/定位/录音播放)。
- **已有设计 token 体系**:项目使用 `--cy-*` CSS 变量(文字色、背景、字号等)。设计师应**沿用或扩展现有 token**,保持与小程序其它页面(首页、达人页、我的页等)一致的视觉语言,而非另起一套。建议向我或前端索取现有 token 清单与既有页面截图作参照。
- 性能:长表单 + 图片/音频,注意首屏与上传反馈。
- 不做 AR;扫码/GPS 仅声明类型,不在本页落地。

---

## 11. 数据 / 接口契约摘要(便于设计判断"哪些是变长动态内容")

- 动态下拉(长度不定):玩家人数、时长、难度 ← 后端字典。
- 类别:跳独立选择页多选,回填为可删标签,数量不定。
- 优惠券:来自「我的优惠券」列表,可搜索,可能为空(需空态)。
- 草稿:有 `草稿/已发布` 两态,列表与本页需能区分(列表页设计另议)。
- 其余玩法字段(剧情/提示/拍照/语音)为本页录入,后端已支持存取。
