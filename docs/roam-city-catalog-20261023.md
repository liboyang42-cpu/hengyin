# 城市漫游目录与地图布点交接

本次给漫游入口增加「城市清单」，按城市和分类浏览、点开详情，能复制地址和资料来源。首批 11 城、33 处内容随小程序提供，不依赖附近活动接口成功或定位授权。用户主动浏览的远方城市不改动当前漫游锚点、定位、轨迹或会话。

## 分类与身份

- 展示分类：宝藏街道、推荐店铺、公园绿地、文化地标。
- 后端业务类型继续保持 type=1 平台地点、type=2 商家据点。
- 平台地点通过 tags 中的保留标签 roam:street / roam:shop / roam:park / roam:landmark 指定展示分类。
- 推荐店铺的业务类型是 1，沿平台地点确认到点链路，不进入商家探店、集章或领券链路。
- type=2 沿用原有业务链；只有 merchantId 是有效正整数时显示「合作商家」，无关联显示「商家据点」。分类标签不能把它改成平台地点。
- 旧地点没有分类标签时保持地标展示，不按名字猜测「公园」或批量回填身份。
- 非商户的 description 仍不作为审核后的「地点记忆」展示；地点意义沿用独立内容审核链。

## 首批数据与核验边界

数据文件：chengyinhub-xcx/subpackageRoam/data/roam-city-catalog.js（随 subpackageRoam 分包下发，不进主包；目录组件、地点卡的理由/来源组件同在该分包，漫游页经 componentPlaceholder 异步引用）。

上海、北京、杭州、成都、西安、重庆、深圳、广州、武汉、香港、厦门，每城 3 处；11 段街巷/步道、11 处公园、4 处推荐书店/茶馆、7 处文化空间。已排除停业信息冲突的不在书店，避免把 A4 美术馆旧址、香蜜湖公园和香蜜公园混用，也未收录晓港公园已停业的旧游乐场项目。

每条保留稳定 ID、城市、类别、地址、原创推荐理由、标签、到访说明、两个来源链接和公开资料核对日期。收录依据是公开资料交叉核对，不是实地探访；不声称实时营业、人少、免费或已成为合作商家。目录界面明确显示核对日期和来源，并提示以经营方或管理方最新公告为准。

首批坐标一律为空，不把街区中心或猜测坐标变成可领取奖励的地图点。目录已可浏览和复制地址，但这些条目不会凭空成为已上架的附近点位。

## 地图布点工具

工具只在本机编译 SQL，不连接数据库、不自动发布。没有新依赖，没有新增表或列。

生成坐标核验模板：

```sh
node scripts/roam-catalog-import.js --template > /tmp/roam-coordinate-review.json
```

运营用腾讯/高德地图逐条确认同名门店、城市、地址、可公开到达的入口，填写 provider、providerPoiId、verificationSource、lat、lng、verifiedOn，并在确认匹配后设置 matchConfirmed=true。坐标必须由地图服务明确返回为 GCJ-02，不猜测坐标系、不自动偏移转换。街道和大型公园的入口必须适合步行，不使用几何中心代替。

按一个城市编译待审核数据，例如：

```sh
node scripts/roam-catalog-import.js --coordinates /tmp/roam-coordinate-review.json --city SH --output /tmp/roam-sh-review.sql
```

未确认、缺失、重复、过期超过 90 天、未来日期、坐标系错误、跨城或名称地址不一致的记录会拒绝生成。模板中的空值不会变成 0,0。输出文件使用独占创建，不覆盖已有文件。

SQL 将新点位设为 status=0（下架）、type=1、无 merchant_id/template_id/coupon_template_id，沿用平台地点探索值配置。种子标识写入 tags，顺序重跑不重复导入；不覆盖旧地点、已有归属或已下架状态。SQL 附带回读，执行前需在隔离测试库确认现有列、同名重复点和生成语句。并发执行不受此种子标签的唯一约束保护，须由单个运营者串行执行。

数据上线继续使用仓库既有迁移/运营审核路径：核对同名点、入口与来源 → 测试库执行和回读 → 按生产变更流程执行 → 后台审核上架。直接连生产数据库及绕过审核均不属于此工具。商家认领、互动模板、优惠券仍走原有申请审核流程。
