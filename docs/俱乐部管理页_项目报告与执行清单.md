## 一、背景与目标

俱乐部(club)在系统里已是独立角色,具备 `club` 表、`club_member` 表、申请→后台审核流程,以及小程序端申请页 `pages/club/apply/index`。但**审核通过后没有自己的管理首页** —— 商家有 `pages/merchant/index/index`,玩家有 `pages/index/index`,俱乐部缺一个并列的管理入口。

本项目为俱乐部补齐独立管理首页,让主理人能:维护资料、管理成员、管理主题/活动、发券核销、查看财务、查看数据曝光、参与招募广场。**本版所有功能全部纳入,不做阶段性删减。**

---

## 二、身份模型决策(已确认)

**三者完全分开、互斥。** 账号 `ums_member.role` 只能是 `player` / `club` / `merchant` 之一:

- 俱乐部账号登录后**只看俱乐部管理页**,不串玩家、不串商家。
- 想以普通玩家身份逛/报名别人活动,需另开账号。
- **不加多角色、不加表、不动现有 RBAC 架构。** 改动最小,贴合现有单 `role` 字段模型。

---

## 三、角色能力(权限表为准)

依据 `user_permission`(migration_rbac_role.sql),**俱乐部是权限最全的角色**:

| 角色 | 主题 | 活动 | 优惠券 | 建主题 | 建活动 | 发券 |
|---|---|---|---|---|---|---|
| player | 1 | 2 | 1 | ✓ | ✓ | ✓ |
| **club** | **5** | **3** | **3** | ✓ | ✓ | ✓ |
| merchant | 0 | 0 | 3 | ✗ | ✗ | ✓ |

俱乐部首页功能 = **商家功能(发券/核销/财务/招募广场)+ 内容创建(主题/活动)+ 成员管理** 的并集。

## 四、路由与入口

- 首页 `pages/index/index.js`(当前 `isMerchantView()` 仅判断商家,line 6-8)新增并列分支:
  `role == 'club'` 且审核通过 → `wx.redirectTo('/pages/club/index/index')`,逻辑照搬商家分支(含 `debug_user_view` 调试覆盖)。
- 新建 `pages/club/index/index`,与 `pages/merchant/index/index` 平级,**以商家首页为模板克隆**,沿用同一套设计语言(`topBar`、信息行、数据卡、`cy-section-header`、九宫格、列表卡、wxss)。
- `app.json` 注册新页面;`app.js` 已有 `role` 存取,无需改。

## 六、后端接口清单(全集)

**新增接口:**
1. `/api/club/update-mine` —— 编辑已通过俱乐部资料(校验 memberId==club.memberId,仅改展示字段)。
2. `/api/club/dashboard` —— 统计卡:成员数 / 主题数 / 活动数 / 曝光量(参照 `ApiMerchantController#getDashboard`,曝光复用 `TmsBrowseRecord` 聚合)。
3. `/api/topic/list-to-club` —— 招募广场(俱乐部可参与的主题列表,对标 `list-to-merchant`)。
4. `/api/registration/club/list` —— 我的参与(俱乐部报名记录,对标 `registration/merchant/list`)。
5. club 版"实时动态"数据(成员加入、报名等事件流;可基于 `club_member`/`CmsRegistration`/`BizEventLog` 聚合)。

**需核对(实现时):**
- `/api/coupon/verification` 核销按券归属(memberId)校验、接受 club;若写死 merchant 则放开。
- `/pages/member/coupon/coupon`、`/pages/role/center/index` 在 club 身份下取数正常。

**复用、无需改:**
- `/api/club/members`、`/api/club/remove-member`、topic/activity 列表与创建接口。

**数据库:无 schema 改动。**

---

## 七、关键决策(已确认)

- **club 版招募广场/我的参与接口:新做独立 club 接口**(`/api/topic/list-to-club`、`/api/registration/club/list`),不动现有商家接口 —— 改动隔离、不影响商家、无回归风险。
- **曝光量口径:账号 + 其名下主题/活动的浏览记录数汇总**(更能反映俱乐部热度)。
- 资料编辑页(复用 apply 表单 vs 新建 edit 页):实现时定,不影响接口设计。
