## 根因与修复

- 整单核销最终经过 `CmsRegistrationMapper.verifyIfNotVerified`，但原 SQL 不识别活跃人工退款工单。
- 章节核销更危险：`redeemExploreChapterAndRecord` 先扣权益/配额，再调核销 CAS，且忽略 CAS 返回值。只改最终 UPDATE 会留下“核销标志没变、但章节已消费”的半态。
- 修复保留两层共享防线：
  - `verifyIfNotVerified` 的原子 `UPDATE` 增加活跃工单 `NOT EXISTS`，覆盖所有整单核销入口。
  - 章节核销在扣权益前调用 `hasActiveManualRefundCaseForUpdate`；单条 `LEFT JOIN ... FOR UPDATE` 与工单创建共用 registration 行锁。
- 实际状态机中 `NO_REFUND` 是唯一不退款终态；其余工单状态继续冻结。
