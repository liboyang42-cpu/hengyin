# 三包共同规则

本轮只修小程序实际已有消费者及共用后端的确定底层断点。新增内部锁、事务、收据和补偿不是新用户功能，可以用现有规则下最小实现；推荐等后批底层也保留原项。新UI、页面、玩法、群聊、旧搭子局和新增经营/付费产品后置。

## 不需要再询问的规则

- 探店日/自由探索订单 `purchaseKind=3`：活动结束即禁止新使用；未用票过期不算核销。缺结束时间暂不出码或核销，补齐恢复；旧7天自动核销规则废止。保持真实历史、原退款/库存/应收规则。
- 路线自玩资格过期后拒绝新文字/语音问NPC，有效续购恢复；历史聊天仍可读。
- 失效/私密历史路线卡和摘要隐藏名字，显示“路线已不可用”，保留ID；不改变正常详情权限或原消息/指纹。
- 草稿本人可读，公开帖正文可公开。没有明确授权的编辑历史权限不擅自扩大或收紧。
- AI明确服务故障退本次次数，明确违规不退；未知及REVIEW_REQUIRED保原规则，不能猜结果。
- 漫游结束后只补原行程此前采集记录，不重复奖励或改已结算账。清本地缓存全部删本范围未同步和待核恢复记录并放弃恢复；迟到回包不重建已清记录，不撤销服务端已发生写入，不清无关鉴权信息。
- 小程序消息/私信源码存在，但群聊type4排除，旧搭子局下线；只修实际消费者，线上启用另验。

现有限购、退款、赔偿、分账、评分、公平曝光及权限政策保持。未确定的新政策、新配额和新业务流程列为后置子项，不为了“整项完成”自行定规则。技术问题自主查源码、修编译/测试、记录运行断点，不把它们当产品问答；用户不需要重复确认已定规则。

## 分包与协作

你不独占代码库，不回退其他任务修改。三任务都从交接分支开始，分别建立独立分支，不强推、不合并master、不部署。先读OWNERSHIP，再生成本包合同（方法、字段、锁序、调用方、文件清单）写到 `docs/verification/mini-foundation-cloud/<包>/contract.md`，然后编码；不必等待用户审批常规实现。

原EXECUTION按业务领域分类；本轮并行以文件所有权优先：

- A拥有订单、支付、票/券、库存、分账/提现、订阅，以及报名通知触发点。`RegistrationCheckoutServiceImpl`属于A。
- B拥有消息、隐私审核证据、analytics事件队列与指标、实际广场分页及推荐消费者核对。C5/C9这部分由B实现，避免与C同时改消费者。
- C拥有AI、NPC、玩法、草稿和漫游定位/落盘/补传/奖励交付。`ApiRoamController`、`RoamMapper`以及原漫游消费者全部属于C。
- 原奖励券的发放Service/Mapper由A，漫游发现/结算触发点由C。报名业务触发点由A，消息投递层由B。跨包只提交调用合同/补丁说明，不越界编辑共享文件；在本包中继续其他独立工作，集成时由所属包补调用。
- B只拥有NPC静态契约测试修正文件；NPC生产调用方属于C，票务资格真源PlayTeam/报名查询由A。B不得为了测试绿改NPC生产权限。

新文件命名和测试归本包业务所有者；通用框架、公共依赖、CI工作流和跨域方法变化不能抢改。共有审计Service由B，A/C调用既有方法；已有审计触发点随原业务文件所有者。

不得读写生产库、做生产迁移/部署/上传微信、关闭安全校验、引入假用户或免验证接口。不要新加依赖、改Redis/JWT配置、重构鉴权/RBAC或做跨模块大改；确定修补复用现有API、Mapper、事务及任务。新的测试migration可以实现并在测试目标验，生产DDL不在授权范围。

使用现有返回包装和实际API。资源变更/锁/事务/身份/配额/新解析都补有意义的红绿或assert验证；核实际JUnit用例数（JUnit5若未被默认runner识别，用现有显式Surefire配置或3.2.5插件运行，不把0个用例算绿），不能用测试进程退出0、HTTP200或JSON字段存在替代业务结果。真实数据库用独立连接回读，未实跑写未实跑。193等历史通过数不能转移给你的新提交。

用原请求/原对象身份及当前状态恢复，未知不能盲重发或造新对象。队列/扫描/补偿单项故障不阻断后页；退款/奖券/XP/库存副作用必须只发生一次。保持已提交PAYING扫描、同意、普通草稿顺序、NPC当前资格和消息状态锁。
