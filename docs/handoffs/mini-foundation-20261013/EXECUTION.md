## 已确定规则

| 对象 | 实施规则 |
|---|---|
| 探索票 | 活动结束即不能新使用；未用票过期不记为已核销。缺活动结束时间暂不出码或核销，补齐后恢复。判定 `now >= end_date` 即到期；保留真实历史使用，不自动改变退款、库存或商家应收。旧“结束 7 天自动核销”已废止。 |
| NPC 自玩权益 | 通行证过期停止新文字、语音提问；有效续购后恢复；保留历史聊天查看。用权益有效期判断，不用未付款订单支付期限替代。 |
| 草稿和公开帖 | 草稿只给本人；发出的公开帖可公开读取。公开帖编辑历史的额外权限范围若无明确现有合同，不擅自收紧成仅成员。 |
| 消息已读 | 当前已有消息消费者按会话及当前成员状态校验，不能恢复旧未读状态。此前已批准的关闭群/退出规则是共用后端修补记录，群聊不进入小程序新功能范围。 |
| 历史路线卡与摘要 | 路线删除、下架或私密后，隐藏名称，显示“路线已不可用”，保留原引用 ID；私密历史投影同样隐藏，不修改正常路线详情访问规则。 |
| AI 输入审核 | 服务超时、故障退本次生成次数；确定违规不退。未知审核结果沿用既有待核规则，不伪装成明确违规或成功退款。 |
| 漫游结束后的轨迹 | **允许将之前采集但未确认上传成功的轨迹补回原行程，只补记录；不重复奖励、不改已结算账。** |
| 用户清理本地缓存 | **全部删除，包括未同步轨迹及待确认请求的本地恢复记录，并放弃这些记录的恢复。** 清理不代表撤销已经发生的服务端写入，也不删除服务端历史或已结算账；迟到回包不得重新落盘恢复已清记录。 |

本轮集中询问的两条漫游规则均已回复，当前没有待用户回答的问题。技术断点由执行者先查源码和调用链；若后续确实涉及新的资金、权限或产品规则，再集中提出，不重复询问上表。

4. Java、MySQL、Redis 用专用开发测试 VPS。先核后台源码、数据库和 Redis 目标；不用生产、假身份或本地 Java/Docker 替代失败环境。数据库场景必须独立连接回读；不删除其他任务资源或全局清缓存。
5. GitHub 标准托管 runner 跑同一提交的 CI；适用矩阵 `max-parallel: 20`，不为凑数重复测试，不在 VPS 放 Actions runner，不启用生产 workflow。
6. 修复失败后只重跑受影响分组，最后统一整轮 CI；真实身份/设备类证据另记。需要本地或真机的项留下操作步骤、预期结果和当前断点。
7. 按三个阶段框逐项打勾。只有源版本、测试、实际调用链及独立结果吻合才勾完整验收；再映射回原表的对应底层子范围，UI/新功能部分继续未勾。
