## 2. P0 级问题

### 2.1 成团字段前后端不一致

当前前端发布城市定向时主要传:

- `teamSize`
- `meetingPoint`
- `saleEndTime`

位置:

- `pages/publish/simple/index.js`
- `pages/publish/fabu/index.js`

但后端自动成团/未成团退款使用:

- `minPeople`
- `signupDeadline`
- `teamStatus`

位置:

- `TeamGroupServiceImpl`
- `OmsTicketMapper.selectUngroupedExpiredTickets`
- `migration_c3_team_fields.sql`

实际影响:

- 前端显示“成团 20 人”。
- `club/enroll` 也用 `teamSize` 计算成团进度。
- 但自动成团任务只认 `min_people`。
- 如果发布时没有写 `minPeople/signupDeadline`，则不会被自动成团/自动退款任务扫描到。

这是当前最重要的流程断点。

建议修复:

- 前端城市定向发布时同时写:
  - `teamSize`
  - `minPeople`
  - `maxPeople`
  - `signupDeadline`
  - `meetingPoint`
  - `refundRule`
- 短期可让 `teamSize` 兼容写入 `minPeople`。
- 后端 `saveTickets()` 也应兜底: 如果 `minPeople == null && teamSize != null`，则 `minPeople = teamSize`。
- `club/enroll` 应从 `minPeople` 优先读取，缺失再 fallback 到 `teamSize`。

### 2.2 多俱乐部前端已经放开，但依赖线上 DB migration

当前代码已支持:

- `/api/club/my` 返回 `owned[]`
- `pages/club/index/index` 多俱乐部切换
- `pages/club/create/index` 再建一个俱乐部
- 后端限制每个主理人最多 2 个俱乐部

但这依赖:

- `migration_club_multi.sql`
- 去掉 `club.member_id` 唯一索引 `uk_club_member`
- 建立普通索引 `idx_club_member`

风险:

- 如果线上未执行 `migration_club_multi.sql`，用户点“再建一个俱乐部”会后端插入失败。
- 如果小程序先上传、后端/DB 未部署，会形成明显的线上坏体验。

建议:

- 体验版上线前必须只读预检线上 `club` 表索引。
- 如果 migration 没执行，前端先隐藏“再建一个俱乐部”。

### 2.3 新页面依赖多张新表，部署顺序错会运行时报错

当前新增流程依赖:

- `club_leader`
- `club_post`
- `club_post_like`
- `club_post_comment`
- `coop_invite`
- `oms_ticket.min_people/max_people/signup_deadline/team_status/refund_rule/need_audit`
- `mms_merchant.capacity/available_time/suit_activity_types/charge_type/demand/coop_open`
- `cms_topic.club_id`

风险:

- Maven 能打包不代表线上库有字段。
- 小程序上传后，如果后端 jar 已部署但 migration 未执行，会出现 SQL 列不存在/表不存在。

建议:

- 按 `_deploy_d78f18c_ordered.sql` 的顺序预检和执行。
- 迁移、jar、微信体验版必须拆开验收，不要混为“已上线”。

### 2.4 仍有 4 个硬编码跳转指向未注册页面

静态检查发现:
