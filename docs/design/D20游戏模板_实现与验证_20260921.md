# D20 游戏模板：实现与验证

用户已确认：1d20 + 作者加值 ≥ 作者 DC；支持普通、优势和劣势；自然 1/20 不自动判定成败；失败结果由作者配置。

## 实现

- 入口：小程序既有模板编辑器 `pages/publish/temp` → 玩法 → D20 检定。沿用编辑器表单、选项和预览组件；玩家沿用 `pages/play`。
- 配置存入现有 `advancedConfigJson.diceRoll`，通过 `mode: d20` 与六面骰区分。DC 为 1–40 整数，加值为 -20–20 整数；成功/失败文案各 1–200 字。
- `ROLL_DICE` 由服务端生成点数。优势取两颗较高值、劣势取较低值。客户端传入的结果和加值不参与结算；同一会话重复提交保留首次结果。
- 玩家只收到已发生的结果文案。公开模板投影隐藏两种结果，采用模板时复用服务端秘密字段回填，校验源模板公开可见，保留作者主动改写。
- 成功和失败均完成本次检定；完成出口分别为 `ADVANCED_RESULT:D20_SUCCESS` / `ADVANCED_RESULT:D20_FAILURE`，可配置既有主题路线分支。
- 作者试玩使用当前草稿和固定样例点数，不调用真实结算、不写玩家进度或奖励。
- 骰子为真实正二十面体：12 个顶点、30 条棱、20 个三角面；原生 Canvas 对三维几何做透视投影、背面剔除、逐面明暗和数字绘制。Quaternion 旋转后让权威点数朝前，相对面之和为 21。优势/劣势先显示两颗落面，再将未选中骰子渐隐、权威选中的骰子同时居中放大；结果区预留空间，避免动画结束时跳位。未引入 3D 引擎；这是三维网格渲染，不是物理碰撞模拟。
- 玩家页精简为标题、单行规则摘要、三维骰子、总分数字和作者结果正文，内容整体居中下移；按用户反馈移除计算式、成功/失败标签和固定样例提示，保留错误重试及读屏判定。作者试玩仍使用固定点数，不影响服务端结算。
- 支持减少动态；离开页面取消动画。画布失败提供可见重试且不阻断检定请求，慢回包等待落面动画结束才展示结果。
- 复用现有会话配置快照、版本/CAS、完成门禁和奖励链；没有新路由、数据库迁移或依赖。

## 验证记录

- 模拟器实际点击时发现结果回填触发相同属性的 observer，重复初始化画布会打断动画；已按 show/mode/rollMode 保留同一画布，隐藏、销毁和错误重试仍清理。回归负控可复现旧实现销毁活动画布。
- 双骰选择动画增量：7/7 D20 测试通过，负控确认旧实现无法通过新增过渡断言；覆盖渐隐、居中、放大、劣势权威取小、减少动态、异常与销毁。模拟器实际点击掷骰，回读 12/7 取 12、总分 14，并确认最后只显示中央放大的 12。

- 第二次文字精简：相关测试 16/16、UI-GATE-0、329 个 WXML/WXS 原生编译通过。模拟器结果区仅显示总分 14 与当前草稿配置的“暗门没有打开”，内容整体下移居中；真实作者文案不作自动截断。

- 玩家页文字层级精简增量：相关测试 53/53、UI-GATE-0 和 329 个 WXML/WXS 原生编译通过；实际模拟器回读优势样例 12/7、总分 14、失败，并取得待掷骰和结果截图。

- 前端相关测试：247/247；覆盖保存回填、模式切换、严格校验、预览、服务端结果透传、分支声明、内嵌继续和共享组件样式依赖，以及闭合三维网格、20 个落面朝向、旋转帧、双骰、减少动态、动画销毁、画布故障和慢回包。
- 后端相关测试：172/172；覆盖自然 1 达到 DC 成功、自然 20 未达 DC 失败、优势/劣势、重复请求不重掷、未掷阻止完成、结果出口、公开投影及采用回填。
- `bash ci/xcx-check.sh` 全量静态门通过，动作台账同步；UI 基线仅移动原有登记的行号，未增加豁免。
- 代码复核发现的采用回填和内嵌继续缺口已修复并复核关闭。
- 实际模拟器检查发现 `wx:else` 与 `wx:for` 同节点导致编译失败，已改为条件块包裹循环。微信自带 `wcc` 对全仓 329 个 WXML/WXS 编译通过；还原错误写法的临时文件会失败（exit 2）。单文件编译接口的成功不作为整包编译通过证据。

- 开发者工具中已取得配置页、规则页、成功/失败结果截图。通过组件 `kitaction` 事件触发试玩，回读优势样例点数 [12,7]、取值 12、总值 14、DC 15、success=false、作者配置的失败文案。此为本地试玩，不是服务端真实掷骰证明。
