## A. 总体评价：当前不可发布

结论：**不可上线，不可商业化投放，不达到设计奖级标准。**

原因不是页面数量不够，而是关键业务链路的任务结果不可信：用户创建俱乐部后会看到“俱乐部不存在或加载失败”，订单页直接显示“功能数据未初始化”，路线编辑中地址和地图没有形成清晰闭环，玩家首页没有建立“城市游戏”的第一印象，商家首页没有围绕商家的真实工作流组织。

当前产品更像“功能模块堆叠后的内测版”，还不是一个能让用户 3 秒内理解、10 秒内开始行动、1 分钟内获得反馈的城市游戏产品。

## C. 用户路径优化建议

### 路径 1：玩家发现并参与城市游戏

当前路径：进入首页 → 看推荐/附近活动 → 点活动 → 选择报名模式 → 订单/支付 → 去玩。  
主要流失点：首屏不像城市游戏；用户不知道附近有什么可玩；订单页失败；城市定向和自由探索解释不够直观。

建议路径：

1. 进入首页：首屏就是城市地图，显示附近路线、任务点、当前位置。
2. 点击地图点或底部路线卡：看到路线主题、距离、预计时长、难度、是否收费、模式。
3. 选择“城市定向”或“自由探索”：页面用一句话解释差异。
4. 报名/购买：成功后进入订单详情和“开始前准备”。
5. 到达现场：地图导航到第一个点位，展示任务、验证方式、进度。
6. 完成后：展示完成证书、积分、徽章、分享、下一条路线推荐。

关键改法：玩家首页必须从 feed-first 改成 map-first，订单必须从技术错误态改成交易可信状态。

### 路径 2：主理人创建俱乐部并发布城市游戏

当前路径：创建俱乐部 → 自动跳详情 → 详情加载失败 → 管理台也弹技术错误 → 发起团进入发布器。  
主要流失点：创建后失败；没有成功确认；发布入口只说团；自由探索能力不可见；接口错误外露。

建议路径：

1. 创建俱乐部：四步表单结束后显示“俱乐部已创建”确认页。
2. 确认页展示俱乐部卡：名称、城市、成员数、公开主页状态。
3. 主 CTA：发布城市游戏；次 CTA：完善主页。
4. 发布前选择模式：城市定向 / 自由探索。
5. 进入专业路线编辑：地图上添加点位，节点完成度实时显示。
6. 发布成功：回到俱乐部管理台，列表出现新城市游戏，提供报名管理和分享。

关键改法：创建成功不能直接跳到可能失败的详情页；发布模式选择必须前置。

### 路径 3：商家承接并运营合作

当前路径：进入商家首页 → 看多个运营模块 → 不确定优先处理事项 → 找承接/合作/核销入口。  
主要流失点：信息过载；收入、漏斗、功能宫格混在一起；商家不知道“今天做什么”。

建议路径：

1. 商家首页第一屏：今日待办，包含待确认合作、待核销订单、待回复消息。
2. 第二层：当前合作项目，显示状态、出发时间、预计到店人数。
3. 第三层：可承接主题，按距离、匹配度、收益预估排序。
4. 第四层：收益与结算，仅在有数据后强调。
5. 门店资料健康度：缺图、缺营业时间、缺优惠时给明确补全 CTA。

关键改法：商家首页不是内容广场，而是运营控制台。

### 路径 4：消息与通知

当前路径：进入消息页 → 自定义顶部可能与胶囊冲突 → 列表/空态。  
主要流失点：导航不稳；系统通知、合作消息、订单消息缺少优先级。

建议路径：

1. 顶部安全区稳定显示“消息”和“全部已读”。
2. 消息分组：合作、订单、系统、私聊。
3. 重要卡片可直接处理：同意合作、查看订单、进入路线。
4. 空态引导用户去发现路线或完善商家/俱乐部资料。

## D. UI/交互优化建议

### 1. 玩家首页：改成地图游戏主界面

首屏结构建议：

- 顶部：城市名、搜索、消息。
- 主体：真实地图，占首屏 55%-70%，显示路线 pin、任务点、附近俱乐部活动。
- 底部浮层：当前推荐路线卡，包含模式、距离、时长、价格、开始按钮。
- 快捷筛选：附近、免费、适合新手、今天可玩、俱乐部活动。

交互要求：

- 拖动地图时底部卡更新为当前视野推荐。
- 点击 pin 时 marker 放大，底部卡切换。
- 无定位权限时显示“选择城市”和“开启定位”双 CTA。

### 2. 专业路线编辑：把“地址”变成“地图点位”

当前问题是用户在弹窗中输入地址后，地图没有立即确认，也没有告诉用户是否保存。

推荐交互：

- 节点卡上点击“选择地点”只打开一个统一地点选择器。
- 选择 POI 后立即：关闭弹窗、地图中心移动到该点、出现 marker、节点卡显示地点名和地址、按钮变为“已添加地点”。
- 手动输入地址时：输入后先点“搜索地址”，搜索结果列表出现候选；用户选中候选后才写入节点。
- “完成节点”前展示节点完整度：地点、剧情、任务、验证、奖励。
- 缺字段时不要 toast 一闪而过，要在对应模块下方显示错误。

### 3. 订单页：从红框错误改成交易中心

订单页应具备：

- tabs 可横向滚动，避免被胶囊或调试浮层遮挡时仍可读。
- 每个 tab 有数量，如“待使用 2”。
- 空态：`你还没有待使用的城市游戏`，CTA `去附近看看`。
- 错误态：`订单暂时没有加载出来`，CTA `重新加载`、`联系客服`。
- 成功态：订单卡包含主题名、模式、时间、集合点/有效期、状态、二维码/核销入口。

### 4. 俱乐部管理台：从“发起团”改成“发布城市游戏”

推荐结构：

- 俱乐部卡：名称、城市、成员、公开主页状态、资料完整度。
- 主 CTA：发布城市游戏。
- 模式选择弹层：城市定向、自由探索。
- 管理区：报名、成员、主页、合作、数据。
- 活动列表：全部 / 城市定向 / 自由探索 / 已结束。

### 5. 商家首页：重新规划为工作台

首屏建议：

- 标题：门店工作台。
- 第一卡：今日待办，按紧急程度排序。
- 第二卡：当前合作，显示项目状态。
- 第三卡：待核销/订单，直接进入扫码核销。
- 第四卡：可承接主题，展示收益预估和匹配原因。
- 底部：收益和门店资料，不要抢首屏。

### 6. 消息页：统一顶部安全区

必须处理：

- 使用统一 `topBar` 或同等组件。
- 右侧保留微信胶囊宽度。
- 大标题不要顶到胶囊下方。
- “全部已读”在小屏时变成图标或放入更多菜单。

## E. 状态系统补全方案

| 状态 | 当前问题 | 必须补齐 |
| --- | --- | --- |
| loading | 部分页面空白等待或没有骨架。 | 首页地图 skeleton、订单列表 skeleton、俱乐部详情 skeleton、商家待办 skeleton。 |
| empty | 空态文案泛化，如“还没有团”。 | 每个空态必须说明为什么为空、下一步做什么、主 CTA 是什么。 |
| error | 技术错误和业务错误混杂。 | 统一错误组件，不显示 SQL、Content type、字段名、栈信息。 |
| success | 创建、保存、发布后反馈不足。 | 成功后展示结果对象和下一步，而不是只 toast。 |
| network failure | 多数页面只有重试或 toast。 | 固定错误卡：网络异常、重试、离线缓存说明。 |
| permission denied | 登录、角色、能力缺失提示不稳定。 | 明确告诉用户缺什么身份，并给申请/切换入口。 |
| edge cases | 地址无坐标、重复提交、无定位、订单空列表、俱乐部上限等边界不完整。 | 每个关键表单增加字段级验证、提交锁、失败恢复、保留已填内容。 |

## F. 修改后的理想版本流程

### 玩家理想流程

打开城瘾 → 看到城市地图和附近可玩路线 → 点击路线 → 理解城市定向/自由探索差异 → 报名或购买 → 订单生成 → 到现场打开地图 → 完成点位任务 → 获得完成反馈、徽章、分享和下一条推荐。

### 俱乐部理想流程

创建俱乐部 → 创建成功确认 → 进入管理台 → 选择发布城市游戏 → 选择城市定向或自由探索 → 地图添加点位 → 设置任务和票种 → 发布成功 → 俱乐部主页出现活动 → 成员报名 → 主理人管理报名和出发。

### 商家理想流程

申请商家 → 完善门店资料 → 首页看到今日待办 → 承接匹配主题 → 配置优惠/核销/营业时间 → 收到玩家到店 → 核销订单 → 查看结算和复购效果。

### 消息理想流程

进入消息 → 顶部安全区稳定 → 先看重要合作/订单通知 → 在消息卡片直接处理 → 进入对应业务详情 → 回到消息状态自动更新。

## G. 是否达到设计奖级标准

**No。**

理由：

1. 核心价值没有在首屏成立。城市游戏产品应该把地图、位置、路线、任务点作为第一视觉语言，而不是普通活动 feed。
2. 关键任务结果不可信。订单、俱乐部、发布器这些商业链路出现错误态或无反馈，达不到生产级，更谈不上奖项级。
3. 信息架构未收敛。挑战、城市定向、自由探索、团、活动、主题之间的命名和导航关系仍混乱。
4. 状态系统不完整。loading、empty、error、success、network failure、permission denied 没有形成统一规范。
5. 商业角色没有被准确服务。商家首页没有围绕“承接、核销、结算、复购”组织，俱乐部没有完整表达两种发布模式。

## 发布前必须完成的验收清单

1. 订单页不再出现“功能数据未初始化”，能显示真实空态、真实订单、错误重试。
2. 创建俱乐部后 100% 能进入成功页或管理台，不出现技术错误 toast。
3. 俱乐部可明确发布城市定向和自由探索两种城市游戏。
4. 专业路线编辑中，选择/输入地址后地图 marker 必须立即可见，节点卡必须显示已保存状态。
5. 玩家首页首屏必须是地图型城市游戏体验。
6. 商家首页重构为工作台，首屏显示今日待办、合作、核销。
7. 消息页和所有自定义导航页统一处理微信胶囊安全区。
