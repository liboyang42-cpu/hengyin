## 做法（按业主 v4 规则）

1. **先照搬现有页面。** 每一屏的样式都由 master 上的真实 wxss 机械转换而来，没有手调：
   - 转换的文件：`style/tokens.wxss`、`lib`、`common`、`dark-mode`、`components.wxss`、`app.wxss`，`components/cy/*`，以及各页自己的 wxss。
   - 换算规则：1rpx = 0.52px（390 宽）。
   - 图标用 `components/cy/icon/icons.wxss` 的真实 cy-icon；设置页的图标是原 svg 内联。
   - 玩家页深色，活动详情页按现状是浅色（`theme-merchant`）。标题保持 `cy-nav-bar` + `cy-page-title`。
2. **新功能只加最小元素。** 多数是一行、一段、一个半屏或一句提示。新建页只有两张：「我的申诉」照抄 `report-mine`，「申诉进度」照抄 `report-detail`。
3. **标记的含义：**
   - 绿色虚线 + 「新增」。
   - 橙色实线 + 「改动」，点标签看改前和改后。
   - 蓝色点线 + 「已写码·待确认」，表示别的 agent 已经写成代码、但业主没批过的界面，点标签看问题。
   - 顶栏「显示标记」关掉，看到的就是改完的干净效果；建议撤掉的已写码块也会一起隐藏。
4. **能直接点着用：**
   - 手机框 390×844，窄屏下铺满整个窗口。
   - 有微信状态栏和右上角胶囊。
   - 页面之间真实 push / pop 跳转，左上返回键可用。
   - 半屏照 cy-sheet 的结构做。
   - 原生弹窗都有：带输入框的 showModal、actionSheet、toast。
   - 右栏可以切换每个新元素的状态：加载中、空、出错、无权限、游客，以及该元素自己的业务状态。
5. **左栏**列出全部屏。**「联动」面板**画出 5 条跨页数据流，箭头上写着页与页之间传递的真实字段。

## 每个功能放在哪里、为什么、否掉了什么

**T-31 组队大厅：放在「我的队伍」的「本场招募」**
- 为什么：`subpackageRoam/my-teams` 已有「我的 / 附近招募」两格，第二格本来就是队伍列表。从主题详情的组队卡点进来时，这一格换成本场全部队伍。数据走 `/api/orient/team/lobby`（master 已有，但目前没有前端调用），不需要定位。主题详情的组队卡在已购票时变成可点。
- 否掉的方案：
  - 新建「组队大厅」页：和「我的队伍」重复。
  - 在主题详情里直接列全部队伍：详情页会太长。
  - 改漫游地图：地图要定位，而组队按场次比按距离准确。

**T-32 队伍进度矩阵：放在「队伍详情」**
- 为什么：成员已经在这一页。建议把已写码的逐行列表换成「成员 × 站点」矩阵，最后一行写全队是否完成，达标线用一句话说清。按评审意见，普通队伍、开关关闭、非成员三种情况下**整段不渲染**。
- 否掉的方案：
  - 放进游玩菜单的「队伍位置」：那里是领队工具，不是每个队员都有。
  - 保留已写码的逐行写法：8 站 × 3 人就是 24 行。

**T-30 排名（按场次）：在游玩菜单加一行进入现有「同行者榜」半屏**
- 为什么：master 上这个半屏已经存在，但没有任何入口。分数那一格改成「已到达结局 / 未到结局 · 用时」，线性主题仍写「N 关」，同名次并列。`LeaderboardRankPolicy` 已经按这个规则排序。
- 否掉的方案：
  - 在顶栏加榜单按钮：10-23 已定顶栏不加东西。
  - 新建排行页。

**T-30 排名（按赛事）：在活动详情加一段「赛事榜单」**
- 为什么：赛事的信息都在活动详情页。
- 否掉的方案：在官方活动列表里展示。
- 后端：**需后端**，只有 `leaderboardEnabled` 开关，没有按赛事的榜单接口。

**T-40 成绩公示与争议窗口：放在章节结算半屏 + 「本局结果」卡**
- 为什么：成绩在结算半屏里出现。争议窗口有 24 小时，所以从游玩记录随时能回到的「本局结果」卡也放同样三行和一个按钮。提交用带输入框的原生确认框。
- 否掉的方案：
  - 已写码的「本局计分」新页：重复，而且暴露编号和代码。
  - 再开一个争议半屏：业主不喜欢多弹层。

**T-38 赛事详情与报名：在活动详情加「赛事联络」一段**

- 否掉的方案：已写码组件挂在页面根节点之外的做法。

**T-35 安全须知确认：在活动详情最后加一段**

- 否掉的方案：放进票夹，或在开局时弹窗。

**T-37 SOS：放在游玩菜单第一行「联系值班 · 紧急求助」**
- 为什么：点开是原生 actionSheet，列出值班电话和 110 / 120，只拨号。不上传位置，也不说「已收到求助」。没有配置值班电话时整行不出。
- 否掉的方案：
  - 在顶栏常驻 SOS 按钮：违反顶栏不加东西的决定。
  - 悬浮按钮。
- 后端：普通主题场次没有值班电话字段，**需后端**。

**T-34 到达申诉提交：放在站点卡「我已到达此站」下面那一行 sheet-note**
- 为什么：这一行写「本次到达未记录 · 申诉」，点开是带输入框的原生确认框，理由 1–500 字。提交后这一行变成「已申诉 · 查看进度」；申诉通过后变成「请在本站重新到达核验」。
- 否掉的方案：已写码的右上菜单多步做法，要先读资格再提交，还显示错误码和记录号。

**T-34 「我的申诉」：设置里加一行，进新页「我的申诉」**
- 为什么：10-23 已定入口在设置。新页照抄「我的举报」，详情页照抄「举报进度」。
- 否掉的方案：放进个人中心，或做成半屏。

**T-33 信誉与门槛：放在「我的申诉」页顶部一行**
- 为什么：被门槛拦下，最想知道的就是「为什么被拦、怎么申诉」，所以和申诉放在同一页。点开半屏列出加减分规则和门槛。拦截记录作为一类出现在申诉列表里。
- 否掉的方案：在设置里单独一行，见待决问题 Q15。
- 后端：**全部需后端**。半屏里的数值只是占位。

**T-42 玩家看到的判定：放在申诉进度页的「复核结论」**
- 为什么：只写结论和一句理由，不给守卫编号、错误码和规则名。通过且原局还在进行时，给出「回到这一局，去钟楼重新核验」；原局已结束时只读。
