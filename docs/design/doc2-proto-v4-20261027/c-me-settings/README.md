# 原型 v4-C · 我的、设置、发票与未成年（待业主确认）

> 只有原型，**没有任何小程序 / 后端代码改动**。业主确认后才写 UI 代码。
> 文件：`index.html`（单文件，CSS / JS / SVG / 图片全部内联，不依赖外部库）。

## 怎么看

- 浏览器直接打开 `index.html`。左栏列出全部屏幕；中间是 390×844 手机框（窄屏自动全屏）；右栏是本屏说明、状态切换、标注清单、接口字段、已写码问题、待确认问题。
- 顶栏：
  - **版本**：`v4 建议`（本原型建议的落地效果）/ `分支现状`（其他 agent 未经批准已写好的界面原样）。
  - **标注**：关掉 = 看落地后的干净效果。
  - **游客**：未登录浏览；任何写操作弹现有 cy-modal「登录后继续」（暂不登录 / 微信登录），登录后继续原动作。
  - **联动**：跨页数据流（发票申请 → 记录 → 订单详情；退款暂停；结果未知恢复；参与 → 角色卡 / 成绩 → 申诉；未成年授权）。
- 标注颜色：绿色虚线「新增」、橙色实线「改动」（点色标看 改前 → 改后）、蓝色实线「已写码·待确认」（点色标看来源分支和发现的问题）。
- 每个新元素在右栏「状态切换」里可切：加载中 / 空 / 失败 / 无权限 / 功能未开放 / 结果未知 等；游客在顶栏统一切。
- 导航是真实的 push / pop（左上返回、顶栏「← 返回」），弹层按 cy-sheet / cy-scene-sheet / cy-modal 的真实结构画。

## 怎么做到「先照抄」

样式不是手画的：`origin/master` 的 `style/tokens.wxss`、`lib.wxss`、`common.wxss`、`components.wxss`、`components/cy/*/index.wxss`、`components/cy/icon/icons.wxss` 以及各宿主页 wxss，按 **1rpx = 0.52px** 机械换算后内联（每页 / 每组件加作用域，数值未改）。已写码页面的 wxss 取自 `origin/feature/cy26-w8-closeout`。结构照各页 wxml 写，图标、空态插画、订单小图标直接取仓库文件转 data URI。文案取 wxml 与 js 中的真实字符串（如订单详情的「已经完成 / 已核销订单不可退款」、时间线「订单已创建 / 支付已完成 / 权益已核销」）。

为新元素补的少量样式集中在 `<style id="proto-css">`，并逐条注明原因（原生 `<icon>` / `<switch>` 替身、发票抬头表单 4 字标签宽一档等）。

## 每个功能：放在哪、为什么、放弃了什么

### 我的申诉（业主 10-23 已定：入口在设置）
- **宿主**：设置页「帖子处置与申诉」下面一行同款 cy-cell → 新页，整页照抄「我的举报」。
- **为什么**：业主已定入口；「我的举报」是现成的「我提交的东西 + 处理进度」列表，结构完全对得上（chip 筛选 + 记录行 + 状态签）。
- **放弃**：放进「帖子处置与申诉」半屏（那是帖子处置，混在一起会让人以为计分申诉也归内容审核）；放在本局计分页里（只能看一局）。
- **需后端**：跨局「本人全部申诉」列表接口（现在计分申诉 / 成绩争议只能按局读，到达申诉只有单条回执）。

### 发票（T-21 抬头 / T-22 申请与恢复 / T-23 退款暂停）
- **入口**：设置「发票」一行（W8 已加，补图标与说明）+ 订单详情新增「发票」段。订单列表卡片**不加**「申请开票」键（v3 有，本版去掉）。
- **页面**：我的发票（照抄我的订单）、发票详情（照抄订单详情）、申请开票（照抄结算页）、发票抬头（照抄参与人信息列表）、新增 / 编辑抬头（照抄参与人信息表单）。
- **为什么拆成 5 页**：每一页都有一个现成的、玩家已经用过的同类页面可照抄；W8 把它们塞进一页、用三颗按钮切换，是新造的界面。
- **业主规则落实**：
  - 只有已配置的开票单位能处理：订单按开票单位分组；未配置单位的订单放进「暂不可申请」不能勾。
  - 每个开票单位单独申请：选了一个单位的订单，其他单位的订单变灰并提示，提交前就挡住。
  - 完整税号只在后台授权且留审计的详情可看；小程序所有位置只显示 `91******8X2D`；编辑单位抬头必须重填完整税号。
  - 退款即暂停：申请状态 PAUSED 显示为「退款核对中」，我的发票 / 发票详情 / 订单详情三处一致。
  - 结果未知：申请页底栏原位提示 + 我的发票顶部同一提示，「查询结果」按原请求回读，不显示请求号；查不到给「再查一次 / 联系客服」。
- **少弹层**：整个发票流程只有一个半屏（选择发票抬头，照抄「选择参与人信息」）；撤回、删除各一次确认（现有 cy-modal）；提交成功直接回列表，不弹成功框。
- **放弃**：W8 的单页三按钮方案（见下）；在订单列表卡片上加按钮；成功弹窗。

### 我的参与 → 角色卡 / 本局成绩
- **宿主**：参与详情（我的参与页托管的 scene-sheet）现有信息卡里，照抄「最终分配节点 / 接待时间」信息行加两行：「我的角色卡 · 查看 >」「本局成绩 · 查看 >」。
- **规则（评审意见）**：报名与主题关联不上时，两行都不出，**也不出错误卡**；「本局成绩」只对城市定向出现，自由探索只出「我的角色卡」。
- **放弃**：W8 的三张独立卡片（无箭头、无图标，含已暂停的「自由探索权益」，无关联时显示错误卡）。

### 订单详情 / 入场码
- 只保留现有内容；新增「发票」段。券码、预约、套票余额等 F3 内容已暂停，不画。
- 入场码（scene-qr-ticket）保留不改；订单详情「查看票夹」→ 入场码（中间的票夹、游玩页本轮无改动，未画）。

### 未成年模式（T-24，关闭）
- C-3：现网设置页**不加入口**，法律文本不变。本组页面为以后准备，单独成组并标「关闭」。
- 设置里（以后）一行 → 半屏（照抄「帖子处置与申诉」半屏）：我的年龄段、规则、我的监护授权；成年人可「发起监护授权」→ 同一半屏换成一次性邀请码（不另开弹窗）。
- 孩子落地页「确认监护授权」：照抄订单详情正文，列出 孩子 / 监护人 / 关系 / 授权内容 / 有效期 / 证明方式 / 规则版本。
- 结算拦截：只用结算页底栏现有错误位的一句话，付款键置灰；不另开拦截半屏（v3 有，本版去掉）。
- 规则：未满 8 周岁不能自己注册付款（监护人购买并陪同）；8–15 付款需授权，城市定向只限白天低风险且监护人同队；16–17 白天低风险可经授权单独参与；年龄未知不按成年人处理；一条授权只绑一项用途，记录孩子、监护人、用途、规则版本、有效期；「购买」与「个人信息处理」分开发起、分开确认；短信验证码不作为监护证明；不收证件照片和人脸。

## 已写码部分发现的问题

**设置 ·「我的发票」**：没有图标（同列表唯一一行）；标题与 v3 已确认的「发票」不一致；位置在业主定的「我的申诉」之前。

**发票页（W8）**
1. 不照抄现有页面：五种视图塞在一页，用三颗按钮当标签，卡片是新造样式，返回键在页内切视图。
2. 给玩家看内部编号与术语：原请求号、原抬头编号、原订单 / 订单数字编号、回执、冻结、开票主体、平台核对、掩码。
3. 选中状态只靠文字前缀「已选 · 」。
4. 不同开票主体要等点了第二个才报错；未配置主体的订单仍可勾选，提交后才被拒。
5. 游客进入是页面里一颗「登录」按钮，不是现有「登录后继续」弹窗。
6. `{{detail.orderCount || 0}}` 缺值显示假 0。
7. 结果未知查不到时没有客服出口；「使用原输入重试保存」交给玩家做技术判断。
8. 订单详情看不到单笔订单的开票状态。

**参与详情入口（W8）**
1. 无主题关联时显示错误卡「角色卡与成绩入口暂不可用」+「重新加载」（评审要求：什么都不显示）。
2. 三张只有一行字的卡，无箭头、无图标，与本页样式不一致。
3. 「定向成绩」对自由探索也出现，点进去是空态。
4. 「自由探索权益」属于已暂停的 F3。

**本局计分（W8）**
1. **结果未知会永久卡死（评审发现）**：同步 / 结算 / 申诉 / 争议任一结果未知 → 四个写操作全部置灰；有请求号但回执查不到的待办没有人工出口（人工核对只给无请求号的旧待办），结算和申诉永远做不了。
2. 用微信原生导航栏，没有 cy-nav-bar + 大标题。
3. 显示对局 / 流水 / 节点 / 结算编号、原请求号、英文 SYNC、原因码 TASK_PASSED。
4. 漏记申诉要玩家手填节点编号。
5. 每个写操作先弹确认框，申诉再开半屏（弹层多）。
6. 用时显示为毫秒；榜单要手动点读取。
7. 说明句技术化。

**我的角色卡（W8）**
1. 说明句技术化（「属性定义已随本局冻结」等）。
2. 「建卡」「角色模板」是内部说法。
3. 每个属性一张卡并重复保留范围 / 数值范围，密度低。
4. 用主题作者配置的色值直接染色，会引入页面配色以外的颜色。
5. 「刷新角色卡」按钮多余。
