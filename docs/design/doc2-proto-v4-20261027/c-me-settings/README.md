样式不是手画的：`origin/master` 的 `style/tokens.wxss`、`lib.wxss`、`common.wxss`、`components.wxss`、`components/cy/*/index.wxss`、`components/cy/icon/icons.wxss` 以及各宿主页 wxss，按 **1rpx = 0.52px** 机械换算后内联（每页 / 每组件加作用域，数值未改）。已写码页面的 wxss 取自 `origin/feature/cy26-w8-closeout`。结构照各页 wxml 写，图标、空态插画、订单小图标直接取仓库文件转 data URI。文案取 wxml 与 js 中的真实字符串（如订单详情的「已经完成 / 已核销订单不可退款」、时间线「订单已创建 / 支付已完成 / 权益已核销」）。

为新元素补的少量样式集中在 `<style id="proto-css">`，并逐条注明原因（原生 `<icon>` / `<switch>` 替身、发票抬头表单 4 字标签宽一档等）。

## 每个功能：放在哪、为什么、放弃了什么

### 我的申诉（业主 10-23 已定：入口在设置）
- **宿主**：设置页「帖子处置与申诉」下面一行同款 cy-cell → 新页，整页照抄「我的举报」。
- **为什么**：业主已定入口；「我的举报」是现成的「我提交的东西 + 处理进度」列表，结构完全对得上（chip 筛选 + 记录行 + 状态签）。
- **顶部一行账号信誉（X7）**：只写「正常 / 受限」，不显示分数。
- **列表内容（C1）**：先只放计分申诉与成绩争议；点开落到那一局游玩页的计分全屏层（原型 A）。
- **放弃**：放进「帖子处置与申诉」半屏（那是帖子处置，混在一起会让人以为计分申诉也归内容审核）；放在计分页里（只能看一局）。
- **需后端**：跨局「本人全部申诉」列表接口（现在计分申诉 / 成绩争议只能按局读，到达申诉只有单条回执）。

### 发票（T-21 抬头 / T-22 申请与恢复 / T-23 退款暂停）
- **入口**：设置「发票」一行（W8 已加，补图标；10-28 起不加说明）+ 订单详情新增「发票」段。订单列表卡片**不加**「申请开票」键（v3 有，本版去掉）。
- **页面**：我的发票（照抄我的订单）、发票详情（照抄订单详情）、申请开票（照抄结算页）、发票抬头（照抄参与人信息列表）、新增 / 编辑抬头（照抄参与人信息表单）。
- **为什么拆成 5 页**：每一页都有一个现成的、玩家已经用过的同类页面可照抄；W8 把它们塞进一页、用三颗按钮切换，是新造的界面。
- **业主规则落实**：
  - 只有已配置的开票单位能处理：订单按开票单位分组；未配置单位的订单放进「暂不可申请」不能勾。
  - 每个开票单位单独申请：选了一个单位的订单，其他单位的订单变灰并提示，提交前就挡住。
  - 完整税号只在后台授权且留审计的详情可看；小程序所有位置只显示 `91******8X2D`；编辑单位抬头必须重填完整税号。
  - 退款即暂停：申请状态 PAUSED 显示为「退款核对中」，我的发票 / 发票详情 / 订单详情三处一致。
  - 开具中（C2）：待开具、已认领、处理中、结果待确认对玩家统一叫「开具中」。
  - 只给发票号（C3）：已开具显示发票号和开具时间，不提供下载；不显示申请号。
  - 全选本单位（C4）：每个开票单位标题行右侧一个文字按钮，只选本单位可开票的订单。
  - 结果未知：申请页底栏原位提示 + 我的发票顶部同一提示，「查询结果」按原请求回读，不显示请求号；查不到给「再查一次 / 联系客服」。
- **少弹层**：整个发票流程只有一个半屏（选择发票抬头，照抄「选择参与人信息」）；撤回、删除各一次确认（现有 cy-modal）；提交成功直接回列表，不弹成功框。
- **放弃**：W8 的单页三按钮方案（见下）；在订单列表卡片上加按钮；成功弹窗。

### 我的参与、角色卡、本局计分（10-28 移出本原型）
