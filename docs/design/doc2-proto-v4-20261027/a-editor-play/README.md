## 怎么做的

- **先 1:1 复刻现有页面，再加最小的元素。** 每一屏都按 `origin/master`（58f4cc42）上那一页真实的 wxml 结构来写。样式不是重画的：`style/tokens.wxss`、`lib / common / components.wxss`、各页的 wxss，以及用到的 `components/cy/*` 和 `pages/play/components/*` 的 wxss，都用脚本原样换算过来（1rpx = 0.52px）。图标是 `components/cy/icon/icons.wxss` 的真实 cy-icon，以 mask 数据 URI 形式内联。
- 玩家页深色，创作页用 `theme-topic-editor` 浅色。标题仍然是各页原来的形式：`cy-nav-bar` + `cy-page-title`，编辑页是白色圆形返回钮。
- 新功能都放进**已有的宿主**，没有新开页面。新开的半屏只有 0 个；被拦、审核这类情况都在已有卡片里换一句话和一个动作。
- 演示数据都是虚构的，没有真实域名和密钥。

## 业主已定的裁决，本原型照做（不再问）

- 本局用时和得分进右上角「…」游玩工具菜单（`p-tools`），不放顶栏。
- 只用现有那一条 RPG 状态栏 `.theme-story-hud`（`p-story`）。没有「本局状态」半屏，状态栏上的属性也不能点开。
- 章节完成卡加 RPG 小结（`p-finish`）。
- 到站被拦、替代任务都是「一句话 + 一个动作」（`p-node`）。
- 属性在主题编辑器里配置，并绑定到检定上（`e-keys` → `e-temp`）。
- 保留：旅程手记计分、章节结算、魔鬼交易、属性显示。
- 点票卡直接开局，不弹确认。本原型不涉及票夹；开局前的安全检查（safety/check）在点票时静默完成。
- 新主题的天然 20 / 天然 1 自动成败默认开，作者显式关掉才写 false（`e-detail`）。
- 打卡结果不明 = 在现场重新核验（`p-node` 的「结果未知」状态）；每人每站只完成 / 计分一次。
- **C-1**：状态键注册表（topic-state-keys）是**唯一**的属性定义处。为此原型做了两件事：
  - 值域卡里的「自定义整数值」改成只读引用；
  - 第一章「初始状态」里属性的开局值也只读。
  - 发布时冻结，游玩只读冻结值。
- **C-2**：只有游玩进行中保留后台定位（现有行为）。其它页面只在前台按需取定位，本原型没有新增任何定位采集点。

## 已写码·待确认：我看到的问题

来源分支：`origin/feature/cy25-w7-team-check`（PR #612–#620）和 `origin/feature/cy26-w8-closeout`（PR #625，草稿，CI 红）。cy26 包含 cy25 的全部界面。

1. **初始状态里的 attribute-binding-editor 和 C-1 冲突。** 它要作者在「旧配置」和「注册定义」之间逐项确认差异，等于承认有两个定义处。选项显示原始键名；用的是原生 checkbox / button；三颗按钮堆在一起。建议整块删掉。
2. **story-rule-editor 的控件和文案不合格。**
   - 用「▾」文字当图标，原生 button / picker / input，间距硬编码 rpx。
   - 显示 `counter.alarm`、「不支持的规则：OP」这类内容。
   - 要作者手打「角色代码 / 状态代码 / 物品代码」。
   - 建议版保留它的数据结构，只换控件和文案。
3. **「…」菜单里的「定向对局」面板。**
   - 把准备、开始、放弃、逐站回执、奖励事实都塞进了菜单。
   - 露出对局号、回执号、「N 秒（服务端回读）」。
   - 行内用裸 text，样式不对。
   - 开始和放弃各弹一个确认框。
   - 与「点票直接开局」「用时、得分进菜单」两条裁决重复且冲突。
4. **检定明细太技术化。**
   - 10 行里有「情境修正上限」「难度 DC」「自然骰自动判定 开启」。
   - 「查询原检定回执」「未查到不代表未写入」玩家看不懂。
   - disabledReason 对非 R5 的检定也会显示。
5. **相册「审核中」是死胡同。** 审核中会隐藏「重新选择照片」，被驳回也没有单独的状态。另外 master 和 cy26 都有一个问题：完成行和配图文字叠在同一位置。
6. **参与详情入口。**
   - 两张卡里只有一行裸字，没有图标、箭头和副标题。
   - 只要报名有主题就显示，不看是否城市定向、是否配了属性。
7. **角色卡。**
   - 服务端下发的任意 hex 颜色被直接写进 style，绕开了 token 和对比度检查。
   - 加载时没有骨架屏。
   - 「侧面」「本局特质」两个词玩家分不清。
   - 「属性定义已随本局冻结」是写给开发看的。
8. **计分页。**
   - 用的是系统导航栏，和角色卡不一致。
   - 玩家能点「同步已通过任务」「结算本局」。
   - 时间线露出 `TASK_CLEARED`、流水号、节点号。
   - 申诉要玩家手填节点编号。
   - 榜单要手点才读，用时写成「4012000 毫秒」。
   - 一页有 8 张卡、6 个确认框，外加 1 个半屏。
9. **到站被拦（cy26 的 play/index.js）**：原型只画了建议版。cy26 被拦时会依次出现：
   - 一个 toast；
   - 菜单里一个 4 行的块，含 `ARRIVE_*` 原始错误码和「记录号」；
   - 一个 6 行的申诉块；
   - 一个可编辑的原生 modal；
   - 一个重新核验的确认框。
10. cy26 与 PR #630 都改了 `play/index.wxml`、`fabu/index.wxml`、`temp/index.wxml`，合并时大概率冲突。

## 待业主决定

1. 值域卡里已有的「自定义整数值」迁移时，是自动搬进状态键（同名 `counter.*`，搬完只读），还是让作者手动重建？原型按自动搬来画。
2. 是否要给「作为角色属性」单独存一个字段？不存的话，所有可见的计数都会出现在角色卡上。
3. 颜色只给 4 种 token 色加默认，不开放任意色，可以吗？已写码的角色卡用的是任意 hex。
4. 状态栏里属性最多放几个？原型全放、靠横滑；也可以只放排序前 3 个。
5. 每站分值是否要做成可配？需后端。
6. 「停留 N 分钟」算不算替代方式？后端的替代方式只有扫码、拍照、答题。原型没有加。
7. 守卫被拦后申诉：确认框里要不要让玩家写一句理由？原型不写，只有一个动作。
8. 特质的内部 key 由系统生成、作者只填名字和说明，可以吗？
9. 「身份是」（ROLE_IN）条件用的身份列表从哪里来？
10. 年龄门槛（18 岁、夜间禁止未成年）要不要让作者可调？
11. 已写码的四块（角色卡页、计分页、「定向对局」面板、attribute-binding-editor）怎么处理？建议：
    - 角色卡保留，修上面列的问题；
    - 计分页大幅精简；
    - 面板和 binding-editor 删掉。
12. 手写字体选哪一款？候选：霞鹜文楷（PR 推荐）、龙藏、站酷快乐体。
