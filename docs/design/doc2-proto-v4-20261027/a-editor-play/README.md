## 10-28 修订（业主第二次评审）

44 条裁决已全部定稿，本版照做（相关的：X1 不要单独的计分页；X2 角色卡保留但要修；X3「…」只加「本局用时」「当前得分」，不放对局面板；X4 删 attribute-binding-editor，属性只在「d20 与角色设定」里建；A1–A9；E1–E3）。业主 10-28 的 7 条意见逐条落实如下。

### 1. 删掉平台夜间规则那一行

「可玩时段」里「平台规则：未满 18 岁的玩家不能在夜间（20:00–06:00）开局。这一条不能修改。」删掉。规则本身仍由服务端执行（`/api/orient/safety/check`），只是编辑器里不再写。

### 2. 初始状态 = 加标签、看标签（`e-init`、`e-init-add`）

- 只剩一组「开局带着」：玩家开局时带着的线索、物品、标签，用标签（chip）显示，每个点 × 移除；最后一个「添加」进下一层。
- 下一层按线索 / 物品 / 标签分组列出主题已有的状态键，多选；顶部输入框可以搜，也可以输入一个新名字（第一行变成「新建标签」）。选好之前右上「添加」是灰的。
- 删掉：cy26 的 attribute-binding-editor 整块（「启用的注册属性」、定义差异、「我确认采用」、「重新读取注册版本」、counter.* 键名、三颗按钮），以及每个属性一张的「开局值」卡。属性的开局值只在「d20 与角色设定」里。
- 保留：master 上已有的「生命值」「幸运值」两张卡，一字不改（`fabu/index.wxml` initialStateEditor）。
- 后端：开局线索 / 标签已经支持——`journeyRules.attributes` 里 key 为 `clue.*` / `tag.*`、`initial = 1` 的行，开局时写进 `state.tags`（`JourneyInitialState.initialize`）。开局放进背包的物品没找到字段，需后端核对。

### 3. 弹层照 iOS 来做

所有半屏（主题详情、d20 与角色设定、更多规则、初始状态、开局前准备）用同一套规则。只用 cy token，按钮仍是 master 的 `node-sheet__close` / `node-sheet__done`（含 `is-disabled`），改的是结构和行为，不是配色。

- **卡片叠放。** 一张半屏再开一张时，下面那张缩到 0.94、变暗，顶边在新卡片上方露出一条；关掉新卡片，它回到原样。不再出现「一张看起来一样的半屏整个盖住另一张」。主题详情 → d20 与角色设定、节点编辑 → 到达与引导 / 下一站都是这样。
- **半屏里的层级 = iOS 导航。** 第一层左「取消」、中间标题、右「完成」。往下一层：左上「‹ 上一层的名字」（如「‹ d20 与角色」「‹ 更多规则」「‹ 主题详情」），中间标题，右上是这一层的主要动作（「添加」/「完成」），填好之前是灰的。纯选择的一层（规则难度、可玩时段）右上为空，点一项立即生效。
- **内容 = 分组列表。** 行的右边是当前值，能往下走的有箭头；分组上面有小标题，不写脚注（10-28 去掉次级说明）；单选做成「一行 → 下一层勾选列表」（规则难度、可玩时段），少量选项用分段控件（进度钟类型、格数）；删除类的行是红字。
- **列表编辑。** 左滑一行出现红色「删除」；「编辑」进排序模式（红色减号 + 右侧三条线拖动）。用在属性列表、开局前准备、进度钟、特质。
- **添加属性**保留业主要的「类型在左、设置在右、一步一步出现」，做成侧栏式类型列表 + 右侧分组表单：名称 →「下一步」→ 范围 →「下一步」→ 开局值。填错就在那一组下面写一句。
- 主题详情里「可玩时段」「开局前准备」从整张卡变成一行（右边是当前值），点进去是同一张半屏的下一层。
