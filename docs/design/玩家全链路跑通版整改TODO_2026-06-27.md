## 1. 结论

玩家端页面骨架是全的、大多接了真接口，但**当前主报名链路是断的**：玩家在活动详情点「立即报名」没有任何反应，报名票种弹窗永远打不开 → 报不了任何活动。这是一切的头号阻塞。

修掉它之后，链路上仍有一串闭环级缺口：付款后详情页找不到「去游玩」入口、走近 GPS 就能绕过答题/扫码/拍照直接通关、安全的结算页是死代码而线上跑的是旧版且支付取消不回滚库存积分、订单已核销仍引导「申请退款」、通关 toast「即将开放」串不到广场。再加上一批孤儿页与身份口径不一致。

整改目标不是修几个按钮，而是把玩家端收敛成一条**能从第一次进入一路跑到通关发广场再到退款/客服**的主线，并清掉旁路上的死页和误导入口。

## 2. 目标链路（主线）

```
发现活动 / 城市定向团
  → 活动详情（四态按钮：未报名 / 已报名未开始 / 进行中 / 已结束）
  → 选择票种（开始/截止/余票/价格/成团状态可见）
  → 报名支付（报名人信息，非配送；积分/券抵扣前后端一致）
  → 我的报名 / 我的订单可查（状态一致、可退款、可客服）
  → 活动未开始：查看报名
  → 活动进行中：继续游玩
  → 节点打卡 / 答题 / 拍照 / GPS（按 validationMethod 校验，不可绕过）
  → 通关结算（徽章 / 成长 / 积分到账，幂等）
  → 发广场动态（关联 activityId / routePreviewImg）
  → 退款 / 联系客服（统一出口）
  → 复访足迹
```

## 3. 已确认决策（用户口径，覆盖审查中性结论）

| 决策 | 口径 |
|---|---|
| 报名时间判断 | **只看票种开始/截止/余票/下架**，不看活动是否已开始；活动未开始但票种有效可报名 |
| 活动详情底部按钮 | 四态：未报名「立即报名」/ 已报名未开始「查看报名」/ 进行中「继续游玩」/ 已结束「查看足迹·评价」 |
| 玩家「我的」页入口 | 只保留 4 个：**我的报名 · 我的订单 · 身份中心 · 我的权益**；商家/俱乐部入口不干扰玩家主线 |
| 「参与的主题」 | 从玩家链路移除（它是商家审核流，非玩家报名）；商家侧若留则改名「品牌/商家参与」 |
| 身份中心 vs 我的权益 | 身份中心看身份/角色/升级；我的权益看会员/积分/优惠券/额度/退款余额。两者不跳同一空页 |
| 地图搜索 | 先降级，不作玩家主入口；发现主路径回到列表/活动详情 |
| 退款接口 | 列表与详情统一走详情的口径（`/api/registration/cancel-refund`） |

> 模式语义沿用既有口径不改：`mode=1` / `mode=2` 仅修文案反向处，不动业务。
