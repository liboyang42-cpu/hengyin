## 1. 总结结论

当前三角色主干已经从“缺页面”进入“页面基本有、接口多数有、但流程细节仍有断点”的阶段。玩家、商家、俱乐部不是三套独立应用，而是一个共享壳 + `/api/role/info`/本地 role 缓存分流。核心页面能加载，后端能打包，但仍存在若干会让用户点不通或体验误解的问题。

最高优先级问题:

1. 仍有未注册跳转: 商户资料标签选择、主题结算页。
2. 仍有前端调用旧接口名: 默认地址、模板上下架。
3. 多处 WXML 动态事件绑定写法不可靠，影响返回/明细/重新申请类按钮。
4. 游玩页未登录/认证失败时只显示系统错误，没有转登录或重试登录的产品化处理。
5. 身份中心额度超额态显示为 `7/3`，缺少明确限制、解释和升级路径。

## 2. 玩家流程

已对齐:

- 玩家首页能加载，暗色沉浸风保留，推荐/附近活动/即将上线区可见。
- 游玩页能打开到错误态，不是白屏。
- 积分与身份中心相关单测通过。

问题:

- `pages/play/index` 在无有效 token 时弹出“请求访问 /api/play/nodes，认证失败，无法访问系统资源”。这对真实用户不是可行动提示，应该改为登录态恢复失败后的“重新登录/返回活动详情”。
- 首页视觉仍展示较强活动海报/占位感，截图里首屏推荐内容偏营销海报，和真实城市解谜/路线探索的产品心智仍不完全一致。
- 身份中心当前缓存态显示为商家，且额度出现 `主题发布 7/3`，没有解释“已超额、暂停发布、申请升级”。

## 3. 商家流程

已对齐:

- 商家台可加载，经营收入、待办、券统计、经营漏斗、常用功能等运营面板已经成型。
- 商家入驻表单可见，基础字段和底部继续按钮状态明确。
- 商家公开主页后端接口 `/api/merchant/public-detail` 存在。

问题:

- `pages/shanghuziliao/shanghuziliao.wxml:62` 仍指向 `/pages/biaoqian/biaoqian`，但真实注册页是 `/pages/publish/biaoqian/biaoqian`。商家编辑品牌偏好时会跳转失败。
- `pages/merchant/apply/index.wxml` 使用 `bindtap="{{...}}"` 动态事件名。应改为固定 handler，在 JS 内根据状态分支，否则部分基础库/编译状态下容易点不动。
- 商家台底部 tab 仍显示“团体”，而当前产品口径是“俱乐部/商家/玩家”。建议统一术语，避免用户误解。
- 常用功能图标风格混杂，部分图标语义不准，如“发现俱乐部”使用蛇形/工具类图标。

## 4. 俱乐部流程

已对齐:

- 俱乐部管理台可加载，包含发起团、编辑资料、主页、成员管理、报名管理。
- 报名/成团管理页已优先展示成团状态、进度、退款入口，且 owner/admin 名册接口已收紧。
- 后端 `ApiClubController` 对成员移除、名册、发帖删除、勋章等关键写操作有 owner/admin/本人校验。

问题:

- `pages/club/apply/index.wxml` 同样使用动态 `bindtap="{{...}}"`。
- 复查截图 `06-club-apply.png` 实际落到身份中心，不是申请表单；说明当前会话状态下“成为主理人”入口会被 roleGuard 判定为已是主理人或缓存态影响。需要明确: 已是主理人时显示“去创建/管理俱乐部”，不是无提示跳转。
- 俱乐部管理台使用 emoji 做操作图标，和商家台/身份中心的 SVG 图标体系不一致，视觉专业度不足。
- 报名管理页暴露“内测工具”块，虽然标注仅开发版，但截图样例里非常显眼。体验版/正式版必须确认不显示。

## 5. 发布/报名/成团链路

已对齐:

- 简易发布页已同时写 `teamSize`、`minPeople`、`signupDeadline`，旧报告中的成团字段漂移已明显收敛。
- 俱乐部报名管理页优先读取 `minPeople`，再兼容 `teamSize`。
- 主理人清退退款后端通过 `cancelPaidRegistrationByOwner` 校验主题归属。

问题:

- 简易发布页首屏地图占比很高，表单信息被压到下半屏；对第一次创建者来说，“我正在创建什么、还缺什么”不够清晰。
- `pages/topic/index/index.js` 跳 `/pages/topic/settlement/settlement`，但该页面没有注册进 `app.json`。主题结算入口会跳转失败。
- 订阅消息模板 ID 仍需平台配置，构建通过不代表成团/开团提醒线上可用。

## 6. 后端/API 契约

已对齐:

- `/api/role/info`、`/api/club/*`、`/api/merchant/*`、`/api/registration/*`、`/api/play/*` 主干接口存在。
- `/api/getwxbindphone` 和 `/api/logout` 存在，之前脚本初扫为缺失是扫描器误判。
- 后端打包通过。

问题:

- `pages/address/address.js:116` 调 `/api/user/address/setDefault`，后端未见对应接口。现有后端是 `/api/user/address/action` 支持 `isDefault`。
- `pages/member/mytemplate/mytemplate.js:309` 调 `/api/template/update-publish-status`，后端实际是 `/api/template/updateLibraryStatus`，且参数名是 `template_id` / `publish_status`。
- 线上仍需按 migration 顺序确认新表/字段，尤其俱乐部、成团、商家协作、AI/NPC 当前工作区有新增 SQL 和未跟踪代码。

## 7. 建议修复顺序

P0:

1. 修 `/pages/biaoqian/biaoqian` 错路由。
2. 注册或移除 `/pages/topic/settlement/settlement` 入口。
3. 对齐 `/api/user/address/setDefault` 与 `/api/template/update-publish-status` 两个旧接口名。
4. 把动态 `bindtap="{{...}}"` 改成固定事件 handler。

P1:

1. 游玩页认证失败改为登录恢复/返回详情，而不是系统错误文案。
2. 身份中心额度超额态补解释和升级/禁用状态。
3. 俱乐部申请已是主理人态改为明确页面，不要静默落到身份中心。
4. 确认报名管理内测工具只在 develop 显示。

P2:

1. 商家台/俱乐部台图标体系统一，去 emoji 化。
2. 首页内容从活动海报感转向路线/节点/任务感。
3. 简易发布页降低地图首屏压迫，强化步骤完成度和缺项提示。
