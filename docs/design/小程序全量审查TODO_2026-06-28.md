## P1 — 重要问题（体验明显受损/逻辑缺口）

- [ ] **P1-1: 游玩页认证失败改为可行动提示**
  - 文件: `pages/play/index.js:85-99` + 全局 `utils/transport/request-client.js:60-76`
  - 现状: 无有效 token 时 API 返回 `"请先登录"`（HTTP 200 + AjaxResult error），前端直接显示为 `emptyTip` 文本，没有引导用户重新登录
  - 期望: 返回 `code==2` 触发静默重登；或前端识别"请先登录"文案→显示「重新登录」按钮
  - 修复: 后端 `/api/play/nodes` 返回 `code==2` 而非 `error("请先登录")`；或前端在 fail 分支加 `emptyKind: 'auth'` + 登录按钮

- [ ] **P1-2: 俱乐部申请「已是主理人」态不要静默跳身份中心**
  - 文件: `pages/club/apply/index.js:38-44`
  - 现状: `roleGuard.isClubLeader()` → `mode='done'` → 显示"已是主理人，去创建/管理俱乐部" → 点按钮跳 `/pages/club/create/index`
  - 复查截图 `06-club-apply.png` 实际落在身份中心，说明入口 `pages/shezhi/shezhi.js:294` 的 `goBecomeTalent()` 逻辑在 roleGuard 判定前就触发了身份中心跳转
  - 修复: 在 `shezhi.js` 的 `goBecomeTalent()` 里先 `roleGuard.load()` 再判定——已是主理人→跳 club/apply（done 态），否则→正常申请流

- [ ] **P1-3: 确认报名管理页内测工具不在生产环境显示**
  - 文件: `pages/club/enroll/index.wxml:88-97`
  - 现状: 内测工具块由 `wx:if="{{_dev && canRefund}}"` 控制，`_dev` 来自 JS data
  - 风险: 如果 `_dev` 未正确初始化或构建时未剔除，生产环境会暴露「强制评估成团」「强制结算/退款」按钮
  - 修复: 确认 `_dev` 仅在 `getApp().isDevEnv()` 时设为 true；后端 `ApiRegistrationController` 的 `debugEvaluate`/`debugProcess` 也加 `@Profile("dev")` 或环境变量守卫

- [ ] **P1-4: 身份中心额度超额态补解释文案**
  - 文件: `pages/role/center/index.wxml:73-91`
  - 现状: 额度显示 `{{usage.themes}}/{{permission.maxThemes}}`（如 7/3），超额态有红色进度条但无文字解释
  - 期望: 超额时显示「已超额，暂停发布。申请升级→」或类似引导
  - 修复: 在 wxml 加 `wx:if="{{usage.themes > permission.maxThemes}}"` 条件块，显示超额解释 + 跳转升级/客服入口

- [ ] **P1-5: TabBar 缺少文字标签**
  - 文件: `app.json:47-79`
  - 现状: 5 个 tab（首页/广场/模板/达人/我的）全是纯图标，`text` 字段缺失
  - 影响: 用户无法从 tab 栏文字判断每个 tab 的功能
  - 修复: 给每个 tab 加 `"text"` 字段（首页/广场/模板/达人/我的）

- [ ] **P1-6: 清除 mytemplate.js 中的死代码**
  - 文件: `pages/member/mytemplate/mytemplate.js:303-330`
  - 现状: `togglePublishStatus()` 函数调错误 API `/api/template/update-publish-status`，但 **未被任何 WXML 调用**（实际用 `templateStatus()` 调正确的 `/api/template/updateLibraryStatus`）
  - 修复: 删除 `togglePublishStatus` 函数

- [ ] **P1-7: 商家台图标体系不一致**
  - 文件: `pages/merchant/index/index.wxml:86-130`
  - 问题 1: 「发现俱乐部」用 `icon_python.svg`（蛇形图标，语义错）
  - 问题 2: 「品牌中心」「承接设置」「公开主页」三个不同功能共用 `icon_brand.svg`
