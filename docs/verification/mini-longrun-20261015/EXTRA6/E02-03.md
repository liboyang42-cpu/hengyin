## 实际引用类型与数据流

授权源码 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CommunityPostServiceImpl.java`：

- REFERENCE_TYPES明确仅ACTIVITY/TOPIC/ROUTE/CLUB/POI；validateUpsert拒绝POST及其他类型。不存在post-to-post关联快照，因此“引用另一个已删帖子继续读”的输入不是当前支持的业务链。
- referenceOptions允许ACTIVITY/TOPIC/ROUTE/POI/MEMBER；MEMBER用于可选成员，不能据此认定MEMBER是可保存内容引用，保存仍受上述白名单校验。
- validateUpsert限制客户端snapshot为JSON对象/长度及PUBLIC_SAFE标记；replaceRelations实际不直接采用客户端snapshotJson，而是调用selectReferenceSnapshot(type,id,authorId)，空结果409，再将服务端结果json(snapshot)以PUBLIC_SAFE写入。
- hydrate只在父帖先通过既定可见性后调用selectReferences。E02-01已使外部detail父子来自同一快照；不因此声明目标引用的后续生命周期已经获得单独授权。

只读依赖 `chengyinhub-system/src/main/resources/mapper/business/CommunityPostMapper.xml`：

| 类型 | 保存时服务端投影/限制 |
|---|---|
| ACTIVITY | 发布/状态/非删除/未取消，且作者本人或已付款有效报名；只选标题、封面、地址名称和开始/结束时间 |
| TOPIC | status/user_status正常、非删除、非模板；标题/封面/地址名称/product_type |
| ROUTE | 本人且已完成；通用标题、距离/发现数量/揭示数量/结束时间，不读取路线坐标轨迹 |
| CLUB | 正常且非删除；标题/logo/city |
| POI | status=1；标题、空封面、city_code或description |

selectReferences仅读取已存snapshot_json/privacy_snapshot等且invalidated_at IS NULL，不实时重新选择目标。主源码中检索到社区引用invalidated_at的读取，但未找到相应社区引用失效写链。这个事实仅说明当前保存式快照机制，不能自动证明业务允许永久公开或要求撤销。

另一个授权源码 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CreativeSquareCommunityPolicyServiceImpl.java` 处理旧ViewCreativeSquare的latest/following、block和举报理由，未调用community_post_reference/selectReferences，不能将其isHiddenByBlock当作新帖引用目标的授权真源，也不能在此造新分享链。

## 决策阻塞与范围

具体触发：ACTIVITY/TOPIC/CLUB/POI在保存合法PUBLIC_SAFE快照后下架/删除/取消，源帖仍PUBLISHED/PUBLIC，随后重读源帖。当前实现会返回未invalidated的历史公开标题/封面/统计快照。它没有把目标完整正文、私密轨迹或新更新字段实时补入。

需要明确既定合同的具体内容：这些曾公开的投影在目标不可用后，是保留历史引用卡片、仅保留不可点击标题，还是立即停止输出某些字段/整卡；是否同样适用于本人已完成ROUTE的公开统计。该选择涉及引用快照留存/可见性，不在本次静默改政策授权内。没有具体旧合同证据前，不把“旧快照不是永久访问许可”的一般原则自行解释为所有历史公开标题必须擦除。

恢复条件：协调者提供现有明确产品/隐私合同或对上述触发的裁决，并给实际需改Mapper/目标生命周期文件的精确写权；再基于既有投影做最小收窄。不得为本项增加新HTTP、引用类型、分享凭证或权限角色。
