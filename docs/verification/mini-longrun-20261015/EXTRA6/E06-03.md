## 静态缺陷与实现

原 `audio-session.js` 的 apply 在调用 setKeepScreenOn 前写 keepOn；异步 fail 与同步 throw 均不撤销，所以后续相同状态操作直接返回，失败被当成已生效。

现在区分 desiredKeepOn（owner集合期望）、confirmedKeepOn（最新请求确认，失败为未知 null）和 keepRequest（当前请求身份）。同值在途去重；同值已确认去重；失败后仅下一次 keepAwake/releaseAwake 调用可以重试，没有自动重试或计时器。相反期望立即替代旧请求，确保最后 owner 释放时，即使开启仍在途也发送关闭。success/fail/同步 throw 只有当前请求身份可以结算；过期或重复回调不能覆盖新 confirmed/inflight 状态。

awake Set、共享 owner 释放规则与 API 缺失降级保持。没有改变 register/unregister、中断恢复、页面调用或业务策略。旧 audio-session.test.js 覆盖共享引用与缺API，未覆盖失败恢复或过期回调；没有修改旧测试。底层平台实际执行异步请求的先后仍需设备集中验证，本模块不声称取消已发出的平台请求。
