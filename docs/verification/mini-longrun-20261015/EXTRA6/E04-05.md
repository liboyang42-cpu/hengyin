## 原触发的完整防线

源码 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/SmsCouponHistoryServiceImpl.java` 的 `redeemCoupon`：

1. 普通读已得到 useStatus=1 时立即返回 ALREADY_USED；不会再结算、计数或审计。
2. 普通读尚为0，但另一个请求已经提交核销时，当前请求必须经过 `claimUnusedCoupon`；CAS零行后转 `selectSmsCouponHistoryByIdForUpdate` 当前锁读，看到1返回ALREADY_USED。
3. CAS失败后的回读还区分不存在/软删→NOT_FOUND、已过期→EXPIRED、开始时刻未到→NOT_STARTED；无法确认合法终态时明确抛状态变化异常，不编造核销成功。
4. 普通读走过期分支时，`expireUnusedCoupon` 同样只从当前未用态过渡；若另一请求已经核销，零行后当前锁读看到1，返回ALREADY_USED而不把核销覆盖为过期。
5. 只有 CAS成功才进入 `recordCouponVerification`、incrementUseCount和审计；计数/审计非1行抛错。方法原有 rollbackFor=Exception事务保持。

SQL `chengyinhub-system/src/main/resources/mapper/business/SmsCouponHistoryMapper.xml`：

- `claimUnusedCoupon` 按 history id + 当前 use_status=0 + 未删 + start/end边界原子更新为1。
- `expireUnusedCoupon` 按 history id + 当前 use_status=0 + 未删 + 当前已过截止条件更新为2，不覆盖1。
- `selectSmsCouponHistoryByIdForUpdate` 使用真实 FOR UPDATE，与初始普通读不同statement，是当前事实读取，不能换回普通快照读。
