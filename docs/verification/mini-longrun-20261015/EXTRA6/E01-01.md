## 源码与边界依据

唯一生产审计对象：`chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/ClubEventScheduleMaterializer.java` 的 `materialize`、`parseDate`、`normalizeType`。只读核对调用者 `ClubEventOpsServiceImpl.createSeries` / `updateFuture`，未修改该 Service。

| 特定输入/边界 | 当前源码行为及结论 |
| --- | --- |
| WEEKLY 跨月/跨年/闰日 | 日期用 `LocalDate.parse` 与 `cursor.plusWeeks(1)`，不按每月日号、毫秒长度或 JVM 默认时区计算；月长/闰年由日历类型处理，没有制造额外场次的分支 |
| CUSTOM_DATES 乱序、重复及带首尾空格 | 各值先 trim/parse 成 LocalDate，再进入同一个 `TreeSet<LocalDate>`；返回 `new ArrayList<>(dates)`，按日历日排序并去重；不同字符串同一天也只生成一个日期 |
| WEEKLY 请求缺场数、0、负数或超过64 | 缺省为1；显式值必须1至64后才进入循环；每轮只加入一个日期，受请求数与90天窗口共同限制 |
| CUSTOM_DATES 大量重复/独立日期 | 按去重后日期集合的 size 验证1至64，不把重复输入误当多场；65个不同日期必拒绝，不需要更改为按原数组长度计数 |
| 今日、今日+90、今日+91 | 公共后检查以 `isBefore(todayShanghai)` / `isAfter(horizon)` 判定，区间为含首尾的今日至+90；ONCE/CUSTOM窗口外拒绝，WEEKLY循环仅收集窗口内日期 |
| WEEKLY 请求64场但90天内只有13场 | 保留既定窗口截断语义，不擅自要求恰好生成64场；已有专属测试明确期待13场 |
| WEEKLY 起点晚于窗口 | 循环无日期进入，随后空集合验证拒绝，不能返回成功空系列 |
| WEEKLY 起点早于今日 | 加入的过往日会被公共日期后检查拒绝；不自动跳过历史并改成另一组场次 |
| null/空 CUSTOM_DATES，非法/null日期，未知 recurrence | 空列表在遍历前拒绝；null日期转空字符串后 parse 失败，经 DateTimeException 映射为既有400；未知类型拒绝；CUSTOM_RRULE保持既有501不可用 |

上海日期来源由生产调用者传入 `todayShanghai()`；物化器本身只处理日历日，不做集合时刻/时区转换。创建路径另验今日集合时刻尚未过去；FUTURE_ONLY调用者另要求日期严格晚于今日。这两层差异是当前既定合同，不能在物化器中统一成禁止今日，从而改变创建行为。
