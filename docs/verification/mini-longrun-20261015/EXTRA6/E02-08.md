## 实际重放读链

精确源码 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CommunityPostServiceImpl.java`：

- act是既有@Transactional写入口，先principal/action/requestId校验，再selectById(postId,memberId)；不可见立即404，发生在isCommandReplay之前。已存互动回执不是绕过当前父帖读取的授权。
- act重放经feedbackResultOrDetail：LIKE/BOOKMARK返回detail，再次调用当前selectById；没有读取回执result_json作为旧详情。
- NOT_INTERESTED/SEE_LESS_AUTHOR/SEE_LESS_TOPIC成功投影仅postId/action/applied，不包含父正文、媒体、引用或旧快照。不能把一个无正文回执解释成正文泄漏。
- unact重放直接detail(memberId,postId)。新的unact虽先删除本人动作再读detail，但最终不可见抛404；外部事务按既有RuntimeException回滚语义处理，不把其中间写调用当已提交越权变更。本项不改取消隐藏/本人动作清理的产品政策。
- isCommandReplay按member/request取回执并核commandType/aggregateId，异命令/异帖409，不跨账号重放。

只读依赖 `chengyinhub-system/src/main/resources/mapper/business/CommunityPostMapper.xml`：selectById始终include visibilityPolicy；作者分支也排除DELETED。非作者只PUBLISHED且满足PUBLIC/FOLLOWERS/COMMUNITY条件，PRIVATE无非作者开放分支。block/mute及本人隐藏条件仍参与。动作/取消动作的回执不单独恢复正文。

## 指定触发的静态结果

| 父帖当前状态与身份 | 重放读链 |
|---|---|
| DELETED，作者或非作者 | selectById不命中；act在回执前404，unact重放detail404 |
| HIDDEN/CHECKING/REMOVED，非作者 | 非PUBLISHED，不能读取详情 |
| PRIVATE，非作者 | 无非作者可见分支，不能读取详情 |
| HIDDEN或PRIVATE，合法作者 | 沿原作者工作区权限可读；不能将既定合法作者读取误报为绕过权限 |
| 已成功负反馈的最小结果 | 仅实体ID/动作/布尔，不输出旧正文集合；未新增分享凭证 |

本类内部detail调用不经过独立detail事务代理，但act/unact已有外层写事务；本项不覆盖外层隔离级别或建立嵌套只读事务，也不声称解决所有跨隔离级别的在途读取。新的只读聚合入口补丁不改变这两条写入口的原事务语义。
