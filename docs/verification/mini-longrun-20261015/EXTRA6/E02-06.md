## 顺序保护与具体并发缺口

`CommunityPostServiceImpl.comments`先detail(viewer,postId)，所以父帖已不可见时，即使传游标也先404。没有发现顺序直读绕过父帖的路径。

但comments为本类内self-invocation调用detail，不经过独立detail的事务代理，外部comments入口此前没有事务。父检查成功后再selectComments时，另一个事务可改父帖PRIVATE/CHECKING并提交新评论。`CommunityPostMapper.xml.selectComments`的root_page及线程查询核评论自身状态/作者/pending审阅/block/mute，但没有重新对父帖执行visibilityPolicy，因而原非作者请求可能读到新私密阶段的评论集合。

最小改动仅 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CommunityPostServiceImpl.java` 的comments入口增加 `@Transactional(readOnly = true, isolation = Isolation.REPEATABLE_READ)`。内部detail及selectComments共享此首读快照；不修改Mapper SQL、父可见性政策、根游标、作者CHECKING自身评论或父帖作者PENDING审批阅读权限。写服务原有事务保持原样。

一致性在首个父一致性读线性化，不承诺撤回取消所有在途请求；后续新游标请求重新检查已提交父帖权限。不是给评论新增公开权，也不建立跨多页冻结快照。
