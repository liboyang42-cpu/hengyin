## 静态缺陷与最小修复

真实外层 `PerkLedgerServiceImpl.reverseRedemption` 在clawback会员锁之前读取redemption及通关状态，可能已经建立MySQL REPEATABLE READ快照。即使后续取得会员行锁，`clawPoints` 原 `selectUmsMemberById` 仍是普通SELECT，不能借持锁自动变成当前读。

真实交错：初始point100建RR快照 → 另一事务余额增至105提交 → 原事务锁会员 → 普通读仍100 → deductPoints真实当前余额105扣10到95 → 原负账写100→90，余额与流水不守恒。余额先降至6时，原读100算应扣10，条件扣减失败而异常，不能沿既定“当前余额不足扣到0、差额审计”处理。

仅把clawPoints余额取得改为已有 `Long currentPoints=umsMemberMapper.selectPointsForUpdate(memberId)`；before仍按null→0、Math.max(0,currentPoints)。requested、min(requested,before)、扣到0、零额不写负账、原事件摘键、rewardBusinessKey、冲回范围、外层审计和锁序均不改。

只读现有 `UmsMemberMapper.selectPointsForUpdate`：Long返回，SQL `SELECT point ... FOR UPDATE`，useCache=false/flushCache=true，专为当前余额读取。无需新接口或改Mapper/XML。该helper仍要求调用方先持会员锁，再锁/改原奖励流水，当前余额读重入已持会员锁；不改变原锁序。
