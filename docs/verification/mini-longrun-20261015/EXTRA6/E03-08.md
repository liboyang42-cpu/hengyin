## 生产者真实形状

`chengyinhub-system/src/main/java/com/chengyinhub/business/service/support/NodeJourneySnapshot.java` 的copyJourneySegments/copyMechanicSegments在输入为对象时调用：

- copyPlayables总写ObjectNode；没有启用入口时是 `playables:{}`，不是数组，也不是缺键。存在入口才写section:true。
- copyBranchOutcomes总写ArrayNode；没有branch终态声明时是 `branchOutcomes:[]`，不是对象，也不是缺键。
- copyChoiceEffects仅在view.size()>0时写choiceEffects对象。没有任何参与投影段时**整键缺失是正常生产状态**，不能类比playables强制补键。某些已配置但没有effects的段可产生空子对象，仍是对象投影，不等于新玩法必须实时回退。
- 输入null/非对象时两个copy入口直接return，不写这三个键。当前runtime.freezeJourney在调用前把不可用blockConfig归一为JSON空对象，已创建的有效冻结块可产出前两种正常显式空。

本producer没有产null或其它类型；不把正常 `playables:{}` / `branchOutcomes:[]` 判成损坏，也不把choiceEffects正常缺键当必须实时补全。

## 表外缺陷的具体静态触发

已存在本局nodeJourney对应节点对象，但playables显式null；作者后来把liveConfig.qa.enabled=true。allowedActions仅检查 `playables != null && playables.isObject()`，否则走liveConfig，晚新增qa会成为本局入口。同理把branchOutcomes显式null/对象后，晚改live branch声明会被outcomeContract使用。两处注释都写“老快照没有该键才回退”，实际却把存在但类型损坏也当缺键。

这与改正常空值不同：没有要求改变playables={}或branchOutcomes=[]的语义，更不能修改helper把损坏值悄悄归一成空掩盖consumer缺陷。
