## 实际text实现及调用者

生产精确文件：`chengyinhub-system/src/main/java/com/chengyinhub/business/service/support/RoamSharePrivacyService.java`。

`text(Object value,int max)`先验证String，按既有 `[\\p{Cntrl}]` 移除controls，再trim，然后以String.length判断并 `substring(0,max)`。JavaString的length/substring按UTF-16 code unit计数，补充平面字符（常见emoji）占high+low两个code unit；当前代码没有检查截断点是否处于surrogate pair中间。

调用字段：routeName、medal、shopMedalName、POI.name上限40；POI.catLabel上限16；time上限10随后DURATION校验；POI.cat上限16随后ASCII `[a-z_]{1,16}` 校验。routeName空串另有既有默认标题，cat非法另有landmark默认；这些分支不应在本项重定义。

真实入口链已只读核对：

1. 小程序 `chengyinhub-xcx/utils/roam-share-snapshot.js` 的buildSharePayload把session.routeName/medal/shopMedalName/poi.name/catLabel转String，**没有40/16文本截断**；publishShareSnapshot将JSON.stringify结果作为snapshot发既有 `/api/roam/share/snapshot`。所以下述合法字符串不会必然被上游挡掉。
2. `chengyinhub-admin/src/main/java/com/chengyinhub/web/controller/api/ApiRoamShareController.java.publish` 对登录主体/clientTs过原闸后调用 `privacyService.normalize(...).toJSONString()`，再把规范结果交snapshotService持久化。normalize只限制整份raw<=64KiB及字段类型等，下面几十字符合法输入完全在大小限制内。
3. 同Controller匿名read先按token查stored JSON，再调用normalizeStored；normalizeStored取ts后回到同normalize/text，因此历史合法原文在读时也可能因该截断点生成破损字符串。不是只存在于一个未调用的私有helper。

## 精确合法输入与失败边界

`😀`在UTF-16为 `\uD83D\uDE00`。以下构造只是静态样本定义，没有执行：

| 入口字段 | 原始合法文本 | 当前确定的JavaString结果 |
| --- | --- | --- |
| routeName/medal/shopMedalName/poi.name | 39个BMP字符（如39个“路”）+😀+“尾” | 长度42>40；substring(0,40)保留39个BMP及high surrogate `\uD83D`，丢弃其low surrogate，生成不配对代理项 |
| poi.catLabel | 15个BMP字符+😀+“尾” | 长度18>16；substring(0,16)留下15个BMP及high surrogate，丢弃low surrogate |
| 40上限正控 | 38个BMP+😀+“尾” | 截断到40恰好包含完整pair，现逻辑可正确保留，不应因修复把完整emoji删掉 |
| 16上限正控 | 14个BMP+😀+“尾” | 截断到16恰好包含完整pair，同上 |

输入本身Unicode有效；不配对surrogate由本服务自己的substring制造。Fastjson2最终会如何转义、客户端如何显示、MySQL编码是否拒绝须后续真实验证，**本packet不声称已运行见到某个具体serializer异常/替换字形**。但合法输入被规范器变成无效UTF-16边界这一事实不依赖上述外部行为。

## 既有controls处理必须保持

当前顺序是removeAll(`[\\p{Cntrl}]`)→trim→长度截断，不能直接在未清理原文上判断pair位置。移除换行等controls会改变截断点，后续回归应包含“controls移除后才恰好落在pair中间”的合法输入。

本项不把该regex升级成所有Unicode Cf、bidi、ZWJ/variation selector清洗，也不增加审核。默认Java POSIX Cntrl与trim的现有行为保持；没有证据授权从emoji里清除ZWJ或将普通合法非ASCII字符列为禁止。grapheme cluster截断与完整surrogate pair是不同层次，本项只防止服务自己拆开一对UTF-16代理项，不重新定义按用户可见字素计数。

## 交E05的最小修复建议（E01不实施）

保留原40/16/10 **UTF-16 code-unit预算**、controls/trim及默认值逻辑。只在确需截断时计算end=max；若end位于合法high/low pair中间（s[end-1]为high且s[end]为low），end减1，再substring(0,end)。这样最多返回max个code unit，不把长度合同扩大成max个Unicode code point（后者可能翻倍UTF-16/存储长度）。

不需要改DTO/Mapper/Controller/小程序调用者/依赖/DDL；现有Java Character.isHighSurrogate/isLowSurrogate即可。未截断的文本应原样保持既有清理结果；完整pair在预算内保留，跨边界pair整体不纳入输出。不要顺便新增“拒绝所有历史不配对surrogate输入”的策略，除非另有既定合同与精确批准。
