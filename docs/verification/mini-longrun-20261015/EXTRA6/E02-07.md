## 删除实际关联守卫

`chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CommunityPostServiceImpl.java` 的deleteComment有原@Transactional、principal/requestId/version校验及精确member/request/COMMENT_DELETE/commentId重放。它**没有预先locked(postId)或读评论再比较postId**；不能借用帖子delete的父行锁结论。

真正更新约束在 `chengyinhub-system/src/main/resources/mapper/business/CommunityPostMapper.xml` 的deleteComment：

- 同一UPDATE同时要求 `c.id=commentId AND c.post_id=postId`，错误配对零行；没有只按评论ID执行更新。
- 同时要求非DELETED、当前expectedVersion。
- operator必须为评论author_id，或为同一个postId的父帖author_id。另一帖的作者不能通过伪造postId获得这个EXISTS权限，因为c.post_id同时受限。
- 更新结果不为1立即409，recomputeCounts/outbox/saveCommandReceipt位于成功分支之后；错误配对不通过该分支改计数或发评论删除事件。

这是SQL原子关联条件，不需要为统一代码形式增加无实际反例的父帖锁。当前没有新增管理员角色分支，也没有缩窄评论本人/父帖作者对CHECKING或PENDING审批评论的原删除权限。

| 指定触发 | 当前实现静态结论 |
|---|---|
| post A + 属于post B的commentId | c.post_id条件失败，409，不进入副作用 |
| 另一帖作者以自己的postId拼接他帖评论 | 同上，不能利用自己帖子的author权限 |
| 正确postId/commentId但既非评论作者也非父帖作者 | owner/EXISTS条件失败，409 |
| 正确配对但expectedVersion过期 | 版本条件失败，409 |
| 已成功COMMENT_DELETE回执重放，传另一postId | 回执原身份仅绑定commentId，早返回为既有no-op，不更新任何评论/计数/事件；本项不擅自扩回执指纹或把no-op报成跨帖删除 |

## parent/root实际可达性

同类comment写入口中，parentId为正时先selectCommentForReply(parentId,postId,memberId)。该查询要求父评论c.post_id=请求postId，并执行父帖可见性及父评论状态/block/mute约束；然后rootId仅由该父评论的root_id或其id导出。没有parentId却传正rootId/repliedToMemberId直接400。新评论的post_id由当前请求帖文传入，repliedToMemberId也由父作者导出。

已检索主Java引用的insertComment调用点只有该comment入口；已审Mapper更新生命周期/审批/删除不改评论post_id/root_id。因此由合法初始root插入及同帖parent派生，可以维持同帖root链；未发现正常接口能凭客户端任意rootId构造跨帖关系。DDL索引不是复合外键证明：`chengyinhub-admin/sql/migration_community_post_platform_20260909.sql` 的root/parent只有索引，没有显式同帖外键。本项不把任意手工损坏/导入数据库当作已可达业务缺陷，也不增加DDL。

E02-06审阅发现selectComments展开root时未显式限制子评论post_id，但在上述写链不变量成立时，不足以直接证明跨帖泄漏；本项没有趁删除审计改查询。外部导入/历史修复来源若另有证据，应由协调者另给精确路径再审。
