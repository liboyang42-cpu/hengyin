## 问题与最小改动

`chengyinhub-xcx/utils/location/bg-tracker.js`：原 `finishSuccess` 仅检查 owner key。第一消费者回调中 force release 后重新 acquire 同 key，旧批次中同 key 的旧回调会借新身份收到 success。原 `finishFailure` 清 owners 后分发已摘出的 failed 数组，第一消费者 release 另一个消费者不能再取消其 fail。

每次 acquire 现在创建独立 owner/waiter 身份。success 分发要求当前 owner 正是该 waiter。分发期间批次保留在 `notifying` 中，release 按 key 取消；force 取消全部当前分发批次。failure 在清 owners 前收集匹配身份的 waiter，随后按取消标志通知，正常 fail 不依赖已清空的 owners，避免吞掉正常失败。notify 使用 finally 移除分发批次，保持重入时批次栈清理。没有新增自动重试或消费者异常吞噬。

保留原 owner key 幂等、最后 owner 才 stop、后台失败降级前台、旧成功满足新 owner、无 owner 晚成功补偿 stop、异步 stop 完成前不重启的既有逻辑。只读 play/roam 的 acquire/release 调用确认签名保持；调用者未修改。
