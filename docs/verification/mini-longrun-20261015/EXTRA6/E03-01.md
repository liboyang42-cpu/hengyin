## 具体缺陷与本队修复

`TopicRouteRuntimeServiceImpl.freezeThemeStory(session,state)` 原来只调用三参 `freezeEnding(topicId,raw,state)`；后者把 session=null 传入 evaluateEnding，选中结局正文因此走实时 chapterMapper。新局冻结 old 章、作者改 new 章、随后完成时，终态 result.story 可能归档 new，绕过本局 endingChapters。首批真实MySQL IT已写该调用链严格回归，但尚未运行。

本项只修改 `chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/PlayJourneyStoryServiceImpl.java`：新增已冻结签名

```java
public Map<String,Object> freezeEnding(Long topicId, String raw,
        TopicRouteEngine.State state, TopicRouteSession session)
```

四参入口把已有 session 交给现有 evaluateEnding，从而复用 endingChapter 的冻结正文、显式空映射不回填与缺键旧局回退，以及已有本局数值快照读取。evaluateEnding显式接收includeArchive：公开ending为true，freeze为false，生成前即阻止archive分支，绝不读取gameSessionMapper后再删除字段；四参也保持没有identity/photos/notes归档的原freeze结果形状，不扩展终态留存。不建立新会话、结果或正文真源。调用方raw仍按原JourneyStory.parse校验，不重排条件。

原三参入口委派四参并传null，保留原实时兼容正文、没有archive的原结果形状及原空剧情行为。没有新增HTTP/DTO字段、结局策略、内容政策、迁移或依赖。
