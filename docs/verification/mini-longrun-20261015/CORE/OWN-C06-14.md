replayTheme在insertSession重复键后确实继续enqueue/recordStageRestAction，但该现象本身不是重复业务副作用证据：ThemeBroadcastService.enqueue仅写待投递表、不投递消息；其Mapper用ON DUPLICATE KEY UPDATE id=id，migration_theme_runtime_20261004.sql已有uk_theme_event(session_id,member_id,event_id)。读取胜者child后enqueue遍历胜者state的events，原事件不能多造待投递行。stage-rest action用固定stage-rest:{chapterId}及现有session/member/action唯一键，recordStageRestAction捕获重复键并确认已有原action；只是登记receipt，不再修改胜者state，因此没有重复恢复hp/luck。

结论：本项指定“相同重玩并发输家重复投递/重复阶段恢复”未证实，不为了少一次调用改既有恢复/补偿路径，也不弱化持久唯一约束。不同实时版本交错可能需另审胜者冻结值与输家预计算stageRest差异，但不能把未复现的可能当本项已确认bug。真实MySQL并发及消息读回仍待集中验证；本次未编写镜像SQL字符串测试、未运行任何验证。
