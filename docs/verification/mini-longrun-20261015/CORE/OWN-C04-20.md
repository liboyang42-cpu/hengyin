# OWN-C04-20 — payment maker/checker precondition

SOURCE_DELIVERED_UNVERIFIED. Verification: NOT_RUN. No Java/Maven/MySQL or other manual validation executed.

## Reachable defect

MerchantPayableServiceImpl.markBatchPaid previously ran MakerCheckerGuard only when its ordinary selectById returned CONFIRMED, then always attempted markPaid. Interleaving: payment request by ops reads positive, unfrozen PENDING; concurrent confirmBatch by ops commits CONFIRMED/confirmed_by=ops; the first request skips the guard but its SQL now sees CONFIRMED and succeeds. Both paid_by and confirmed_by become ops. The service transaction does not make its ordinary SELECT a locking read.

## Existing contract and minimal change

MerchantPayableBatchMapper.markPaid and its XML require CONFIRMED -> PAID; MerchantPayableBatchController documents and reports the same restriction. PENDING direct payment was never allowed. Service now returns false for a non-CONFIRMED snapshot after the original progression guards; CONFIRMED always runs the original MakerCheckerGuard then the unchanged CAS. Existing trim and case-sensitive actor identity, amount/frozen guards, voucher check, roles, invoice rules and fees remain unchanged. Confirmed actor is not rewritten by any existing batch lifecycle transition. The SQL still protects concurrent frozen/amount/status changes. No lock or mapper expansion, no payout capability, and no Clawback changes.

## Regression source and limits

OWN_C04_20Test invokes the actual service with mapper doubles: a PENDING snapshot cannot reach a SQL stub that would return success after concurrent confirmation; same trimmed actor is rejected; distinct CONFIRMED actors retain CAS false/true propagation; PAID and missing status cannot invoke payment CAS. These are branch tests, not proof of MySQL interleavings. Real concurrency remains unexecuted.

Existing MerchantPayableServiceTest needs no fixture change: its success and CAS-result tests already use CONFIRMED; amount/frozen rejection remains before the new status check and its exact assertions remain intact. Existing B03AssetMybatisIntegrationTest covers amount/frozen races and normal distinct actors, not this stale-PENDING guard bypass. Prior baseline test results do not validate this change.
