## 创建草稿

CmsTopicServiceImpl.createTopicInternal先由saveDraft==1决定草稿身份；即便publishMode为simple，草稿分支也优先将status/userStatus置0，并在插入后setTopicIsDraft(topicId,1)。商家/俱乐部池开关不替代该草稿状态。

原创建流程对商业提审使用!saveDraft，对自办活动壳使用!saveDraft条件，V2组合送审同样要求!saveDraft。因此草稿不因携带招募日期或专业版字段直接触发公开壳/组合发布。ApiTopicController.createTopic的创意广场同步明确带legacyCommunityWritesEnabled && !saveDraft && publishToCreative==1，客户端保留开关不绕过草稿私有性。

## 编辑既有草稿

updateTopicByOwnerInternal从数据库selectTopicIsDraft读身份。只有chapterFlowV2 && 原草稿 && 显式saveDraft==0构成提交发布；saveDraft==1或未传仍keepDraft，传给rebuildTopicContent。重建里!draft才执行商业提审/refreshSelfHostActivity；keepDraft也阻止update尾部publishBeforeReview/submitTopicBundle。不能把已有V2显式saveDraft=0发布动作当成存草稿漏门禁。
