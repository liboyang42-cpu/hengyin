## 源码反证

`chengyinhub-system/src/main/java/com/chengyinhub/business/service/impl/CmsTopicServiceImpl.java`：

- saveChaptersAndNodes（4933起）先将旧chapterDTO复制到新实体，然后在4949明确setId(null)，通过insertCmsTopicChapter生成新ID。4959使用recordChapter(chapterDTO.getId(), chapterId)，输入是保留的真实旧身份与该行生成的新身份，不是章节数组下标。
- compileChapterFlow（4997起）的V2路径也在5036清新行ID，5046调用recordChapter(source.getId(), chapter.getId())。章节顺序另由compiled.getChapterSortId()生成，与身份映射分开。
- RouteNodeMaps.recordChapter（5334起）只为正旧ID/新ID建映射；重复正旧ID时抛IllegalArgumentException("章节 id 重复")，不会静默让后章占据前章身份。缺旧ID的新章不与其他新章共享假旧ID。
- persistJourneyStoryAfterChapterRebuild（3427起）把chapterOldToNew传给JourneyStory.remapChapterIds。域helper对真实chapterId引用按映射查找，缺映射沿原fail-closed拒绝，不按现数组位置猜原章节。
- 更新公开入口updateTopicByOwner/updateTopicByOwnerV2WithReview均有rollbackFor=Exception事务；重复旧ID异常不被重建流程吞掉。

因此，已有章节反向重排时sortId按新数组决定，但原章节引用按各自旧ID查到其新ID；本项“引用因位置映射而串位”的假设与实际实现不符。不为已有唯一映射重造同义代码。
