# OWN-C01-51 — Bank withdrawal preflight CAS-loser replay

Status: SOURCE_DELIVERED_UNVERIFIED. All verification: NOT_RUN.

## Static finding and existing invariant

BankWithdrawalCommandServiceImpl.submit runs current consent lookup, consumeBankWithdrawal and withdrawalRequest in one transaction. Under MySQL/InnoDB REPEATABLE READ, the consent lookup can establish a snapshot before an equivalent concurrent winner commits consumption. The losing consumeIfConfirmed UPDATE performs a current read, affects zero rows, but the old selectById fallback is a consistent snapshot read: it may still see CONFIRMED and reject the already-CONSUMED equivalent intent. This is a replay-availability defect, not evidence of duplicate debit. The real deployment isolation level was not inspected.

- Keep original null/owner check, CONSUMED action/request/fingerprint equality and stateError/expiry classification unchanged. No consent, confirm, reject, prepare, token, permission or monetary policy changes. No business DDL/API/dependency changes.
