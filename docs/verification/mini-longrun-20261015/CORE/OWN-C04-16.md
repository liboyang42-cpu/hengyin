实际代码：admit只在本人事务内插入新行，若另一不同requestId占同session active_slot则唯一键冲突，事务回滚。service.afterInsertCollision先读incoming requestId，存在则恢复其回执；不存在则inProgress(incoming ID)，原文案明确“上一条问题还在处理中”，NOT_RUN、REQUEST_IN_PROGRESS、retryable=true、retryAfterSeconds=1。

原active完成释放槽后，调用方若明确再次提交相同incoming ID，此前并未调用provider，可以首次受理；受理后同ID按既有持久回执重放，不再生成。不自动重发、不把本次读不到行混成provider已未知，不放宽user/request唯一身份。
