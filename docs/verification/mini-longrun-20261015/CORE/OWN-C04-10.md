# OWN-C04-10 — provider后持久化不可用不能谎报未调用

根因 C04-AFTER-PROVIDER-RECEIPT-UNAVAILABLE；结论 SOURCE_FIX。
交付 SOURCE_DELIVERED_UNVERIFIED；回归 NOT_RUN。未运行任何手动验证/编译/语法/diff-check。
业务源叠加C04-09不可变快照；该项原有20s时钟修复保留，不混为本项修改。

实际触发：generate已经返回审核后的答案；finish事务因数据库/日志失败，fallback当前read也失败或无行；原requestStateUnavailable却返回FAILED/NOT_RUN/retryable=true。另一个触发是finish已成功，但语音合成后的最终持久读不可用。两者都不能证明模型未调用，原返回分类错误，且会诱导当成明确失败新发请求。

最小修复仅NpcChatService：记录本worker是否已收到provider结果；生成后的finish与最终read携带该事实；provider专用AiProviderOutcomeUnknownException也携带既有未知事实。持久化不可确认/缺行/回滚后只读到原PROCESSING行时，沿原requestId返回已有PROCESSING/UNKNOWN/REQUEST_OUTCOME_UNKNOWN/retryable=false，不返回内存旧答案。能读到权威终态则仍按原持久行返回（包括删除后safeText=null的成功墓碑）。调用前已知未运行的存储故障分类保持原合同。

这是返回分类修复，不写新状态、不新增HTTP字段、不退款/重发、不绕过本人屏障，不将内存答案伪装持久成功。未知仍保留原请求查询；如果底层回滚后数据库仍暂时是原PROCESSING，本次已知provider结果不再被其旧NOT_RUN字段误导；不擅自篡改该持久回执或另造对账系统。

新增OWN_C04_10Test六类源码：finish+read异常；finish/read缺行；rollback后只读到原live PROCESSING；最终read在持久成功后失效；provider专用超时叠存储故障；调用前配置不可用仍沿原分类。均NOT_RUN，不声称数据库真实行为通过。

经协调者追加授权，只调整旧NpcChatServiceTest.oldWorkerCannotReturnOrSynthesizeItsUnsavedResult中的provider已返/finish0/读不到行分类为UNKNOWN/不可重试；不返旧答案、不写log、不合成断言保留。其调用前leaseLostBeforeProvider不可用断言未改变。
