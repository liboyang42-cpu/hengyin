## Reachable interleavings

CashWithdrawService.withdraw calls the channel outside its short financial transaction. While it waits, another sync/requery can observe SUCCESS and CAS the same original ID to a terminal state, or operations can freeze that row. The old accepted write unconditionally set status back to PROCESSING; ambiguous wrote UNCERTAIN unconditionally. Either could overwrite a terminal/frozen receipt. Separately syncOne can hold an old PROCESSING row across queryTransferResult; its late UNKNOWN/PROCESSING receipt update could overwrite channel status/detail after a competing observer completed/froze the same ID. An old timeout check could then proceed from that stale row.
