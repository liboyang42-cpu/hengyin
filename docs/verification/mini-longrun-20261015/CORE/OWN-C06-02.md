静态调用链：GameSessionRuntimeServiceImpl.command 是 rollbackFor=Exception 的公开事务方法。初始 selectReceipt 未见行时可并发进入；insertReceiptClaim 使用 INSERT IGNORE，原唯一身份是 activity_id/actor_member_id/request_id，并非action。只有返回1的线程进入dispatch。返回0的线程使用 selectReceiptForUpdate 当前锁读，而非重复普通快照读；唯一键等待获胜事务提交后读同一原回执，再经replay校验requestHash。异体请求返回GAME_IDEMPOTENCY_CONFLICT，未放宽请求身份。获胜者业务写入和completeReceipt同事务；completeReceipt条件要求原id、PENDING及原hash，失败抛异常回滚。

结论：该具体“两个线程同时首次未命中导致重复dispatch”线索由现有数据库唯一键、插入返回值分支和当前读保护，不新增同义锁/DDL。未修改生产源；没有编写只重复SQL字符串的回归。既有GameSessionRuntimeServiceImplTest含原回执重放、不同body冲突；后续真实MySQL并发验证仍需同时首查未命中、胜者提交/回滚两种受控交错，不能以此源码反证称实跑通过。未运行任何验证。
