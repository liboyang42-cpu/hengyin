# OWN-C06-04 会话CAS失败原子性

NO_CHANGE_SOURCE_REVIEW；SOURCE_DELIVERED_UNVERIFIED；NOT_RUN。

静态依据：command公开入口@Transactional(rollbackFor=Exception.class)，ApiGameSessionController经runtimeService代理进入。dispatch及bumpSession为同对象私有方法，不创建独立提交事务；station/submission/player outcome/story等runtimeMapper写入均在原命令事务内。bumpSession调用updateSessionCas，其WHERE包含id、expectedRevision、fromStatus及终态排除；受影响行非1立即抛GameSessionException（RuntimeException），没有在command/dispatch吞掉。completeReceipt仅在dispatch返回后执行，完成回执失败也抛同类异常；故成功子表写但session CAS失败时，原PENDING回执与子表写一并回滚。失败回执由控制器在原调用异常后独立recordFailure，不能把原部分写变成成功。

结论：针对本项“业务子表修改后session revision CAS失败仍半提交”未找到实际缺陷，不添加同义事务注解或改CAS政策。该结论针对同DataSource的数据库写；消息/外部服务最终一致性不是由此静态证明。后续专用MySQL需强制子表成功后CAS=0并独立连接核子表、revision、回执回滚，当前未运行测试，不能声称事务实际验证通过。
