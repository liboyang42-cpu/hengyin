# OWN-C06-03 明确失败回执归属

NO_CHANGE_SOURCE_REVIEW；SOURCE_DELIVERED_UNVERIFIED；NOT_RUN。

静态溯源：ApiGameSessionController.command通过注入的runtimeService代理调用command；GameSessionException逸出command导致该事务回滚后，控制器才调用独立REQUIRES_NEW的recordFailure。没有同类内部调用绕过该事务边界。recordFailure检查actor/member/activity/requestId/requestHash/action；未形成指纹的坏参数不会持久化伪失败。初始已有回执直接返回；并发初始未命中时仍只调用insertReceiptClaim，即INSERT IGNORE受原三元唯一键约束，绝不UPDATE回执。若另一成功事务先占有原key，失败插入等待后忽略；若失败先占有，成功命令插入失利后读取并replay该原失败，不能追加业务写。completeReceipt更新还要求PENDING及相同hash，无法把FAILED改APPLIED。

结论：未发现失败记录覆盖已APPLIED事实的路径，不改正确的insert-only设计。recordFailure不比较已存在body是因为它不返回/修改已存在回执，查询仍绑定本人、原活动、原requestId；异体命令冲突由command.replay处理。不增加权限、政策、唯一键或DDL。没有为凑项添加重复实现测试；后续应在专用MySQL验证success提交/失败插入交错，当前未运行任何验证。
