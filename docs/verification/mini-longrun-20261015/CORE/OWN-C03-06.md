## 已有保护反证

ApiTopicController.publishDraft先按现有scope解析会员归属，再检查本人和草稿状态。其注释也明确预读只是提示；真实竞争保护在service，而不是相信controller的selectTopicIsDraft。

CmsTopicServiceImpl.publishDraft与publishDraftWithReview均有rollbackFor=Exception事务。二者进入publishDraftInternal第一步就是cmsTopicMapper.clearDraftIfDraft(id)，影响行数<=0立即返回，未查询/创建活动壳，也不送审核。

CmsTopicMapper.xml.clearDraftIfDraft实际SQL为：update cms_topic set is_draft=0 where id=#{id} and del_flag=0 and is_draft=1。相同主题并发请求竞争同一行时，只有第一条清标成功的事务继续；后者等待后看到状态不再是草稿，不进入副作用。第一条异常则事务回滚原标记，并非先独立提交标记再执行发布。

发布路径简易版在末尾ensureSelfHostActivityShell；专业版通过submitTopicBundle→publishBeforeReview补建，末尾不会再给pro重复调用简易补建。已有ensure分支还查询已有活动壳并跳过。CmsTopicPublishDraftTest源码可见notDraft_returnsFalse_noStatusMutation及壳已存在不重复建的原回归；只读未运行，不把mock测试当真实并发验收。

## 合同限制

这里已有的是同草稿转换/副作用最多一次的保护，HTTP第二次仍可能返回“不是草稿”，不是持久化请求回执重放接口。create丢响应无ID问题不由此解决。不得为了说成“幂等”新增requestId、放宽草稿前置、改审核/额度政策或将非草稿再发布。

本项没有证实新重复转换缺陷，仅新增本证据；不复制现有回归。下一项OWN-C03-07审草稿公开副作用，全部保持NOT_RUN。
