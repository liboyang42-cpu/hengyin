## Existing defect and boundary

PlayerRunSessionMapper.upsertPaused previously replaced an existing scope unconditionally. A delayed save at 100 could overwrite PAUSED at 200 or revive ENDED at 300. markEnded likewise allowed an old clear at 100 to erase a PAUSED save at 200. Both operations address existing member/activity/self-topic scopes; neither requires a new API or field.

The existing client savedAt comparison treats an ENDED timestamp equal to a local save as authoritative. The existing ShareSnapshotRunSessionMybatisIntegrationTest.runSessionUpsertReadAndClearAreScoped explicitly expects missing-scope clear to return zero and permits a newer save to reopen an older ENDED row. Those boundaries are preserved.

## Minimal source change

Only PlayerRunSessionMapper.xml changes in production. ON DUPLICATE KEY UPDATE accepts a newer timestamp, or an equal timestamp while the existing row is PAUSED. It rejects an older save and an equal-timestamp save against ENDED. saved_at is assigned last because MySQL evaluates single-table assignments from left to right; all timestamp guards therefore compare the original stored timestamp. Changing run_state first does not change the guard result: an accepted newer save remains newer until the last assignment, and a PAUSED tie remains PAUSED.

markEnded adds saved_at <= incoming savedAt to the existing scoped UPDATE. An equal-time clear wins and older clears affect zero rows. Missing rows still produce zero; no tombstone is inserted. A strictly newer save still reopens ENDED. Existing authorization, interface/controller, schema, wire fields and scope predicates are unchanged.
