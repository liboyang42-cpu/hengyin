# 商家与俱乐部功能竞品能力基准（2026-08-23）

## 1. 结论先行

对标 Meetup、Eventbrite、活动行、百格活动和 WildApricot 后，“功能完整”不能按页面数量判断，必须至少形成两条可真实闭环的链路：

1. **商家/主办方闭环**：创建发布 → 营销获客 → 报名/售票 → 现场签到核销 → 退款与结算 → 数据复盘 → 跨活动复购 → 风险治理。
2. **俱乐部闭环**：建会/入会 → 角色分工 → 组织活动 → 成员沟通 → 会费/活动收费 → 出勤记录 → 内容沉淀 → 成员与内容治理。

只有“能创建、能展示、能报名”属于可用雏形，不足以判定完整。当前行业基础线已包含退款策略、名单管理、手工或二维码签到、成员沟通和基础治理；CRM 自动化、跨活动用户画像、精细权限、自动续费、硬件签到和平台级风控属于进阶差异化。

## 2. 研究范围与口径

### 2.1 竞品定位

| 平台 | 本次用作什么基准 | 官方资料揭示的核心侧重 |
|---|---|---|
| Eventbrite | 全球活动交易与主办方运营 | 售票、营销、现场、财务、团队权限、分析和退款治理一体化 |
| Meetup | 线下兴趣社区与俱乐部 | 组建群组、成员角色、持续活动、讨论沟通、会费、出勤和平台治理 |
| 活动行 | 中国本地活动平台与主办方 SaaS | 微信生态传播、票务、报名审核、现场验票、主办方主页、用户沉淀 |
| 百格活动 | 中国企业级活动/MICE 运营 | 活动建站、营销自动化、CRM、复杂现场服务、会后分析 |
| WildApricot | 俱乐部/协会会员运营 | 会员等级、续费、目录、活动、沟通、会员内容和财务自动化 |

这五个平台服务的主任务不同，不能简单比较“谁的功能最多”。本报告取其共同闭环作为**行业基础**，取自动化、跨活动数据、复杂现场和精细治理能力作为**进阶差异化**。

### 2.2 分级规则

- **行业基础**：在多个相关平台中已有官方功能证据，或是完成交易/履约/社群闭环不可缺失的能力。
- **进阶差异化**：需要跨活动数据、自动化、细粒度权限、复杂财务/治理或专用现场设施，只有部分平台提供。
- 表中“未作为证据”不等于竞品一定没有该功能，只表示本次可访问的一手资料不足以用它作肯定依据。
- 资料均来自产品官网、官方帮助中心或官方应用商店页面；功能与价格会变化，结论是 **2026-08-23 可访问资料快照**。

### A 类最低验收线

若要判定“商家功能完整”，至少要同时满足：

- 商家能独立完成一场活动从草稿到发布，不依赖平台人工改数据库或代操作。
- 免费报名和收费票都能形成订单/报名记录；容量、重复报名和票状态有约束。
- 参与者获得可核验凭证；现场能手工兜底，重复或无效凭证不能假绿。
- 取消/退款/结算不是客服口头流程，而是有状态、时限、金额和通知的产品链路。
- 商家能看到浏览、报名、支付、签到、退款的基础漏斗，并能合法导出或复用用户。
- 名单、财务、退款、核销不能靠共享主账号；至少有角色或权限隔离。
- 活动、商家和参与者均有投诉/举报/封禁或升级处理入口。

### B 类最低验收线

若要判定“俱乐部功能完整”，至少要同时满足：

- 俱乐部不是一个普通内容标签：它有独立身份、成员关系、规则和入退会状态。
- 主理人能把活动工作交给协作者，但协作者不会因此获得所有会员或财务权限。
- 活动、成员、会费/活动费和出勤记录能关联，不能分别成为互不相认的孤岛。
- 群发、活动通知、成员讨论和私信至少有一条可用的持续沟通链路。
- 俱乐部能沉淀历史活动、成员或内容，让一次活动结束后关系不会清零。
- 主理人可管理违规成员和内容，普通成员也能绕过主理人向平台举报俱乐部/活动/成员。
- 付费俱乐部必须具备会费周期、支付状态、退款/退出政策和财务可追溯性；否则只能判“兴趣群”，不能判完整会员组织。

## 5. 用于城瘾审核的成熟度判尺

| 等级 | 商家/主办方 | 俱乐部 |
|---|---|---|
| L0 展示 | 仅有商家页、活动列表或按钮入口 | 仅有俱乐部列表/详情或内容标签 |
| L1 可执行 | 能创建活动、报名/购票、查看名单 | 能建会、入会、发活动、RSVP |
| L2 运营闭环 | 可核销、退款、结算、通知、看基础数据 | 有角色、沟通、出勤、移除/封禁、基础收费 |
| L3 增长闭环 | 有渠道归因、CRM、跨活动标签/触达、复购 | 有会费自动化、会员等级、分群、内容沉淀和留存数据 |
| L4 平台化 | 有精细 RBAC、复杂现场、财务审计、平台风控与企业集成 | 有多层组织、精细权限、平台 Trust & Safety、申诉留痕与开放集成 |

**建议判定规则**：只有达到 L2，才可称“核心功能完整”；L1 只能称“主流程可用”；L3 以上才接近成熟线下活动 App 的竞争能力。审核时每个能力都应分别核验 UI 入口、权限、后端收据/状态、失败路径和独立负控，不能用按钮存在或接口 200 代替闭环证据。

## 6. 对产品决策最重要的五个洞察

1. **商家与俱乐部不能共用一套“发布活动”模型就算完成。** 商家核心是交易、履约、结算和复购；俱乐部核心是持续成员关系、分权、沟通、会费和治理。
2. **活动后的状态决定产品是否形成壁垒。** Eventbrite/活动行/百格都把名单、渠道和活动表现带回下一场；Meetup/WildApricot 把出勤、会员、沟通和续费带回长期组织。
3. **退款和治理已是基础能力，不是上线后再补的后台流程。** 成熟平台让退款政策在购买前可见，并为取消活动、纠纷、违规活动和举报提供明确路径。
4. **中国场景的差异化重点在微信传播与复杂现场。** 活动行和百格把小程序码、邀请海报、微信通知、RFID/人脸/闸机/胸卡等做成能力层；但这些应建立在报名、票状态、退款和数据闭环之上。
5. **“有 CRM”必须用跨活动可复用来证明。** 单场名单不是 CRM；最低证明应包括统一用户档案、跨活动标签/备注、合规分群触达和来源/行为回流。
