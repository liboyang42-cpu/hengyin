# 游玩页重设计 · 设计文档（沉浸式城市探索）

> 日期：2026-06-21 · 分支：feat/topic-route-map
> 目标：把买票后进入的「游玩页」从"待办清单"重做成**地图优先、深色沉浸的城市探索游戏**：玩家边走边玩（citywalk），看章节叙事文字、扫码/GPS 到达、含模板的节点进答题，逐站点亮、逐章推进。

---

## 0. 一句话结论

现在的游玩页（`pages/play/index`）是一张纯文字节点清单，离手册定位的"宝可梦式城市探索游戏"很远。本设计以**地图为主界面**、**章节首次全屏过场 + 可重看**、**深色沉浸（与广场 Strava 改版统一）**为骨架，复用已有 `route-map` 组件与模板答题引擎，依赖一批已存在但未下发的数据字段。范围 = 游玩页前端重设 + 所需后端（P0：`/api/play/nodes` 补字段、新增 `/api/play/arrive`）。

---

## 1. 锁定的设计决策

| 维度 | 决策 |
|---|---|
| 核心骨架 | **地图优先 · 探索流**（地图是常驻主界面，玩家定位居中，节点是图钉） |
| 章节叙事 | **首次进章全屏过场 + 之后可重看**（顶部章节条点开重看） |
| 视觉基调 | **深色沉浸**，与广场 Strava 改版统一（`#0a0300` 底 / `#FC4C02` 珊瑚橙） |
| 解锁规则 | **跟随主题模式**（`mode` 字段）：`mode=1` 城市定向 → 线性闯关（按 `sortId` 依次解锁）；`mode=2` 自由探索 → **全节点开放、自由选路** |
| spec 范围 | **前端重设 + 所需后端 P0**（nodes 补字段 + /arrive）一起写 |

> **两种主题模式（`mode`，主题/票务级，现有字段，见 `OmsTicket.mode` / `CmsRegistrationMerchant.mode` / `info.mode`）：**
> - **`mode=1` 城市定向**：线性、有"下一关"递进感、章节叙事强；图钉有"未解锁(锁)"态。
> - **`mode=2` 自由探索**：所有节点一开始即可前往，玩家自由选路（集章/集邮式）；**无"未解锁"态**，图钉只有"可前往 / 已点亮"两态；"下一站"卡改为"离你最近的未完成节点"。
> 两种模式共用同一套地图骨架、节点卡、扫码/到达/答题流；差异仅在**解锁规则**与**图钉态**。

## 2. 信息架构

```
主界面 = 地图（常驻）
  ├─ 顶部章节条：当前章名 + 点亮进度(2/5) + 「重看本章过场」入口
  ├─ 中部深色地图：
  │     · 玩家定位（白点描橙）
  │     · 节点图钉态（随 mode）：
  │         - mode=1 城市定向：已点亮(橙·盖章✓) / 进行中(橙·脉冲环) / 未解锁(灰·数字+锁)
  │         - mode=2 自由探索：已点亮(橙·盖章✓) / 可前往(橙·数字，全部可点)  —— 无锁态
  │     · 路线 polyline（贴路线 routeGeometry 优先，节点直连兜底）
  └─ 底部「下一站」卡：节点配图 + 名称 + 距离/步行时间 + 主按钮(导航 / 我到了)

叠加层（非常驻）
  ├─ 章节过场（全屏）：章节大图 + 章名 + description + 里程/时长 + 「开始本章」
  │     首次进入该章节自动触发；之后由顶部章节条手动重看
  ├─ 章节完成小过场：本章节点全亮时的庆祝 + 引出下一章
  └─ 节点详情卡（半屏 sheet）：点图钉 / 到达时弹起
        节点图 + 名 + 营业时间 + description 故事
        → 到达手段：扫码 / GPS 自动点亮
        → 含 templateId 才显示「进入答题」
```

界面分三个可独立理解的单元：
- **PlayMap**（地图组件，fork 自 `route-map`）：渲染底图、玩家定位、三态图钉、路线；对外事件 `nodeTap(nodeId)`、`arriveInFence(nodeId)`。
- **ChapterIntro**（章节过场层）：输入章节对象，输出「开始/关闭」。
- **NodeSheet**（节点详情卡）：输入节点对象 + 完成态，承载故事 + 扫码/到达/答题动作。

## 3. 节点交互流（线性解锁）

```
进入游玩页
  → 拉 /api/play/nodes（含 mode + 章节/坐标/图/故事/模板/进度）
  → 焦点节点：
       · mode=1 城市定向：第一个未完成且已解锁的节点（= 上一完成节点的下一个 sortId）
       · mode=2 自由探索：离玩家最近的未完成节点
  → 若该节点所属章节首次进入：全屏章节过场 → 「开始本章」落到地图

点节点图钉（mode=1 仅当前节点可点；mode=2 任意未完成节点可点）（或走进 GPS 围栏自动弹）
  → NodeSheet：看 description 故事 + 营业时间
  → 到达此站：
       ① 扫码打卡  → POST /api/play/checkin
       ② GPS 到达  → 进 50m 围栏自动点亮 → POST /api/play/arrive
       （节点无坐标时只走扫码；高价值/发券节点保留扫码强校验）
  → 到达成功后：节点有 templateId 才出现「进入答题」
       · validationMethod=1 文字题（可输入弹层）
       · validationMethod=3 选项题（看题面 → 选 A/B/C/D）
       · POST /api/play/answer
  → 完成单节点：盖章动效 + "+N 分"飞入 → 解锁下一站 → 自动展开下一站卡
  → 本章节点全亮：章节完成小过场 → 下一章过场
  → 全主题节点全亮：通关 → 城市足迹卡（P2）

未解锁节点（仅 mode=1，灰锁）：点击只提示"先完成上一站"，不弹故事/答题
```

解锁判定（按 mode）：
- **mode=1 城市定向（线性，前端 + 后端双保险）**：
  - 前端：节点按 `sortId` 升序，`done` 之后第一个未完成节点为"进行中"，其后全部"未解锁"。
  - 后端：`/arrive` 与 `/answer`/`/checkin` 校验"该节点的前序 sortId 节点是否均已完成"，否则拒绝（防止扫后面的码跳关）。
- **mode=2 自由探索（全开）**：所有未完成节点均可前往/完成，**无前序校验**；后端仅做围栏/答案/报名校验。前端图钉无锁态，"下一站"卡指向就近未完成节点。

## 4. 状态与边界处理

| 场景 | 处理 |
|---|---|
| 坐标系 | 全链路 gcj02（`wx.getLocation` / `wx.openLocation` / 后台录入 picker 一致）。围栏用 Haversine，默认 50m。 |
| 定位权限 | `wx.getLocation` 精确定位是**受限接口**，需 mp 后台「地理位置接口」申请开通 + `app.json` 加 `getLocation`/`scope.userLocation`。首次申请前置全屏说明（NRC priming）。拒绝授权 → 降级为手动「我到了 / 扫码」。 |
| 节点无坐标 | `/arrive` 无法围栏判定 → 仅展示扫码；地图该图钉用列表态兜底。需一次存量坐标回填 + 确认后台节点级 map picker。 |
| 营业时间外 | 用 `businessTime` 显示"营业中/已打烊"；打烊节点 NodeSheet 提示，不阻断但不误导。 |
| 离线/弱信号 | 节点数据进页面后本地缓存；断网仍可看图走位；`/arrive`/`/answer` 失败可重试、不丢已得进度。 |
| 防作弊 | `/arrive` 信任客户端上报坐标（可被模拟定位绕过）。发券/高价值节点保留 GPS+扫码双重；普通节点 GPS 即可。 |
| 活动有效期 | 票已买但活动已结束 → 游玩页只读（按 `CmsActivity` 起止时间判定）。 |
| 「到点即完成」bug | 现状 `validationMethod=0/null` 节点无完成路径 → 由 `/arrive` 提供完成路径，彻底修掉阻断 bug。 |

## 5. 数据契约（后端 P0）

### 5.1 `GET /api/play/nodes` 补下发字段
`CmsTopicNode` / `CmsTopicChapter` 实体已有，仅需 `m.put`：

主题级新增：`mode`（1 城市定向 / 2 自由探索，从活动对应主题或玩家所购票务解析），前端据此分支解锁规则与图钉态。
节点级新增：`longitude` `latitude` `imgUrl` `description` `nodeTime` `businessTime` `chapterId`
路线/章节级新增：返回结构补 `chapters[]`（含 `name` `description` `imgArr` `totalMileage` `totalTime` `routeGeometry`），节点按 `chapterId` 归属、按 `sortId` 排序。
> `routeGeometry` 用于地图贴路线 polyline；不补则地图只能画直线兜底。

### 5.2 新增 `POST /api/play/arrive`
- 入参：`{ activityId, nodeId, longitude, latitude }`
- 逻辑：
  1. 登录 + 报名成功校验（复用现有 `isRegistered`）。
  2. 节点属于该活动主题校验。
  3. **线性解锁校验（仅 mode=1）**：前序 sortId 节点均已完成，否则 `error("请先完成上一站")`；mode=2 自由探索跳过此校验。同样的 mode 判定要补到 `/checkin` 与 `/answer`。
  4. 节点有坐标时做 Haversine 围栏校验（默认 50m），超出 `error("还没到这一站附近")`；无坐标时按业务约定（建议拒绝 GPS、引导扫码）。
  5. 命中 → 复用 `advanceProgress(memberId, node, actId)`（幂等写进度 + `award(12)` 节点分 + 全完成 `award(13)` 通关分 + `grantTemplateCoupon`）。
- 返回：与 checkin 一致 `{ nodeId, firstTime, done, total, completed }`。

### 5.3 前端「我到了」分支
`pages/play` 的 `onNodeTap`：`validationMethod=0/null`（到点即完成）→ 取定位 → 调 `/arrive`。

## 8. 验收标准

- [ ] 含「到点即完成」节点的活动能正常逐站完成并通关，积分 12/13 正常到账（修阻断 bug）。
- [ ] 游玩页主界面是深色地图：玩家定位、三态图钉、路线均正确渲染。
- [ ] 章节首次进入触发全屏过场，可重看；章节文字（name/description/imgArr）正确展示。
- [ ] 点节点 → 看故事 → 扫码/GPS到达 → 含模板节点出现「进入答题」→ 答题走通。
- [ ] mode=1 城市定向：线性解锁，未解锁节点不可越级完成（前后端均拦截），图钉有锁态。
- [ ] mode=2 自由探索：所有节点开局即可前往/完成，无越级拦截，图钉无锁态，"下一站"指向就近未完成节点。
- [ ] GPS 围栏：devtools 模拟定位圈内命中、圈外拒绝各一次通过。
- [ ] 埋点漏斗就位：进入游玩 → 到达首站 → 完成首站 → 通关。
- [ ] 视觉三处橙统一为 `#FC4C02`。

- 不做步行路径规划 API（步行时间用 距离/80m·min 估算）。
