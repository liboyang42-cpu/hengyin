# 创建游戏(关卡编辑器)重构设计报告

> 文件:`pages/publish/temp/index`(小程序「创建游戏 / 创建模板」页)
> 日期:2026-06-23
> 范围:前后端均可改(全栈自由),所有功能一次做完,不分期
> 平台约束:微信小程序(可用能力:文字/选项、扫码 `wx.scanCode`、定位 `wx.getLocation`、拍照、音频播放;不做 AR)

---

## 0. 一句话目标

把现在这个"问答题 + 发券"的长表单,重构成一个**模块化的「关卡编辑器」**:玩家在 Citywalk / 景区里走到点位 → 解锁 → 玩这个关卡 → 完成 → 拿奖励。本页产出一个**地点无关、可复用的关卡**,地点/坐标/剧情主线在「主题/路线」层(`fabu`)绑定。

---

## 1. 产品定位(为什么这么改)

- **这是一个基于真实地点的 LBS 解谜/打卡游戏的"关卡素材"。** 单个关卡 = 一段体验:到达 → (读剧情)→ 完成挑战 → 拿奖励。
- **乐趣来自 5 件事**:① 剧情把人从 A 拉到 B;② 谜题逼你观察现场;③ 拍照打卡 / 社交炫耀;④ 提示防劝退;⑤ 进度/解锁/收集(进度解锁在路线层)。
- **现状只覆盖了"管道"(完成 + 奖励),缺"体验"(剧情/线索/拍照/提示/语音)。** 本次重构补齐节点级的体验层。
- **地点不在本页绑**:本页关卡是通用的;扫码内容、GPS 坐标、所属商家/景区在主题层放置该关卡时再绑定。本页的"扫码/GPS"完成方式只声明**用哪种方式过关**。

## 2. 现状问题清单(重构动因)

来自对 `temp/index.wxml(424行)/index.js(1326行)/index.wxss` 的审查:

1. **核心玩法机制被藏起来。** 「验证方式 / 反馈方式」藏在浮层(`openPop` → `pop-func`),默认 `validationMethod:0`(无需验证)、`feedbackMethod:0`,**默认产出无玩法空壳**。
2. **多个入口指向同一浮层,且与直觉相反。** 点标题区 `temp1`、类目图标 `col2`、浮动「+」`david_nsadd` 全部 `openPop`;真正的改标题浮层 `popTitle` 的触发函数 `openTitlePopup` 无任何控件调用 = 死代码。
3. **标题显示两遍。** 顶部 `temp1 .tit` 与卡片内 `游戏标题` 同为 `formData.title`。
4. **分区导航是坏的。** 标签(活动基本信息/通用设置/活动类别/规则说明)与卡片标题(基本信息/游戏规则)对不上;**两张卡片重复 `id="card4"`**([wxml:96/103]);"通用设置"无对应区块;`calculateSectionPositions` 查询失效。
5. **必填规则三套打架。** `*` 标星(标题/描述/玩家人数)、`(可选)`(难度/场所/材料)、`validateForm` 实际校验(强制 difficulty、强制类别)互相矛盾——UI 写"游戏难度(可选)"但代码空值拦截。
6. **错误只用 `wx.showToast` 一次报一个**,`errors` 对象收集了却不在 WXML 渲染行内错误。
7. **描述提示"不超过30字"但无 `maxlength`、无计数器。**
8. **命名混乱**:游戏 / 活动 / 主题 / 模板 / 节点 五个词指同一对象;入口叫「创建游戏」,落地写"模板活动标题",CTA 写"保存为我的模板"。
9. **无草稿、无预览、布局会跳**(条件卡片穿插出现)。
10. **代码 bug**:`bindPickerPlayersChange` 误写 `difficultyIndex:0`(应为 players);大量注释死代码;孤儿浮层(`popTitle`/`popDescription`)。

## 3. 目标信息架构(IA)

单页 + 固定区 + 模块区,底部主流程为"预览 → 草稿/发布"。

```
顶部:封面图 + 游戏标题(入口已预填,点此可改;只出现一次)
分区导航(吸顶,3 项,与真实区块一一对应):基本信息 · 规则 · 模块
─────────────────────────────
[固定] 基本信息
   游戏描述*(0/30 计数)
   玩家人数*  |  游戏时长*
   难度(选填) |  场所(选填)
   所需材料(选填)
   游戏类别*(标签,显眼)
─────────────────────────────
[固定] 游戏规则
   规则说明(文本)
─────────────────────────────
[模块区] 已添加模块(可加可删,配置上台面)
   ▸ 完成方式      (mechanic)
   ▸ 完成奖励      (mechanic)
   ▸ 剧情故事      (content)
   ▸ 提示          (content)
   ▸ 语音讲解      (content)
   [+ 添加模块]  ← 列出未添加的可用模块
─────────────────────────────
底部主按钮:查看预览
```

发布流程:**编辑 → 查看预览(玩家视角覆盖层)→ 保存草稿 / 发布游戏**

## 4. 模块规格(全部一次做完)

每个模块 = 一张台面卡片,标题行带「删除」;未添加时出现在「+ 添加模块」清单。配置全部就地,不再用浮层。

### 4.1 完成方式(mechanic,最多一个)
玩家如何过关。分段选择 + 选中后就地展开配置:

| 选项 | `validationMethod` | 就地配置 | 小程序实现 |
|---|---|---|---|
| 文字问答 | 1 | 问题 + 正确答案 | 输入框比对 |
| 选项问答 | 3 | 问题 + 2~4 选项 + 正确项 | 单选比对 |
| 扫码打卡 | 4 | (无,扫码内容路线层绑) | `wx.scanCode` |
| GPS 到达 | 5 | (无,坐标路线层绑) | `wx.getLocation` |
| **拍照打卡(新启用)** | **2** | 可选:需含元素描述 `photoRequireDesc` | 拍照上传,**提交即完成**(人工审核后置,`reviewStatus`) |
| 无需验证 | 0 | 无 | 到点即完成 |

> 旧值 `2` 原为禁用的"图片验证",本次复用为"拍照打卡"。

### 4.2 完成奖励(mechanic,最多一个,内部可多选奖励类型)
完成后给什么。三类可同时配置:

| 奖励 | 字段 | 配置 |
|---|---|---|
| 优惠券 | `couponId` | 选择我发布的优惠券(沿用 `/api/coupon/mypublishlist`) |
| 文字反馈 | `feedbackText` | 一段完成文案 |
| 勋章 | `medalImg` `medalName` | 上传勋章图 + 名称(从原"常驻"改为奖励模块内) |

`feedbackMethod` 语义保留(1 券 / 2 文字),勋章独立字段并存;三者可任意组合。

### 4.3 剧情故事(content,最多一个)—— 最高乐趣杠杆
玩家到达点位、开始挑战前先看的叙事。
- `storyText`:到达剧情文案(长文本,建议 ≤ 300 字)
- `storyImg`:配图(可选)

### 4.4 提示(content,最多一个)—— 防劝退
- `hints`:分级提示数组,1~2 条(`hint1`/`hint2` 或 JSON `hintList`)
- `answerReveal`:兜底"查看答案/解析"(可选)
- 玩家端:逐级解锁提示,最后可看答案。

### 4.5 语音讲解(content,最多一个)—— 景区强需求
- `audioUrl`:上传一段音频(创作者录制/上传)
- `audioDuration`:时长(秒,可选,展示用)
- 玩家端:到达后可播放(边走边听导览/旁白)。小程序用 `InnerAudioContext` 播放。

## 7. 校验规则(统一)

| 字段 | 必填? | 规则 |
|---|---|---|
| 游戏标题 | 是(入口已填) | 非空 |
| 游戏描述 | 是 | 非空,≤ 30 字(`maxlength` + 计数器) |
| 玩家人数 | 是 | 必选 |
| 游戏时长 | 是 | 必选 |
| 游戏类别 | 是 | ≥ 1 个 |
| 难度 / 场所 / 材料 | 否 | 不标 `*`,不校验(**修掉"可选却被拦"**) |
| 完成方式(若添加) | 其配置必填 | 文字:问题+答案;选项:问题+≥2选项+正确项;拍照:可选描述 |
| 完成奖励(若添加) | 选的类型必填 | 券:选中;文字:非空;勋章:图+名 |

行为:**行内红字报错** + 提交时**滚动到首个错误字段**,不再用 toast 单条轰炸。`发布` 走全量校验;`保存草稿` 仅校验标题非空。

## 8. 数据契约(前后端,全栈自由)

### 8.1 `formData` 字段变化
保留现有字段;**新增**:

```
storyText        剧情文案
storyImg         剧情配图
hint1, hint2     分级提示(或 hintList JSON)
answerReveal     兜底答案/解析
photoRequireDesc 拍照要求描述(可选)
audioUrl         语音文件
audioDuration    语音时长(秒)
status           0=草稿 1=已发布
```
`validationMethod=2` 复用为"拍照打卡";`difficulty` 改为真选填(可空)。

### 8.2 接口
- `POST /api/template/publish` —— 接收上述新增字段;`status=1`。
- **新增 `POST /api/template/draft`** —— 保存草稿(`status=0`),返回草稿 `id`,支持覆盖更新。
- `POST /api/template/info` —— 返回新增字段,用于编辑/草稿回填。
- 列表(我的模板 `mytemplate`)—— 能区分并展示草稿态。
- 拍照打卡玩家端提交:存照片 + `reviewStatus`(自动过/待审),审核接口后置但**字段先留**。

> 具体字段类型/库表 DDL 由后端确认;若改线上库结构,走 `chengyin-db-migrate` skill 的只读预检 + 确认流程。
