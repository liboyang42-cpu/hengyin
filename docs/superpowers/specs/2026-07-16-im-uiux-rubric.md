# IM 消息中心 UI/UX 评分表(可核验)

> **为什么要这张表**:「95 分」如果由实现者自己拍板,就是自己给自己打分,毫无意义。
> 本表把分数拆成**每条都能用截图或代码验证**的项 —— 谁来打分都该得出同一个数。
>
> 立表时间:2026-07-16(第 1 轮评审前,**先立表再看结果**,避免事后对着结论凑分)

## 计分规则

- 满分 100,分 5 个维度各 20 分。
- **扣分只来自「对抗验证存活」的发现**:P0 扣 8 / P1 扣 3 / P2 扣 1。
- 一条发现只扣它**最相关的那个维度**,不重复扣。
- 单维度扣到 0 为止(不出现负分)。
- **每条扣分必须附**:截图证据或代码行号 + 引用的规范条款。无法验证的「感觉不精致」**不计分**。

## 五个维度(各 20 分)

### D1 信息架构与导航(20)
- 分类是否符合用户心智(私信/俱乐部/系统)
- 层级、返回、标题是否清楚
- 同一信息不重复表达(冗余强调也是缺陷)
- 参照:HIG Navigation · 微信「清晰明确」· M3 Tabs

### D2 视觉层次与排版(20)
- 一眼扫过去的视线顺序是否 = 信息优先级
- 字阶层级、字重对比、间距节奏(DS §3 8rpx 网格)
- 光学对齐(非仅数学对齐)
- 跨 tab / 跨行的一致性
- 参照:HIG Layout+Typography · M3 Lists/Type scale · Award 级工艺

### D3 色彩与无障碍(20)
- DS §2.1 颜色纪律(紫只给选中tab/进度条/稀有;主CTA黑白;蓝=链接/系统;红=危险/未读)
- 对比度(正文 4.5:1 / 大字·图形 3:1)
- 深色模式层次(HIG:深色下不要纯黑当唯一底)
- 触达区 ≥44x44pt(HIG)/ ≥48x48dp(M3)
- 参照:HIG Color+Accessibility · M3 · WCAG

### D4 交互与反馈(20)
- 每个动作有即时反馈(按压态 / toast / 乐观更新)
- 与微信原生 IM 的一致性(左滑、气泡、输入栏)—— 用户脑中的参照物
- 动效:该有的地方有吗(DS §7 fast140/standard220)
- 失败可恢复、不留假状态
- 参照:HIG Feedback · 微信 IM 惯例 · M3 State layers/Motion

### D5 状态完备性(20)
- 加载 / 空 / 错误 / 降级 四态齐全且各自正确
- 空态有 CTA(DS §5 参考实现 coop/list)
- 边界:长文本、3位数、脏数据、已删实体
- 参照:HIG Empty states · 微信三态规范 · M3 · DS §5

## 停止条件

- **总分 ≥95** 且 **零 P0** 且 **零 P1**(P0/P1 各扣 8/3 分,留着不可能上 95)
- 即:95 分等价于「无阻塞项、无该修项,最多 5 条打磨级 P2」

### R3 明细(2026-07-16,R2 的 12 项修复后)

7 条发现 / 全部存活 / 去重后 **5 个 distinct**(3 条 P1 是同一问题被三镜头独立抓到)。
脚本的 id 碰撞 bug 已修(强制镜头前缀 + 按索引配对),本轮存活数可信。

**P1 × 1(同一问题,三镜头独立抓到)**
- **`cy-avatar` 的 `size="sm64"` 是静默失效的 token**(D2 -3):
  `components/cy/avatar/index.js:17` 的 `map = { xs:48, sm:64, md:88, lg:120, xl:160 }` —— **键是裸的 `sm`**;
  而同文件 `:4` 的属性注释写的是 `// xs48/sm64/md88/lg120/xl160 或数字 rpx` —— **它公开了一套 map 根本没实现的词汇表,注释就是陷阱本体**。
  于是 `map['sm64']`=undefined → `Number('sm64')`=NaN → `|| 88` → **静默回退 88**。
  后果:头像实渲染 88rpx 而 `.row-avatar` 宿主盒只有 64rpx → 溢出 24rpx > `.row` 的 16rpx 行间距
  → **相邻行头像直接相撞**(09 实测两圆心距 ~83px < 直径 ~92px)。
  全仓 `size="sm64"` 共 5 处(chat 4 + member/index:145 1),**全部静默变 88**;其余调用方一律传数字
  —— 这正是它从未暴露的原因(别处没有 64rpx 宿主盒把它顶穿)。
  **与 `--cy-font-micro` 同类:静默失效的 token。** R1 的卡片行修复引入了其中 2 处。

**P2 × 4**
- `cy-empty` 的 CTA 硬写 `hover-class="none"` → 空态屏上唯一可点元素零按压反馈(R1#7 已把 cy-pressed 铺满本页所有可点元素,这是唯一破口)
- **R2 的静音图标修复没真修好**:我让「放大到 32rpx」,agent 照做、我看图也觉得能读了 —— 但放大 8 倍观察,它仍读作「禁止/∅」而非「静音的铃铛」。**根因不是尺寸是几何缺件**(只画了铃身,没画铃口/铃舌)。⚠️ 我接受了修法却没验证「目标是否达成」。
- `.hd-more` 三点用 `status-info` 蓝:M3 Top app bar 要求 leading/trailing 图标同族 on-surface、不用强调色;DS §2.1 蓝=信息/链接,而 `onMore()` 弹的是 actionSheet(查看俱乐部/举报/清空)——既不是链接也不是信息。**这是我造成的**:R1 让 ⓘ 变蓝,R2 换成三点却留着蓝。
- 同一发送人连发多条时每行无条件挂头像,系统不理解「消息串」(Award 镜头:组件堆砌 vs 设计意图)
