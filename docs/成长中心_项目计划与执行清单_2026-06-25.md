> 编写日期:2026-06-25
> 范围:小程序前端(chengyinhub-xcx) + 后端(chengyinhub,若依 Java) + DB(无需迁移)

---

## 1. 背景与现状

需求:做一个**成长中心**页面,核心包含 **排名(排行榜)** 与 **勋章**。

调研当前小程序后,发现「成长 / 等级 / 勋章 / 排名」相关能力**已存在但分散在 3 个页面、3 套接口**,且字段命名不统一,且**没有真正的排行榜**(只有「Top X%」一行文字)。

### 1.1 现有相关页面

| 页面 | 路径 | 现有内容 | 接口 |
|---|---|---|---|
| 身份中心 | `pages/role/center/index` | 头像、角色、`Lv.{growthLevel}`、积分/资产、本周收益、**当前排名 rankPercentage(Top X%)**、勋章墙 | `/api/growth/center`、`/api/medal/wall`、`/api/user/points/statistics` |
| 玩家成长页 | `subpackageP3/pages/growth/index` | `Lv.` + 经验值 expValue + 积分、成长任务 missions、徽章墙 badges | `/api/growth/center` |
| 勋章墙/我的成长 | `pages/member/badges/index` | `Lv.` + 累计打卡/里程/连续天数 + 徽章网格 | `/api/play/growth` |
| 积分页 | `pages/jifen/jifen` | 可用积分、积分任务、积分明细、积分商城(代码里「排名 TOP20%」被注释掉) | 积分相关 |
| 会员中心 | `pages/member/index/index` | `levelId` → group1~5.png 等级图标、角色徽章组件 roleBadge | — |

### 1.2 现有关键缺口

1. **没有排行榜列表**:后端只有「我的积分名次百分比」(`UmsMemberMapper.xml` 按 `ums_member.point` 排序算出 `TOP20%/40%…`),没有「取前 N 名用户」的榜单查询与接口。
2. **数据三套并存**:`/api/growth/center`、`/api/play/growth`、`/api/medal/wall`,等级字段有 `levelNo`、`level`、`levelId` 三种叫法。
3. **缺统一入口**:成长能力没有一个聚合页承载。

### 1.3 已确认的需求决策

| 决策点 | 选择 |
|---|---|
| 页面落地 | **新建独立成长中心页** |
| 排名形态 | **完整排行榜列表**(前 N 名 + 我的名次),非仅 Top X% |
| 改动范围 | **前端 + 后端一起** |
| 排名指标 | **积分榜 + 成长榜(经验值)可切换** |
| 榜单周期 | **全站总榜 + 周榜** |

即排行榜为 2(指标)× 2(周期)= **4 种组合**。

---

## 2. 数据可行性(已核实)

4 种榜单均可从现有表计算,**无需建新表 / 无需 DB 迁移**:

| 榜单 | 数据源 | 算法 |
|---|---|---|
| 积分总榜 | `ums_member.point` | 按 point 降序 |
| 积分周榜 | `ums_member_points_detail`(`change_points` + `change_type` + `create_time`) | 本周正向积分 sum 降序 |
| 成长总榜 | `member_growth.exp_value` | 按 exp_value 降序 |
| 成长周榜 | `growth_mission_progress`(`reward_exp` + `progress_date` / `create_time`) | 本周 reward_exp sum 降序 |

「我的名次」复用现有 `UmsMemberMapper.xml` 第 280–344 行的排名 SQL 模式(`@user_rank` 变量法)。

## 3. 目标设计

### 3.1 页面结构

```
成长中心页(独立,subpackageP3/pages/growthcenter/index)
├─ 成长头卡
│   头像 · 昵称 · Lv.N · 经验进度条(当前 exp / 升级所需) · 我的两个名次
├─ 排行榜区
│   ├ 指标 Tab:[积分榜] [成长榜]
│   ├ 周期 Tab:[总榜]   [周榜]
│   ├ 列表:名次徽标(前 3 名特殊样式) / 头像 / 昵称 / 分数
│   └ 吸底条:「我的名次」(名次 + 头像 + 分数)
└─ 勋章墙
    已点亮徽章网格(name + iconUrl),未点亮置灰(可选)
```

### 3.2 后端接口设计

**新增** `POST /api/growth/leaderboard`

请求参数:
| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| metric | string | `point` / `exp` | 排名指标,默认 point |
| period | string | `total` / `week` | 周期,默认 total |
| limit | int | 默认 50,最大 100 | 取前 N 名 |

返回 `data`:
```json
{
  "metric": "point",
  "period": "total",
  "list": [
    { "rank": 1, "memberId": 123, "nickname": "xxx", "avatar": "https://...", "score": 12000 }
  ],
  "me": { "rank": 87, "memberId": 999, "nickname": "我", "avatar": "...", "score": 320, "rankPercentage": "TOP40%" }
}
```

**可选优化**:把 `rank`(我的名次)并入现有 `/api/growth/center` 返回,使成长中心首屏一次拉全(等级 + 经验 + 排名 + 任务 + 勋章),排行榜列表切换 Tab 时再单独请求 `/api/growth/leaderboard`。

2. 排行榜可在 [积分榜/成长榜] × [总榜/周榜] 间切换,数据正确且排序正确。
3. 列表显示前 N 名(头像/昵称/分数/名次),前 3 名有特殊样式。
4. 吸底「我的名次」与列表一致;我在前 N 名内时高亮对应行。

6. 未登录 / 无数据 / 空榜单均有合理兜底,无报错。

## 7. 风险与注意

- **周榜性能**:周榜按明细 sum + join,用户量大时需确认 `ums_member_points_detail.create_time`、`growth_mission_progress.progress_date` 有索引;必要时后续改为定时任务预聚合(本期先实时查,前 100 名量级可接受)。
- **并列名次**:同分时名次处理规则需统一(本期采用「相同分数顺次排名」,即简单 row_number)。
- **生产 DB**:本期仅读查询,不改表结构、不写数据,风险低。
- **隐私**:榜单展示昵称/头像,确认产品侧允许公开展示(通常成长榜可公开)。
- **字段统一**:本次不强行收敛 `level/levelNo/levelId` 三套命名,成长中心内部统一用 `/api/growth/center` 的 `levelNo` + `expValue`,避免牵动旧页面。
