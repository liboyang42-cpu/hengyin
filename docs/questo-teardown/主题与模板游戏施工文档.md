### 0.5 凶手指认：一种成品模板，底层复用图片选择

**玩家操作是“看人物档案→选嫌疑人→确认指认→查看证据解释和结案后果”。** 比普通图片题多的是内容结构、提交前后的状态和反馈，不另造凶手判题算法。

- **人物卡：** 每人有稳定ID、头像、姓名、身份和已获证词；可展开只读档案，再返回选择。图片下有可读的姓名。未获得的证词不提前展示。
- **选择与确认：** 点头像只是选中，允许改选；明确点击“确认指认”才消耗一次正式机会。展开档案、误触、重试网络请求均不消耗机会。
- **两种模板规则：** 基础版单选凶手；证据版先选人、再选支持他的已获证物，以原两步QA/条件串联。仅选对人但理由不成立，不标成有依据结案。首版不扩任意人证组合推理器。
- **作者配置：** 人物资料、正确人物、是否需要理由、证物选项及已有取得条件、错误反馈、成功揭晓、继续调查/再次指认/跳过后续；提示/次数/代价直接引用0.4同一组规则。
- **反馈时机：** 选择前不返回correct/完整答案/未解锁提示；正式提交后才按该题规则返回反馈。两步题若要求最终才揭晓，应先核原QA的提前反馈行为，仅补必要的反馈时机配置，不能第一步就泄露完整结案答案。
- **跳过：** 显示作者写好的“未自行破案/接受揭晓”结尾，按跳过规则结算；不显示“你成功指认凶手”，不重复发成功奖励。关键线索题跳过后怎样继续必须提前配置并校验，否则发布报错或不提供跳过。

示例：三个原创人物卡，玩家查看已取得的证词，选择其中一人，再选择“时间记录存在矛盾”的证物，确认提交；正确后播放解释如何排除另两人，错误则收到不剧透的反馈并按剩余机会继续调查。真实作品仍需完整证词、证物、答案及可排除解释，不能只靠三张头像让玩家盲猜。

### 0.6 BE-16 / CT-07及计分校准的最新落地边界

已读用户新补的BE-16、CT-07、M.7和 `hint_probe.sh` 源码。阶梯可配置文字、图片、字/数字、答案与跳过，不要求每道题固定六级。`HelpPoolConfig`、首局帮助包、宝石/金币等来自参考产品，必须先映射城瘾真实账本；未实现币种不能生成可用消费入口。位置工具中扩半径/直接解锁和暂停扣15XP/分钟不在本轮启用，原定位与到达证明继续沿既有规则。

脚本只查询公开作品和榜单；`adjusted_score = stops * base - hints * cost - skips * base`，默认base=300/cost=30。故11站、3次提示、1次跳过得到2910是**模型模拟值**；公开榜首3600和600分别是两个作品的**观测值**。仅凭这组结果不能确认具体时间/连对/无提示加成，也不能排除作品版本或关数口径变化。脚本未实际消费提示并读取同一玩家前后分数，本轮仅核过源码，未重新请求竞品接口。

城瘾计分交付必须可对账：`净分 = 基准分 + 已获加成 - 提示扣减 - 跳过扣减`。每笔有原动作/回执、冻结规则版本和原因，显示原始分、各项调整和净分；重复请求不重复扣。这里不硬编码300或30，也不据竞品榜首反推并启用未经确认的加成。旧局、旧榜口径保留，新配置仅在明确支持的榜单范围生效。

本轮已启动新增后端实现。主题模板由T1/T2两位分别制作4套配置包与原采用链合同；共享玩法由G0–G6七位完成，D负责所有端UI改法的单文档汇总。模板配置包、源码接线、VPS验证、真实城市绑定和实地试玩分别签收，不把测试资源或源文件存在当成作品已发布。

## 5. 城瘾现在有什么，哪些不能直接说“全有”

### 5.1 本次核过的源码链

| 能力 | 当前源码事实 | 实施判断 |
| --- | --- | --- |
| 文字、单选、多选 | `AdvancedActionJudgement.submitQa` 使用 `qa.mode=TYPE/PICK`；多选按完整集合匹配；客户端提交输入/选项ID | 可复用；新题材只改内容。表达性选择用原 `judge=false`，不伪装客观正确答案 |
| 排序、匹配、分类 | 原 `SUBMIT_SORT/MATCH/CLASSIFY` 与判定方法存在 | 可复用；图片内容是否从作者保存到组件仍需独立核对 |
| 图片找物 | `hidden` 对应 `hiddenObject`，已有热点命中与去重 | 可做图中找物；不等于相机识别现实物体，也不证明现场对象确被观察 |
| 物品/资源/条件/结局 | `ThemeRuntimeEngine` 已有持有、取得、使用、消耗、条件和终局投影 | 可组合；数字物品不是现金/优惠券，不能由作者配置直接发真实权益 |
| 额外任务 | `GameplayRuntimeConfig` 已有 `quests.extraOnly/extraSlot` 和 `acts.completionRule`；`GameplayTaskEngine.actComplete`跳过extraOnly | 原资料的extraChallenge不需要直接新增同名引擎。优先补作者入口、展示和回归 |
| 案件册/背包 | 小程序 `play-topbar`、`theme-backpack`已有入口/视图；后端有冻结且按已取得来源过滤的线索投影 | 先验配置→取得→查询→显示；不是从零建案件册和库存表 |
| 角色与合作 | 共享运行有角色分配、确认、角色私密线索及队伍作用域 | 复用；退场/只读或未开放组合不能凭组件存在重新放开 |
| 计时 | `AdvancedGameRuntimeServiceImpl`保存节点运行deadline，恢复沿原deadline | 节点计时存在；不能把一个节点的timer当整个案件计时已完成 |
| 图文音频 | 章节blocks与题干媒体、问答组件图片/音频呈现存在 | 可制作媒体线索；仍要核保存、冻结、资源权限和各端显示 |
| 选项配图 | 小程序QA组件明确说明选项只有 `{id,label,fb,correct}`，图片/音频没有完整产出链 | 明确缺口，按G05补全共享链，不能只画图片选项按钮 |
| Hangman逐字猜词 | 本次相关后端和玩家/编辑目录未找到同名完整实现 | 用户已确认新增；不把 `typeIn` 或文字问答视为等价，按G10完成逐字状态链 |
| 到达读数专用字段 | 本次相关目录未找到 `arrivalReader/arrivalReading`实现 | 能先用原到达后叙事表达；结构化强度/日志若有真实消费需求，再按G08补 |

这些结论是源码核查，不是设备实跑。已有key的普通、R5、个人、队伍、公共世界模式有各自限制，不能把支持表里的key拼在一起便视为可发布。

### 5.2 两条采用路径继续分开

- 整套主题：原 `POST /api/template/topic-template/use` → 新主题草稿，当前返回 `data.topicId` 对象；完成城市、节点和引用绑定后再发布。
- 小游戏内容：原 `POST /api/template/adopt-draft` → 自己的个人模板 → 节点绑定该个人模板ID。公共库ID不直接当节点的 `templateId`。

第2至8项并行包正在补跨城绑定、预检/状态、内容冻结、恢复、队伍和交易等底座。首轮源码交付、后续修正、统一测试和部署是不同状态，本文件不预先把它们标成已上线。

## 6. 建议制作的8套范本

以下是施工规格与原创方向，不是已经写完的剧本。每套最终都要交付玩家正文、证据、反馈、提示、结局和发布者绑定表。

### T01 都市谜案

目标体验：玩家通过观察与核对推翻一份不可靠记录，并提出有依据的解释。优先普通悬疑，不依赖血腥题材、演员或AI对话。

- 因果结构：家中收到记录与请求 → 到现场核对一个具体矛盾 → 带着证据作出判断，人物对判断有实际回应。
- 复用：`qaText/qaPick/sort/classify`，原线索状态和案件册；需要分支时沿原路线/结局配置。
- 内容必须写：人物各自知道什么、为何求助、直接问清楚能解决什么、仍需现场确认什么；证据支持到什么程度。
- 城市绑定：可观察的稳定标识/位置关系、合法观察点、来源照片、事实值、答案别名、缺失时的替代证据。
- 首版结案：两步现有问答完成“判断+理由”，不承诺任意证据自由组合。选错保留对应反馈和继续调查路径。
- 签收：没有取得关键证据时不提前显示它；选对人物但理由不成立，不可冒充完整结案。

### T02 怪谈与幽灵追踪

目标体验：发现对象、整理记录、辨认不符合规则的那个对象。怪谈是虚构故事，读数是作者写的叙事反馈。

- 因果结构：家中收到一份异常记录 → 走访若干目标并核对规则 → 比较记录，识别目标并完成处置/告别。
- 复用：原任务、`qaPick`、物品/线索与案件册，选做任务按原extraOnly配置。
- 必须写：每个目标独有的证据、规则的实际文字、可以排除的解释、最终题的充分理由。
- 读数：先使用到达成功后的原叙事/反馈；需要强度卡片时按G08，无GPS到达事实不展示成功读数。
- 城市绑定：每个目标所需的地点特征及合法时段；夜晚不是默认要求。
- 签收：目标清单恢复后不丢失；重复到达不重复记取得、发奖励或自动播放；最后一题仍由原服务端判定。

### T03 亲子感官观察

目标体验：儿童观察，成人协助记录，两人交流后形成发现。以看、比较、排序为主，减少长文本和打字。

- 因果结构：在家建立一个需要修复/找回的具体目标 → 现场完成互补观察 → 用发现帮助角色完成一件事。
- 复用：`qaPick/sort/match/classify`；图片找物与现实观察分开标识。
- 必须写：儿童看到什么、成人提供什么帮助、双方如何沟通；不可把成人代点完所有题当作合作设计。
- 代码优先：G05图片选项，使儿童可以从图中选择；题干配图不是图片选项已完成。
- 替代：声音、吹气、方向等设备交互仅在各端确实支持时使用，提供作者批准的客观题替代；不默认引入AI识别。
- 签收：关声可完成；图片加载失败有可辨认的文字等价内容；普通节点答题不增加未经批准的付费重试或次数惩罚。

### T04 年代追索

目标体验：从档案与现状的差异理解一次变化，重建事件顺序，而不是宣称手机能回滚真实世界。

- 因果结构：收到一份有日期的旧记录 → 现场确认哪些信息仍成立、哪些已变化 → 重建时间线并决定怎样保存/讲述这段经历。
- 复用：图文/音频blocks、`sort/qaPick/qaText`、已核实的状态条件。
- 必须写：档案内容与出处、虚构人物部分、变化发生时间、推理的未决替代解释。
- 城市绑定：历史照片使用条件、现状对应关系、可复核时点。当前看不到某物，不直接证明过去也不存在。
- 首版不需要AR、三维录像或进度倒带。需要“重看档案”时做只读回顾，不重发完成或奖励。
- 签收：换城市后不仅换地名，连档案、观察和答案一起重绑；历史事实缺依据时不能当唯一正确答案。

### T05 城市寻宝与观察寻物

目标体验：根据发现缩小搜索范围，取得有意义的线索或数字纪念物。

- 因果结构：家中拿到起始线索 → 在实际场所查明它指向什么 → 找到目标并揭示为何值得寻找。
- 复用：问答、图片找物、任务/物品、条件和原路线。
- 三种模式必须分清：图中找物使用热点；现场观察使用可验证问题；实物寻找需要声明物料、放置许可、复位和回收负责人。
- 默认版本不埋宝箱、不要求商家配合、不要求翻动公物或询问路人。
- 选做线：沿extraOnly配置，完成主线即可收束，未做支线不被算成主线失败。
- 签收：两个城市的线索逻辑相同、现场事实各自成立；重复领取和跨局借用道具被原围栏拒绝。

### T06 建筑、艺术与地方文化

目标体验：眼前可见的细节改变玩家对一处地方的理解。可以是发现、解释或一次有目的的停留，不要求每站出题。

- 因果结构：带着一个具体问题出发 → 从两个视角/两组材料获得信息 → 解释差异或作出有后果的选择。
- 复用：图片题干、问答、排序/匹配、找物与blocks。
- 城市绑定：实际构件/图案、公开通路、观察位置、文字出处、遮挡/维修替代；不编造“每座亭子都有铭牌”。
- 图片选择按G05；需要图片排序时先核原sort的作者数据和renderer，只有图片接线缺失才扩展，判定仍按原itemId顺序。
- 签收：纯看屏幕而不观察现场不能轻易得到全部必要信息；但休息、对话和结束场景可以没有题。

### T07 节日与原创奇幻

目标体验：帮人物修复一个具体问题，选择、物品与结尾发生呼应。节日是版本和包装，不是新引擎。

- 因果结构：在家收到求助 → 分别恢复/取得所需条件 → 玩家选择影响人物的回应和收束方式。
- 复用：章节blocks、问答、物品/状态、条件、分支/结局；多人版再接原角色与队伍状态。
- 内容分两版：常年可玩的原创奇幻、明确开放日期的节庆版。没有真实布置时，剧情不能要求现场存在节庆装置。
- 单人版角色通过预录内容/远程消息出现；不能写成并不存在的真人到场接走道具。
- 签收：选择后有写好的实际回应，不能只显示不同选项却所有结果完全相同。

### T08 高级调查结案

目标体验：玩家自己决定调查顺序，取得证据，再作指认；关键挑战可复用既有计时，不新增全案时钟。

- 基础版：复用T01的两步判断与理由、既有案件册/背包和条件，先把一条完整调查链做通。
- 调查版：作者写齐已获证据门槛、指认题和后果；按G06接图片选择，按G09复用既有计时，不扩自由推理。
- 状态分开：已到达、已取得线索、已读、已提交指认、判断成立、案件已结束、获得奖励，不能用一个“完成”布尔值覆盖。
- 结案前可回到调查，但回看不重置服务器时间。未成功结案可以有收束剧情，不能伪装成成功完局发奖。
- 必须写：嫌疑人/解释集合、每条证据支持和排除什么、哪些是必要条件、缺证据时是否允许猜测提交、误判与超时的后续。
- 签收：客户端只交选择与动作身份；服务器根据原局已取得事实判定。换账号、换队、旧回执或未取得证据均不能借用。

## 7. 一套范本必须交付哪些内容

每套T01–T08至少交以下一套完整材料，作者和开发共用，不再分散成只有封面、站点列表和口头解释。

| 材料 | 最少内容 |
| --- | --- |
| 体验与故事 | 受众、玩家身份、事件起因、人物目的、转折、玩家行动造成的结果；章数由故事决定 |
| 逐场景正文 | 入场状态、实际台词/叙事、玩家目标、能看到的证据、实际操作、结果与下一步理由 |
| 判定与反馈 | 可接受答案/别名或选择范围、错误反馈、H1/H2/揭晓、无法继续时的路径；个人偏好不按对错处理 |
| 地点要求 | 证据/空间/事件/关系中的具体作用、必要特征、发布者填写值、照片、替代与失效处理 |
| 角色与材料 | 脚本角色、真实同行者、真人主持分别声明；物料精确到谁提供/摆放/复位/回收 |
| 配置清单 | 每个交互对应原能力key、个人模板ID、节点绑定、声明变量/物品、路由与后果；不用竞品字段冒充现有接口 |
| 媒体清单 | 自有/许可来源、署名要求、图片/音频/文字等价内容；写了规格不等于已经制作媒体 |
| 城市实例 | 至少两份独立绑定记录；未知坐标、现场事实、时间和步行距离保持待核验 |
| 版本与端 | 草稿、发布版本、支持端、必需能力、采用/运行隔离与迁移限制 |
| 验收 | 内容桌面审查、配置读回、运行判定、各端显示、冷玩家实走分别记录，不能合并成一个“完成” |

建议第一个范本先做三章：在家建立事件、现场完成关键调查、通过行动收束。后续需要更多事件时再加章，不为了贴竞品站点数而填充。

## 8. 11张施工卡：具体改哪里

这是11个交付包，包含内容、复用接线和有条件扩展，不是11套新增后台系统。本文编写期间不直接把新卡扩进正在开发的第2至8项代码。

### G01 题材、范本与小游戏入口分开

- 优先级：P0；负责人：产品/内容、作者端、后台。
- 改动：在现有模板发现/分类入口区分整套主题与单个小游戏；题材标签、玩法、城市、人数/时长与是否需要物料分开显示。
- 后端：先用现有分类、主题模板和个人模板/公共库对象，不为这9个题材新增业务引擎或一张万能模板表。
- 交付：8套范本的分类与说明；采用按钮调用对应原API，ID来源明确。
- 验收：选整套主题得到新主题草稿；选小游戏得到个人模板，能绑定节点；两种ID不能串用。

### G02 制作并绑定8套内容范本

- 优先级：P0先T01/T02/T03/T05，其他分批；负责人：内容策划与发布者。
- 改动：按第6、7节写正文、证据、反馈、提示、后果与城市绑定表，装配进已有主题/模板草稿。
- 后端：内容配置满足现有机制时不新增题材专属handler。现成可复用的内容也要走服务端采用，不从公开详情复制秘密字段。
- 交付：每套一份可审核的完整配置及媒体清单；第一套先绑定两城验证可复用性。
- 验收：第二位发布者无需原作者口头解释即可采用、补齐当地事实和独立发布；不能把写完本文算作8套剧本完成。

### G03 跨城绑定与发布问题定位

- 优先级：P0；负责人：现B2/B3，作者端/App负责人接界面。
- 复用：`TopicContentCopyServiceImpl`、原采用口、`TopicPublishCheckService`、原发布冻结链。
- 本轮关系：沿正在交付的地点合同、NEW_CITY重绑、编辑窗口、发布检查接入；不另建一套城市替换器。
- 发布者操作：选择目标城市，逐槽填实际节点/观察事实/答案/照片/开放条件，查看服务端缺口并定位原编辑字段。
- 验收：只换地名但保留旧城事实不能冒充已重绑；旧客户端正常采用兼容；新城未绑必需地点不能发布；普通公开响应不泄露作者备注。

### G04 已获线索、追踪目标与案件册接通

- 优先级：P0；负责人：内容、现运行时owner、各玩家端。
- 复用：原线索声明、任务结算、冻结来源和案件册/背包。怪谈目标清单是这些事实的内容视图。
- 改动：作者能够声明线索名称、来源节点和用途；玩家展示已取得/未取得，按需增加目标分组、关联关系、已读标记。
- 边界：已读是呈现状态，不等于取得；未取得的证据正文、他队私密线索、最终答案不能预下载进可见列表。
- 验收：取得后有来源与实际内容，恢复后仍在；仅刷新案件册不触发结算；另一个账号/队伍不能读；回看旧局取原发布内容。

### G05 图像选项与图片类交互补共享链

- 优先级：P1，亲子首版需要图片选项时升P0；负责人：原QA配置/冻结owner、编辑器、小程序与App。
- 确认缺口：现QA屏只支持题干图；选项配置/过桥/renderer没有完整图片链。图片排序是否同样缺链另核原sort。
- 最小改动：在原选项内容合同上补可选图片引用、替代文字与资源权限校验，贯通作者保存/读回、发布冻结、公开白名单投影、组件渲染。
- 判定：仍交原optionId/itemId，继续由原 `SUBMIT_QA` 或排序判定；不交客户端 `correct=true`，不新增图片选择专属判题器。
- 字段：新字段的命名由原配置owner确认并写进合同，本文不把示例图片字段当现成API。
- 验收：两张相似图可正确区分；改作者原图不改旧局；旧文字选项正常；图片缺失有等价文字；答案标志与秘密反馈不提前下发。

### G06 用图片单选/多选配置证据指认

- 优先级：方向已确认，按0.5做成品模板；负责人：内容、原QA/条件owner与各端。
- 具体玩法：点选嫌疑人头像，再单选或多选证物图片。作者配置正确选项、反馈和下一步；判定继续用原optionId与单/多选规则。
- 需要“先拿到证物才能指认”时，接原已获线索/物品条件。没有这个需求时不额外增加条件系统。
- 代码增量集中在G05的图片选项链和确实缺少的配置入口，不另立“指认引擎”或新增自由推理服务。
- 验收：文字/图片选项使用同一QA判定；可改题面、选项和反馈；若配了证物门槛则不能伪造取得；重复提交不重复产生后果。

### G07 可选挑战接原extraOnly规则

- 优先级：P1；负责人：原任务规则owner、作者端与玩家端。
- 复用字段：`gameplayRuntime.quests[].extraOnly/extraSlot`、`acts[].completionRule`；复用 `GameplayTaskEngine.isExtraTask/actComplete`。
- 改动：作者能明确“必做/选做”，玩家能辨认支线；核保存、冻结、可达性和完成列表均使用同一配置。
- 不直接增加竞品 `extraChallenge` 第二套协议。个人剧情分支、共享任务与其他旧路线模式不能仅凭字段同名互相套用。
- 验收：主线完成时未做支线不挡结束；支线完成不替代必做任务；互斥/额外槽不产生不可能完成的幕；重复完成不重发奖励。

### G08 到达叙事与“读数”

- 优先级：P1；负责人：内容、现到达/冻结owner、玩家端。
- 最小版本：作者使用现有到达后的叙事/结果反馈，解释为什么此时到这里、获得了什么信息。
- 条件扩展：若确需统一强度卡片和可回顾日志，在原冻结呈现中补一个只含公开叙事的可选结构；先定义实际消费者，再确定字段/API，不默认加表。
- 规则：读数明确为虚构剧情信息；不把GPS精度、传感器噪声说成“测到幽灵”。服务端合法到达后才解锁，原距离、精度和兜底围栏保持。
- 验收：未到达不解锁；重放显示同一条结果且不自动重复播放；到达失败不会收到成功叙事；私密线索和答案仍按原门槛读取。

### G09 复用现有计时配置

- 性质：已有能力的模板装配与回归，不立项新增计时系统。
- 作者在现有支持范围内配置时长和反馈，将计时用于相应挑战；规则和内容可在新草稿中修改，旧局继续用冻结配置。
- 核对原功能的开始、暂停/恢复、重进和超时语义，原支持什么就提供什么配置，不把界面秒数当新的权威时钟。
- 本审核稿不额外开发全案总时钟。以后确有这一独立需求时再核现有覆盖，另经用户审核。
- 验收：同一计时功能能供不同主题使用；修改设备时间或重进不绕过原截止；超时仍走原失败/继续规则，重复提交不重复结算。

### G10 逐字猜词、有限谜面变换和轻皮肤

- 优先级：P1；负责人：内容/设计与各端，必要时原QA owner。
- 文字问答仍复用原判题；预制图片只能作为内容过渡，不能拿它签收用户已确认的动态谜面配置。
- 有限谜面变换：镜像只作用谜面呈现；倒序先定义字/字母和标点处理；密码只提供明确、有限的作者可选规则及必要参数，不运行作者脚本。配置、资源、发布冻结和跨端效果一致，原答案判定不变；“看变换规则/恢复原文”是否算提示沿G12，不能直接把秘密原文提前发给玩家。
- 猜词验收：重复猜同字不重复扣机会，猜对揭示全部相同位置，重进保留已猜/剩余机会；中文按完整字符处理，整词别名不意外改变逐字揭示位置。
- Hangman已确认：先写逐字/整词、中文与Unicode、错误次数、重复猜测、提示/揭示和恢复规则；核现有文字答案路径后扩原组件，不把输入挑战改名便签收。
- 普通QA现有免费重试等约束不因竞品风格改变；收费揭示、道具消耗或次数惩罚另按已有授权规则。
- 皮肤：先做案卷、自然手册、年代通信等少量样式；不搬字体/品牌资源，不把美术换肤算新玩法，也不因皮肤改变输入和奖励逻辑。
- 验收：暗色/户外可读、文字替代、关闭动效/声音仍可操作；更换皮肤不重置局或发出第二次完成提交。

### G11 发布、复用与跨端验收

- 优先级：每套公开前P0；负责人：协调者、现发布/运行owner、内容和各端负责人。
- 用原发布检查定位到章节/节点/块/字段，缺失能力阻止不支持的内容发布或进入；作者批准的等价替代才可使用。
- 必须核六个环节：作者配置 → 保存读回 → 模板/地点绑定 → 发布冻结 → 玩家渲染提交 → 服务端判定/反馈/恢复。
- 签收两份不同城市/题目的配置实际调用同一生产机制；看见组件、目录或HTTP 200均不能替代行为证明。
- 运行证据独立记录小程序、iOS、共享/个人局与真实路线；不继承其他SHA、旧截图或夹具的绿色。

### G12 通用提示、机会、跳过与成绩规则

- 范围：0.4完整链及0.5凶手模板的消费者；优先复用原提示、积分流水、动作回执、揭示记录和冻结版本。不得新建平行帮助系统或靠客户端藏答案。
- 先核两条提示旧链的语义差异：逐级解锁记录会影响解谜分；积分unlock原实现可返回两条提示且幂等键为member+event+node。不能直接把它包装成“按局/按级收费”，否则跨局漏扣或重复扣。补新语义时旧链兼容，明确作用域。
- 配置分为内容、次数/开放条件、消耗、进度后果、成绩规则；值来自作者/平台获准范围。保存和发布需校验题型支持、余额种类、非负代价、跳过后续可达以及必要线索替代。
- 原普通QA要求免费重答；新增有限机会必须显式新版本/新规则，经支持矩阵、冻结、运行和旧局回归后开放，不静默改变所有旧题。
- 服务端只发获准提示片段；首字提示由冻结答案/作者覆写生成，不把完整答案交给客户端切字符串。重复字、空格、中文首字和英文首字母都有明确规则。
- 使用提示/作答/跳过时校验原玩家或队伍/节点/角色作用域；同动作仅落一次账、一次次数、一次进度。扣款失败不解锁，解锁失败不留扣款；已取得提示可重读。
- 揭晓与跳过保留不同事实；沿既有完成模式可表达时复用，不能表达才加最小状态。跳过不制造答对、真实到达、扫码或支付证明；队伍奖励和终局不重复。
- 排行榜只消费服务端已结算事实：原用时保留，罚时独立，得分/资格原因可解释；旧局使用旧版本规则，榜单同一比较组不混用不同口径。
- 后端交付：配置及版本合同、保存/发布校验、冻结及安全投影、提示/机会/跳过动作与回执、结算/榜单联动、负例测试。接口名和字段以现有实现核定后给各端，不在本稿伪造已存在API。
- UI交接：作者在原模板编辑加帮助规则；玩家关卡加提示层级、剩余机会、代价确认、跳过与回执恢复；完局/榜单显示辅助完成及成绩明细。仅文档交接，小程序/Vue/Swift由各端负责人做。
- 验收：并发双击/断网重试只消费一次；重登恢复正确；未解锁无答案；余额不足零副作用；猜错消耗一次而看档案不消耗；用完机会进入配置后续；跳过不发成功奖励；各端与榜单同源；旧题免费重答不变。

| 完局与榜单玩家 | 展示提示/跳过记录、本局分数/罚时或榜单资格原因 | G12；真实用时和排名罚时分开 |
| App负责人 | 核上述组件是否在正常入口、保存与回执合同是否一致 | 本文是新增内容交接，基础任务继续看[iOS交接](iOS优化交接.md) |

## 10. 执行顺序与交付边界

1. **底座收口：** 继续现有第2至8项后端实施和统一验证，本文不重复派发同一套跨城、发布、冻结、回执和交易改动。
2. **做第一套：** 用T01或T05制作三章范本，写齐正文与一个完整推理链，绑定第一个城市；以原QA/任务完成全链。
3. **证明可复用：** 第二位发布者绑定第二个城市，并核来源修改不改变已发布副本/旧局。
4. **做首批四套：** T01/T02/T03/T05共用上述底座，亲子需要图像选项时接G05；案件册与选做按现有能力补作者/玩家入口。
5. **做第二批：** T04/T06/T07主要增加档案、当地文化与原创素材，按实际需要补图片类呈现和轻皮肤。
6. **接调查与通用帮助：** 按0.5/G06制作凶手指认模板，按G10补三项已确认能力，按G12补提示/机会/跳过与成绩规则；不扩全案计时或自由推理。

本次是新增施工计划，未把它混入原24小时后端目标。新增内容工时须先用第一套完整范本和第二城绑定测量；剧本、素材、各端接线和实走时间不能用“复制模板几分钟”代替。完整排期在G02首套交付、G05/G10/G12完整链和各端责任确认后再锁定。

## 11. 必须跑的验收场景

| 编号 | 场景 | 正确结果 |
| --- | --- | --- |
| A01 | 两个不同主题使用同一种单选/多选 | 实际调用同一判定服务，题面/答案/进度互不串用 |
| A02 | 同一范本换城，只替换标题未重绑 | 新城必需地点/事实未满足，不能冒充发布就绪 |
| A03 | 取得来源模板后作者修改原稿 | 已发布副本与旧局继续读原冻结内容 |
| A04 | 作者重排章节、删改实时节点 | 新制旧局章节、文本和验证方式不漂移；新发布版本独立核验 |
| A05 | 只到达地点，尚未取得关键证据 | 不显示完整证据或直接放行有证据门槛的结案 |
| A06 | 单节点小游戏已完成，路线未完成 | 不记为整局正式完成、不发整局成功奖励 |
| A07 | 问答重复提交或响应丢失 | 原动作身份恢复，完成/道具/奖励只结算一次 |
| A08 | 回执PENDING或查询不到 | 保持待确认，不能伪装失败后自动新建动作重复执行 |
| A09 | 换队/退出后用旧链接、旧角色或旧回执 | 原权限与作用域拒绝跨队读写，不能借用他队证据 |
| A10 | 私有作者备注、角色线索、答案预下载 | 不随公开主题/资源投影提前泄露 |
| A11 | 主线完成，选做未做；或只做了选做 | 前者按规则可结束，后者不能替代必做任务 |
| A12 | 图片未加载、关闭声音或使用文字替代 | 仍能辨认操作；没有批准的等价替代时不能默认跳过必做题 |
| A13 | 闭园、标识更换、观察点被挡、GPS不准 | 使用发布者批准的替代/改期/继续路径，不编造现场答案 |
| A14 | 真实限时中修改设备时间、退出重进、截止点并发 | 服务端原截止不被重置，终态不重复，失败不冒充成功 |
| A15 | 选择一种关系/价值表达 | 有相应回应，不把个人偏好算客观答错 |
| A16 | 冷玩家仅凭正文、素材与正常UI游玩 | 能解释当前目标、可用证据和下一地点理由；记录真实卡点再修 |
| A17 | 未解锁提示/首字提示，抓取普通题面响应 | 不含完整答案、未解锁提示、correct或秘密原文；只发获准片段 |
| A18 | 双击提示、断网重发、两端同局并发，随后重登 | 按原动作回执仅计次/消费一次，恢复一致；余额不足不解锁也不推进 |
| A19 | 看嫌疑人档案、改选，再正式确认；错误后重试 | 浏览不耗机会；有效正式作答才计次，剩余次数由服务器返回 |
| A20 | 用完机会或跳过必要线索题 | 按配置继续/揭晓/失败；没有替代线索时不得卡死后续，也不得伪造答对或成功奖励 |
| A21 | 提示/跳过后完局，与未使用者比较成绩 | 分数、独立罚时、辅助标记及榜单资格按冻结规则一致；旧局口径不变 |
| A22 | 猜词重复字/中文/断线恢复，谜面镜像/倒序/密码跨端查看 | 重复猜不重复扣，正确揭示位置一致，原答案不泄露，三端使用同一冻结规则 |

后台构建/测试走批准的开发测试VPS或既有CI路径。新增文档和静态源码检查不算以上场景已通过；实地、真机、购买、授权和生产发布分别签收。
