# 三方协作协议

协议版本：`CY-COORD-20261015-v1`。这是三份最终提示词共同引用的规则。角色分工不变：Codex修现有bug/共用后端并协调，Claude做小程序UI/新功能及明确委派的专属后端，独立iOS agent做原生iOS。Flutter不做。本文不表示任何agent已启动、已领取文件或已建立自动同步。

## 一处控制文档 一个协调者

控制仓库：`liboyang42-cpu/hengyin`；控制分支：`codex/mini-bugs-backend-cloud-plan-20261015`；目录：`docs/plans/mini-codex-cloud-20261015/`。

Codex的C00/C99协调者是控制分支的唯一写入者，独占更新OWNERSHIP.md、BACKEND_CHANGES.md、tasks.json和统一提示词/范围文档。此角色由执行Codex提示词的agent承担；本次未核实各agent是否已启动，运行和领取状态由C00实际登记。

业务候选分支与其SHA写入OWNERSHIP.md，不能把控制文档分支当已集成业务候选。协调者用独立checkout处理控制文档；不要在其他worker运行时切换共享工作区分支。Claude和iOS在自己的任务分支/仓库接续工作，不被要求一起切文档分支。

## 防止重复开发

1. C00先核当前master、PR11父链、PR12–15及三方正在做的任务，已有实现/旧组件先复用。
2. 同一业务能力使用原任务/BK编号。已修、误报、裁决不做与未纳入项分别记录，不为凑数造代码改动。
3. 新功能专属后端可以由Claude实现，但须先登记文件与合同；共用核心、已锁文件仍由原所有者处理。iOS不另建业务后端。
4. 不按小程序/iOS各复制一套同义接口、回执、会话、账本或运行时。也不把“后端有Controller”当可直接接通。

## 文件所有权

- 所有权覆盖源码、测试、fixture和配置文件；以仓库＋精确路径/有边界的新增目录登记。不得笼统认领全部utils、全部Controller或整个后端。
- TASKS.md/tasks.json中的owned_files是Codex任务的初始预留，C00需核当前工作后发布实际ASSIGNED清单；OWNERSHIP.md最初的PENDING不是实际派工。
- 每个文件同一时刻只有一个写入者；不同checkout也不能消除同文件冲突。WXML/JS分属两人时先冻结事件名、参数、状态与返回合同，再分别编辑。
- shared DTO/请求封装/app.json/动作路由清单/门禁基线/workflow/pom/迁移索引默认由协调者统筹；worker给最小补丁，协调者串行整合。新增页面不授权直接抢写全局路由清单。
- 文件转交必须有原所有者停止编辑、提交或补丁交付、协调者确认新基线/新所有者的记录。沉默、超时、PR关闭或会话暂时空闲均不自动释放。
- 独立checkout可按各自明确路径提交；共享工作区worker不并发切分支/暂存/提交，由协调者串行收口。禁止git add全部路径、reset/checkout覆盖其他任务，或替别人重写历史。

## 三方如何提交请求和交付

每方维护自己的草稿PR正文，或自己分支上一份专属交付文档。固定标记：`CY-HANDOFF: CODEX`、`CY-HANDOFF: CLAUDE`、`CY-HANDOFF: IOS`。共享记录由协调者汇总，不由三方同时编辑。

请求/交付至少包含：

- 控制分支与协议版本；任务/I/BK编号；实际仓库、分支、基线SHA和当前提交。
- 已有实现/反证；拟改/已改的精确文件、专属测试；申请的新文件或需转交的文件。
- API/DTO/事件签名差异、两端影响、兼容fixture；无协议变化写NO_API_CHANGE。
- 当前状态、实际测试输出与未跑项；依赖的合同版本、候选及测试部署；具体阻塞/待决策。

没有PR可先在自己分支提交一份只属于自己的请求/交付文档，再开草稿PR，不改业务代码来制造PR。协调者在分派、集成、接口变化及本轮收尾前主动读取两个公共仓库内带这些标记的交付记录，登记请求的处置；该记录不构成任意向其他会话/邮件/聊天发消息的授权。

没有自动推送或后台监控。各方在开始依赖工作、接口接线、更新基线或联调前重新读取控制分支；协调者离线时可继续已独占且独立的工作，其余报告等待，不猜批准、不无限占用运行等待。用户不必手工转抄所有接口变化，但需要先启动协调者。

## 后端变化发布顺序

DRAFT → CONTRACT_FROZEN → SOURCE_READY → TEST_DEPLOYED。合并状态另列；两端适配/验收各自另列。这些状态由证据驱动，不自动逐级升级：

| 状态 | 必须具备 | 客户端可以做什么 |
|---|---|---|
| DRAFT | 问题/方案/待定字段和责任人 | 研究、设计、复现；不能猜协议或声称可用 |
| CONTRACT_FROZEN | 方法/路径/DTO/单位/错误/权限/分页/requestId/version、两端兼容与fixture已审阅固定 | 源码及明确标注的fixture适配，当前OFF的写能力保持OFF |
| SOURCE_READY | 对应候选SHA、相关真实测试结果与已知限制 | 检验该候选；不推导目标服务器已部署 |
| TEST_DEPLOYED | 授权测试目标、运行包/源码版本对应、数据库目标和必要准入已核 | 在相应授权身份下做真实VPS联调；仍不等于原生/微信真机或生产发布通过 |

协调者在BACKEND_CHANGES.md每条记录同时写实现/PR/合并/部署状态、iOS与小程序各自影响和验收。旧客户端、旧局、旧订单兼容要明确；不可兼容或资金/权限/产品政策变化先提供具体方案并停止该行为变更，其他独立任务继续。没有协议变化也登记，避免前端猜测。

同一合同两端使用同一组正常/失败/未知/冲突/越权fixture，但不共享同一可写测试数据或构建目录。共享fixture由协调者拥有，worker可用各自专属副本验证后提交差异，不能并发覆盖基准。

## 环境与签收

Cloud编辑/轻量Node检查；Java开发/集成测试、MySQL/Redis与测试服务在专用VPS，额外CI用GitHub托管runner。iOS的Swift/Xcode测试按其既有获准环境。Cloud localhost不是Mac隧道；不可达就如实记未验证，不回落生产或另建替代后端。

本批不新增DDL/依赖，不修改生产配置/开关，不部署/上传。鉴权/RBAC、资金、支付、留存与产品政策按原批准边界；先完成复现、最小方案、影响及回退准备再提决策。小程序会费/群聊/投票不恢复；不把它自动套成删除iOS已有模块或批准原生收费。

签收分别记录源码/相关测试、PR/CI、合并、迁移、测试部署、客户端适配、设备/真实业务及生产发布。fixture、返回200、SDK成功、检查项跳过、PR标题和文档状态都不能替代后一层证据。
