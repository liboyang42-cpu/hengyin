# GitHub 地图设计与城瘾实体分层研究（2026-08-25）

## 结论

城瘾不需要寻找一个“现成游戏地图仓库”整体搬入。更可靠的组合是：

- **MapLibre GL JS** 负责可交互矢量地图、缩放层级、3D 倾斜和自定义图层。
- **Protomaps Basemaps** 提供可完全换肤、许可友好的轻量底图设计。
- **deck.gl + H3** 负责迷雾、街区探索度、热区、路线轨迹和大量动态对象。
- **Maputnik** 让设计人员可视化调整底图颜色、道路、建筑、水域和标签层级。
- **StreetComplete / MapComplete / FacilMap** 只作为任务点、主题图层和协作地图的产品参考，不建议直接作为城瘾运行时依赖。

地图是否清楚，关键不在于“商家、玩家、景点、节点分别使用不同颜色”，而在于：**不同实体使用不同轮廓和空间层级，颜色只表达状态；不同缩放级别与玩法状态只显示当前需要的对象。**

## 已查看的地图设计

### Pokemon GO

- 玩家是屏幕中心唯一的人形角色，不与 POI 共用 pin。
- 白色/粉色交互半径把“看得见”和“点得到”分开。
- Gym、PokéStop、Power Spot 被做成有高度的空间装置，远处仍可辨认。
- 道路与建筑被压低对比度，地图首先是一张游戏场景，其次才是导航图。

适合城瘾：玩家中心、交互半径、重要景点的高度差。风险是常驻入口和事件过多会侵占地图边缘。

官方证据：[Pokemon GO Map View](https://niantic.helpshift.com/hc/en/6-pokemon-go/faq/84-what-is-the-map-view/)

### Pikmin Bloom

- 真实道路只是淡色骨架，玩家走出的花路成为地图主视觉。
- 大花是地标，小花是玩家行为留下的连续痕迹，两者尺寸完全不同。
- 设计重点不是“附近有什么”，而是“我走过以后这里发生了什么”。

适合城瘾：个人迷雾、足迹、探索记忆和低压力氛围。风险是花路过密后会盖住道路。

官方证据：[Pikmin Bloom App Store](https://apps.apple.com/us/app/pikmin-bloom-walking-game/id1556357398)

### Ingress

- 深色底图几乎退到背景，Portal、连线、控制区成为唯一主角。
- 点、线、面构成同一套空间规则，不是彼此独立的装饰。
- 阵营颜色表达归属状态，而 Portal 轮廓保持一致。

适合城瘾：街区探索度、主题路线连线、区域完成反馈。风险是高对比霓虹和军事 HUD 不适合城瘾日常漫游。

官方证据：[Ingress](https://ingress.com/en)

### Monster Hunter Now

- 森林、沙漠、沼泽以大面积色块覆盖真实路网，先告诉玩家“这里是什么区域”。
- 怪物 pin 体积大、带星级；脚印直接表达追踪路径；资源点则更小。
- 区域、目标、路线三层同时存在，但密集活动时地图会明显拥挤。

适合城瘾：主题街区皮肤、大型限时目标、目标追踪。风险是不能把每个商家都做成同等大小的怪物 pin。

官方证据：[Monster Hunter Now App Store](https://apps.apple.com/us/app/monster-hunter-now/id6445906110)

### Orna

- OpenStreetMap 上直接放置像素人物、怪物、建筑和地牢，不再套通用地图 pin。
- 实体靠剪影区分：城堡就是城堡，宝箱就是宝箱，NPC 就是人物。
- 真实路网和幻想世界并置，成本比完整 3D 游戏地图低。

适合城瘾：NPC、景点、商家可以拥有不同空间形态。风险是高密度精灵会遮挡道路并产生点击冲突。

官方证据：[Orna GitHub/App Store 来源说明](https://apps.apple.com/us/app/orna-fantasy-rpg-adventure/id1451775309)

### Adventure Lab

- 默认是标准真实地图，绿色 pin 表示可发现的 Adventure。
- 地图主要负责“发现入口”，选中后由底部卡片说明距离、时长、评分和主题。
- 任务内部再逐步显示节点，避免总览地图暴露全部剧情点。

适合城瘾：商家/主题发现层与路线任务层分离。风险是同色同形 pin 太多时缺乏内容差异。

官方证据：[Adventure Lab App Store](https://apps.apple.com/us/app/adventure-lab/id1412140803)

### StreetComplete

- 附近待处理问题全部显示为带图形的任务 pin，图标语义非常明确。
- 玩家位置只是蓝点，任务按类型使用不同图形和色环。
- 实际截图也暴露了反例：高密度区域的 pin 会覆盖道路、建筑和彼此。

适合城瘾：任务图标语义和“到现场回答一个问题”的闭环。只建议参考设计，不直接复制代码；仓库为 GPL-3.0。

GitHub：[streetcomplete/StreetComplete](https://github.com/streetcomplete/StreetComplete)

## 城瘾实体视觉语法

### 1. 玩家 Player

- 使用人形头像或带朝向的角色，不使用通用 pin。
- 永远位于最高交互层，并配一个半透明可交互半径。
- 移动时才有轻微方向动画；静止时不持续跳动。
- 其他在线玩家缩小为圆形头像，只在组队或附近社交模式显示。

### 2. 商家 Merchant

- 使用低高度“店招牌”或圆角方牌，内部放品类图形。
- 名称、营业状态、权益只在街道级缩放显示。
- 低缩放级别聚合为商圈，不显示每家店。
- 合作/任务商家增加外环或小角标，不更换整个图标颜色。

### 3. 景点 Attraction

- 使用高于商家的“城市图腾”轮廓，例如塔、门、碑、建筑剪影。
- 比商家更早出现，允许从街区级缩放看到。
- 已到访增加个人印记；未到访保持清晰轮廓，不用灰掉造成“不可点击”误解。
- 重点景点可在倾斜地图中使用轻量 2.5D 高度。

### 4. 任务节点 Quest Node

- 只在玩家选择某条主题路线后显示。
- 使用编号圆片或菱形，不使用地点 pin；通过 `锁定 → 可进行 → 当前 → 完成` 四态表达进度。
- 当前节点允许轻微呼吸动画，其余节点静止。
- 节点之间由方向明确的路线连接，未解锁的后续路线可淡化或隐藏。

### 5. NPC

- 使用人物半身像或站立剪影，仅在街道级或进入任务后出现。
- NPC 必须依附景点或任务节点，不能作为孤立的永久 POI。
- 同一位置多个 NPC 合并为“人物组”入口。

### 6. 活动与临时事件

- 使用光柱、倒计时环或顶部小旗，靠短期动态而不是新的一套永久 pin 区分。
- 活动结束后完全移除，避免地图留下失效入口。

## 显示层级

| 地图状态 | 默认显示 | 隐藏/聚合 |
|---|---|---|
| 城市总览 | 已探索区域、主题街区、少量核心景点 | 商家聚合为商圈；隐藏 NPC 和任务节点 |
| 街区浏览 | 景点、商圈、精选商家、可选主题入口 | 普通商家按筛选显示；隐藏未选择路线节点 |
| 街道探索 | 玩家、附近景点、商家、交互半径 | 远处对象淡出；密集商家聚合 |
| 主题路线进行中 | 玩家、路线、当前/后续节点、相关 NPC、必要商家 | 隐藏无关商家、其他主题和普通 POI |
| 历史回看 | 个人足迹、迷雾消散、照片和已完成节点 | 隐藏实时玩家与临时事件 |

## 编码规则

- **形状表达类型**：玩家、商家、景点、节点、NPC 的轮廓必须不同。
- **颜色表达状态**：可进行、进行中、完成、暂停、限时，而不是单靠颜色表达实体类型。
- **尺寸/高度表达重要性**：景点高于商家，当前任务高于普通节点。
- **动效表达实时性**：只给当前目标、移动玩家和临时事件使用动效。
- **光环表达距离/可交互性**：进入范围后显示，而不是把图标整体变色。
- **文字只在需要时出现**：总览显示区域名，街区显示景点名，街道级才显示商家名。
- **不能只依赖颜色**：图形、文字和状态环必须共同工作，兼顾色弱与户外强光。

## 推荐实施顺序

1. 先定义上述六类实体的视觉语法和缩放显示表。
2. 以当前城瘾地图做一个静态图层原型，只放玩家、1 个景点、3 个商家、1 条路线和 4 个节点。
3. 再加入个人迷雾/H3 探索区，验证是否仍能看清道路和当前任务。
4. 最后才增加在线玩家、动态活动和 NPC，逐层做密度上限。
