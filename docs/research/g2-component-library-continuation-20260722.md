# G2 组件库续建判定（2026-07-22）

## 本轮可落地的重复模式

后台业务页中仍有 7 个真实详情页各自手写 `el-descriptions`：活动、会员模板、会员提现、官方活动、订单、模板库和主题。它们共同需要的是“页面已经格式化好的只读字段”的稳定信息层，而不是共享 API、字典或写操作。

本轮新增 `CyDetailGrid`，并在两个不同约束的真实消费者验证：

- `business/order/detail.vue`：订单、收货、备注和物流的三列/单列详情；支付方式和订单状态继续由页面自己的 `dict-tag` 插槽提供。
- `business/memberwithdrawal/index.vue`：收款资料的单列详情；`business:memberwithdrawal:viewpii`、按需读取和审计接口仍完全留在页面。

组件只接收 `{ key, label, value, span, hidden }`，允许页面按 `key` 提供富文本插槽；不请求详情、不判断权限、不解释领域字段。

## 仍不应伪实现的项目

| 能力 | 当前证据 | 结论 |
| --- | --- | --- |
| `CySavedView` | 只有 URL 查询条件；没有保存视图表、个人/系统视图接口、权限或默认视图语义。 | 先定义并实现后端持久化模型，再做前端组件。 |
| 视频预览 | 后台 Vue 页面没有实际的 `<video>` 或统一视频 URL 字段消费者。 | 等至少两个真实页面形成相同视频协议后再抽象。 |
| 订单/合作/核销证据面板 | 订单详情是商品/物流事实；合作与核销目前是各自字段和台账表，并未输出同构的图片/文本/编号证据项。 | 不把不同领域字段猜成统一“证据”协议。 |
| 骨架/局部加载新组件 | 已有 `CyEmptyState`、`CyResourceState` 和 `CyDataTable`；其余加载点是各自页面的 `v-loading` 覆盖层，尚无可复用的相同骨架结构。 | 先在至少两个页面形成同一加载布局，再抽象，避免包装 Element UI。 |
| 全局业务搜索 | `HeaderSearch` 只在 `defaultRoutes` 中检索菜单；#170 的搜索改动仅在小程序，后台没有跨用户、商家、主题/活动、俱乐部、合作单、订单、投诉的权限聚合接口。 | 先定义后端聚合、结果脱敏/权限过滤和跳转语义。 |
| 业务面包屑 | 现有 `Breadcrumb` 只能从静态路由 `meta.title` 推导；订单、主题等详情路由没有对象名称/ID 的统一语义。 | 先冻结“一级域 / 列表 / 对象详情”的路由元数据契约。 |
| 统一错误页 | 当前只有独立的 401/404 页面；网络中断、全局异常、维护和局部失败没有统一的鉴权/失败边界。 | 先确定全局错误处理与重试责任，不能用一个展示组件伪装成完整故障体系。 |

## 后续准入规则

新增 G2 组件前必须同时满足：至少两个真实页面存在同一交互或信息结构；页面可以提供已格式化展示数据；组件不需要猜领域字段、请求、权限或状态机。每个组件至少接入一个真实页面并有对应 contract 测试。
