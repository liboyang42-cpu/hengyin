## 1. 总结论

这份 Figma 不是一组可以整包照搬的品牌皮肤，而是一套“交互机制参考库”。Figma 自己在 `220:643` 已给出采用边界：

- A：Roadmap、Shared Element、Draw Path、Reveal 等机制可以直接采用，只替换城瘾业务内容。
- B：Coin、Infinity Scroll、Flashlight、Reaction 等可以保留结构，但品牌资产和核心物件必须换成城瘾自己的资产。
- C：二维码本体不能做 Reveal 动画；必须先生成、校验并保持静态可扫，动画只能放外围。

因此施工统一执行以下规则：

1. 保留 Figma 的信息顺序、空间关系、转场节奏和唯一主动作。
2. 文案、状态和可点击能力只能来自现有接口或现有 handler。
3. 版式色彩尽可能按具体 Figma Frame 还原，但统一沉淀为 `--cy-*` token；Roadmap 保留源稿白底与紫色路径，Atlys 商标、护照、签证等专有资产仍不得复制。
4. 新增偏好约束：玩法参考尽可能不用纯黑大底；黑色源稿优先保留结构与节奏，并转换为城瘾浅色舞台，不自行扩写黑金视觉。
5. 原稿没有的按钮不新增；原稿看似可点但城瘾没有下一步合同的元素保持信息态。
6. 每个参考节点开工前单独读取 `get_design_context`，不能只凭参考标题施工。

## 3. 首批施工：Roadmap `220:761`

### 3.1 原样保留

- 标题先出现。
- 标题左侧路径向下绘制。
- 节点按顺序进入。
- 全屏只允许一个当前/下一站高亮。
- 底部保留一个固定“继续”主动作。
- 节点是进度信息，不扩展为一组新按钮。
- 白底、`#4B46F5` 路径/CTA、深色标题与灰色正文按 `220:761` 固定组件 token 还原，不继承玩法页黑底。

### 3.2 城瘾业务映射

| Roadmap 展示 | 城瘾真源 | 说明 |
|---|---|---|
| 章节眉题 | `chapter.idxLabel` | 现有章节数据 |
| 标题 | `chapter.name` | 现有章节名 |
| 节点序号 | `node.num / sortId` | 现有节点排序 |
| 节点标题 | `node.name` | 现有地点名 |
| 节点正文 | `gameTitle / description / address` | 按已有字段优先级降级 |
| 已完成 | `node.done` | `/api/play/nodes` 返回 |
| 前路未知 | `node.locked` | 服务端按 `unlockAfterNodeId` 和完成集合计算 |
| 下一站 | `nextNode.nodeId` | 现有 `computeNext` 推荐结果，不冒充“你在这里” |
| 继续 | `closeIntro` | 进入原有地图/玩法流程 |

状态规则：

```text
done=true                       -> done
done=false && locked=true       -> locked
nodeId == nextNode.nodeId       -> active（文案“下一站”）
其它                            -> future
nextNode 缺失或 ID 不存在       -> 不高亮任何节点
```

加载失败、登录过期、未报名、未购票、节点未配置、数据异常继续由 `pages/play` 现有 `emptyTip / emptyKind` 分支承接，不塞进 Roadmap 内部。

## 7. 动效施工约束

Roadmap 动效顺序固定为：

1. 标题进入。
2. 路径绘制。
3. 节点依次出现。
4. 当前/下一站脉冲一次或低频呼吸。
5. CTA 出现并保持稳定。

必须支持 `reducedMotion`：关闭位移、路径绘制和循环脉冲，信息与按钮仍完整可用。不得为了还原动效引入新依赖或 Canvas；首批只使用原生 WXML/WXSS。

## 8. 验收门禁

每一批都必须同时满足：

1. Figma：记录具体 node ID，保存参考截图，不按记忆还原。
2. 数据：列出每个可见字段和状态真源；未知值 fail-closed。
3. 行为：每个可点击控件能进入既有下一步；参考稿无交互的元素不得私自变按钮。
4. 测试：先做能判红的状态/结构负控，再恢复为绿。
5. DevTools：真实编译、目标路由、组件/页面数据读回、0 console error。
6. 像素：截图必须人工打开，对照层级、间距、折线、节点位置、CTA 安全区；截图桥失败时不得宣称视觉通过。
7. 全仓：`npm run --silent test:unit` 与 `bash ci/xcx-check.sh` 通过，action ledger 无漂移。
8. 发布：本地绿不等于微信上传或真机通过；上传必须另行授权。

## 9. 明确不施工的内容

- Atlys 品牌、签证文案、护照、原 Coin、其它产品 logo 与专有资产。
- 没有后端字段支撑的“你在这里”、排名、奖励金额、连续天数、在线成员和预计到达。
- 二维码本体动画。
- 未做拒权/取消/恢复合同的相机、定位、传感器玩法。
- 仅因 Figma 看起来可点而新增的入口。
- 为了统一视觉而重做 `mode==2` 自由探索、地图、核销或票务业务。
- 没有服务端真源的卡住次数、离线变化、追回票据、永久访问承诺和历史赛季进度。
- 用连续签到、倒计时、过期灰态或“想你了”制造复玩压力。
