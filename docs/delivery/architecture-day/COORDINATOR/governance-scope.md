## 3 质量属性与终点验收

以下均为目标门槛，不是已经测得的结果。容量和延迟目标先在批准资源内测基线，不以虚构 RPS 或“新增一次 SQL 仅 2ms”排期。

| 编号 | 质量属性 | 场景与可验证门槛 | 必须保留的证据 |
|---|---|---|---|
| Q1 | 业务正确性 | 同一资金/奖励/库存意图在重复、并发、重启后经济效果至多一次；合法首次效果确实发生；余额/明细/订单/回执守恒 | 真实 MySQL 前后读回、唯一身份、故障点、断言 |
| Q2 | 状态可靠性 | 非法迁移、跨人/跨商家/跨活动写入均拒绝且零副作用；UNKNOWN 不伪装成失败或成功 | 状态矩阵、权限负例、持久状态与回执 |
| Q3 | 可恢复性 | 对每个已接受命令都能定位终态或明确待恢复状态；崩溃后无需创建新业务身份才能继续 | 重启前后原 ID、租约栅栏、恢复时间、人工处置记录 |
| Q4 | 故障隔离 | AI/地图/单通知通道持续失败时，支付回调、状态读回和其他玩法仍在预算内；积压有界 | 混合负载、池/队列/连接指标、失败注入 |
| Q5 | 变更成本 | 选三项常规变更做演练：一种玩法规则、一种通知通道、一个统计查询；只改所属模块及声明的公开合同/适配，其他域内部写侧零修改 | 变更影响清单、依赖图差分、回归结果、评审解释 |
| Q6 | 可测试性 | 每条启用的核心写链有正常、拒绝、重复、并发、响应丢失和重启用例；测试报告无必需用例缺失或跳过 | 用例 ID 与业务合同映射、CI 测试计数和结果 |
| Q7 | 可观测性 | 任取一个失败业务 ID，可从入口追到意图、数据库事实、回调、任务和恢复；不依赖某个进程内存或原执行者 | 脱敏日志/指标/账本的相关性证据 |
| Q8 | 可扩展性 | 在固定资源、明确数据规模和并发下给出容量曲线；新增实例前证明调度接管和业务幂等；缓存/队列/连接有界 | 环境清单、资源限制、压力与故障测试、容量上限 |
| Q9 | 并行开发安全 | 两个独立模块工单并行完成，共享合同由集成人合并；最终同一候选全量门禁通过，无他人改动被覆盖 | owner 记录、分支/补丁、冲突裁决、候选 SHA |
| Q10 | 可回退与持续演进 | 停止新写后仍能读回、对账、处理原意图；回退不删除账本，不重发未知付款，不跨 runtime 解释会话 | 扩展/切换/回退演练，原数据校验和与业务读回 |

最终验收必须同时满足 Q1–Q10。类变短、枚举变多、测试文件数量增加、HTTP 200、单次截图和构建成功均不能替代这些门槛。

### 5.1 模块职责和写权

| 边界 | 唯一负责的事实 | 对外允许的合同 | 禁止承担 |
|---|---|---|---|
| identity/access | 身份、权限、授权范围 | 鉴权和 scope 校验结果 | 替业务推断资源所有者 |
| catalog | 草稿、发布审批、不可变配置/路线版本 | 获取冻结版本、内容查询 | 修改支付/结算终态 |
| play | 会话、任务、验证、到达/完成事实 | 用例命令、CompletionQuery、源事件 | 直接修改资金/核销账本 |
| registration/fulfillment | 报名、票据、履约、权益核销 | 订单归属与履约事实、明确命令 | 推断微信渠道已支付 |
| funds | 支付意图、退款/提现、会计明细与结算资格 | 受控资金命令、不可变结果、对账查询 | 读取客户端金额作为付款真源 |
| rewards | 积分/券/奖励资格及唯一发放事实 | 基于源事实的发放与冲销 | 把统计回填当作新奖励事件 |
| club / community / merchant / roam | 各自成员关系、内容、商户经营、漫游状态 | 领域公开 API 与查询投影 | 跨域 Mapper 直接写入 |
| notify/media/AI integrations | 投递/审核/生成意图和渠道结果 | typed result、持久任务、恢复状态 | 决定退款资格、吞掉未知计费结果 |
| operations | 调度、迁移证据、发布清单、告警 | 触发已授权领域命令 | 绕过应用用例直接批量改业务终态 |

第一阶段实行“**一个事实一个写入所有者**”，现有混合表按字段组登记暂时所有者和唯一受控变更入口。不能先宣布一张混合表只属于一个域，再让其他合法写路径悄悄绕行。后续确有收益时按 expand-contract 分表。

跨域只读 SQL 暂不全禁。先给每个消费者登记业务口径、查询预算与 owner，迁移高耦合读者到批量查询服务或领域发布的投影。不能把一个 JOIN 换成 N 次 API/方法调用，制造新的 N+1。

### 5.2 依赖方向和事务边界

入口适配器负责协议、身份提取和输入校验；应用用例负责授权范围、业务编排与短事务；领域策略负责状态规则；Mapper/供应商适配器负责持久化或 I/O。规则可保持在现有 POJO 和 service 中，不引入通用领域框架。

跨域资金流程由明确的应用协调者调用双方公开命令，在同数据库允许的事务中完成需要原子的效果。将通知改成异步不能顺带改变“积分/券何时可见”的产品语义。事务自调用、传播级别、重试层级和行锁顺序在迁移前后必须一致并有测试。

模块不能依赖另一个模块的内部 Mapper/entity；公共 DTO 不直接复用可写数据库实体。编排协调者放在上层，而不是让两个域互相调用再用 `@Lazy` 隐藏循环。是否需要接口由实际替换点/依赖反转决定，不为每个类自动生成接口。

## 6 不可放宽的实现合同

### 6.1 命令和幂等

危险写命令显式包含 `commandId`、actor/scope、目标业务 ID、必要的 `expectedVersion/expectedChapterId` 及语义输入。actor 来自可信身份，不能采用客户端自报。所有重复处理先校验当前身份、原归属和允许读取范围。

- `commandId` 在一次用户意图产生时创建，跨超时、刷新、进程重启保持不变；确认结束后新意图才能新建 ID。随机 UUID 可以生成新意图，禁止在每次网络重试或服务端缺省路径重新生成。
- 相同身份和语义指纹重放既有业务结果；同键不同语义返回稳定冲突码。旧版本/旧 epoch 的迟到响应不得覆盖新会话 UI 或状态。
- 原意图的目标、输入和前置版本不可变；同 key 不得偷偷改 expectedVersion。先校验身份和回执读取权限，再识别合法已执行回放，不能因实体后来版本变化拒绝读取原回执。确认未执行的版本冲突终结该意图，刷新后由用户确认创建新意图；执行结果未知时只能按原键原参数查回。
- 客户端 pending 意图按登录主体、会话/实例、动作 ID 分区。退出或切换账户后暂停原主体的发送，不能换成新账号 token 自动提交；重新登录原账号才按授权查回。仅保存恢复需要的最少数据，敏感请求正文不跨账号暴露。
- 本地事务命令：资格校验、业务效果、唯一业务记录、回执终态在同一事务提交。可独立短事务预领回执，但必须有明确 lease/fence 恢复，业务终态不得在提交后另写。
- 外部调用：先提交原始意图和确定渠道号，事务外 I/O，再依据回调或同号查询完成本地事务。超时进入 UNKNOWN；UNKNOWN 不等于 NOT_FOUND。
- 不保证外部网络 exactly-once。保证本地经济效果唯一，并使用供应商幂等、同号查单或人工核验处理外部未知结果。
- 响应正文和 PII 可按批准策略清理；资金/权益的不可重放身份、渠道编号、业务唯一性和归档 tombstone 不套统一 7 天 TTL。

优先复用 `game_command_receipt`、个人路线动作、支付 inbox 与既有账本。每个命令只选一个权威业务回执，禁止全局 HTTP 拦截器再包一个互相不一致的状态机。[Stripe 的幂等文档](https://docs.stripe.com/api/idempotent_requests)可参考同键回放和参数一致性；不能照抄它的缓存保留期作为本系统资金唯一性的保留期。

### 6.2 提现与支付事实

提现回补至少需要：原提现身份及金额一致、成功扣款有可持久读回证据、未发生既有回补；并满足以下之一：已经证明从未提交/确定未受理，或已受理后渠道明确最终失败/撤销且无成功事实。未提交证据必须绑定原意图，并证明没有其他执行者仍可能派发。两人复核是权限控制，不能代替资金事实；不能为了安全把有确定未提交证据的合法回补永久挂起。

渠道结果按“已证明未提交/确定未受理、已受理后最终失败、未知、成功”分类。`ServiceException`、HTTP 非2xx 或一次 NOT_FOUND 都不足以证明未受理。当前转账适配器的统一失败分类需修复 [E19]；SYSTEM_ERROR、5xx 或无法证明未受理时保留原号进入 UNKNOWN，按渠道要求查证。微信官方要求 SYSTEM_ERROR 沿用原批次号和原参数，并提示受理后立即查单可能暂查不到：[商家转账开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012065168)。查询间隔、可见性窗口和允许的同号恢复必须按实际接入产品配置，不能盲重发。

历史 status 3/4 且证据不足的记录进入只读调查，不自动退款；保留 CW/CD、原金额、原用户和渠道结果。修复代码不得把未知记录改为成功或失败以便通过门禁。

支付统一入口先验签解析，再验证订单预期渠道绑定、appid、mchid、币种、金额、交易号与订单号。四个业务域仍保留自身归属、状态 CAS 和业务唯一性。appid 应来自这张订单创建时的渠道上下文，不能接受“配置里任意一个 appid”。

回调 ACK 只在明确可接受的持久终态或已持久受理并有可靠处理合同后发送；拒绝必须可定位。回调乱序、成功后迟到失败、退款早于本地支付确认都必须按证据状态机处理，不由路由器猜测。

### 6.3 玩法事实和完成查询

至少区分 `ARRIVAL`、`TASK_VERIFIED`、`NODE_COMPLETED`、`THEME_COMPLETED/ENDED`、`ENTITLEMENT_REDEEMED`、奖励资格与已发放奖励。探店日“答完游戏”与“权益核销”不能合成一个布尔字段。

权威事实关联 actor/个人或团队 owner、activity、session/playInstance、冻结配置版本、node/quest/attempt、正常或兜底来源、发生时间、源回执和奖励资格。已有 `play_instance_id` 不重复造列；新投影是否加表/列由实际口径差距决定。

`CompletionQuery` 统一查询语义，runtime 保留各自控制状态。先影子计算和集合对账，再切换消费者；禁止将所有 runtime 直接写成同一条 `player_node_progress.status=1`。历史统计回填不发券、不发奖、不触发付款。

章节推进必须同时有原意图、期望章和合法目标章。CAS 验证当前队长/权限及期望状态；同意图已到目标返回已执行，过期期望返回当前事实与冲突，不自动刷新后再次推进。

### 6.4 可靠投递与恢复

采用现有 MySQL 和 Quartz。统一的是以下合同和验收工具，而不是强制一张 outbox 表：

1. 业务事实与必须送达的意图在同一事务写入；afterCommit 只能作为低延迟唤醒，持久扫描恢复不依赖它。
2. 短事务按索引领取到期记录，提交 owner、fence、lease；网络调用在事务外。结束写回必须同时匹配身份、owner/fence、有效状态；旧执行者不得覆盖新结果。
3. 事件和通道投递分开记账，唯一性至少覆盖事件、目标、通道；fanout 部分成功只恢复未成功的通道。
4. 明确区分 READY、PROCESSING、DELIVERED、RETRYABLE_FAILURE、UNKNOWN、MANUAL_REQUIRED 等语义，并映射既有存储，不要求强制采用这些字符串。
5. 仅在领域证明可重试时退避重试；超过预算保留死信与原身份。微信授权已可能消耗、AI 已可能计费、渠道付款未知时先查证，禁止统一重投。
6. 心跳和 lease 仅证明执行者状态，不能证明外部副作用未发生。崩溃后按业务事实恢复，不能直接把全部 CLAIMED 设回 READY。
7. 重试有次数/时长/并发预算、带抖动退避、按通道隔离；队列索引及历史归档需真实数据规模 EXPLAIN 和负载验证。

`SKIP LOCKED` 可以用于队列竞争领取；它返回跳过已锁记录的视图，不能用于金额守恒或完整集合审计。[MySQL 官方说明](https://dev.mysql.com/doc/refman/8.0/en/innodb-locking-reads.html)明确区分了这两类用途。固定 LIMIT 200 或拆 ready 表并不能自动证明扫描成本恒定。

### 6.5 显式状态与失败结果

保持现有数据库编码，通过带编码的领域枚举/常量和明确 guard 描述允许迁移；只在实际写入口逐步收拢，不全仓替换数字或新增一套可动态修改的状态机配置表。

CAS 更新零行分为：相同意图已完成、版本冲突、目标不存在、无权限、非法状态、数据库故障。不能一律当成功，也不能一律告警。

在现有返回包装内确定稳定 `errorCode`、业务 `outcome/state`、`commandId` 和恢复提示。中文消息仅展示；客户端不靠中文匹配判断失败。审核不可用、内容违规、人工待审、供应商执行未知必须分开。既有 AI 输入失败退配额与模型已启动后的 UNKNOWN 保护均保留。

### 6.6 开关与发布安全

优先复用现有配置，记录开关 owner、作用域、默认值、审计和回退行为。以活动/会话/订单为稳定分组，不能对共享团队成员随机分配不同 runtime。

开关可以停止新建会话、特定新写或新外部派发；必须保留状态查询、原回执读回、回调接收和受控恢复。不能把进行中的新 runtime 会话自动切进旧 runtime；只能由原解释器继续、暂停待补丁，或走独立批准的数据转换。

当前无旧小程序兼容负担：联调候选绑定后端 SHA/JAR、schema、配置和小程序构建；新合同统一上线。保留能力/合同版本用于环境错配诊断，不建设全面版本兼容平台。其他已登记调用者必须完成合同测试后才能切换。

## 7 可分工施工包

以下估算为设计、实现、相关测试和评审的人日范围，不含等待审批、供应商联调、历史数据调查、上线观察和未知返工。每个包仍应拆成可独立回退的小 PR；不是一次性大重构授权。

### WP00 基线和启用范围冻结

- **责任与范围：**集成人维护候选 SHA、工作树状态、依赖版本、部署/数据库身份、业务启用清单和本轮证据索引；校正 AGENTS.md 中的旧技术栈描述。源码、运行环境分别取证。
- **实施：**登记所有当前客户端与高风险端点；从真实映射生成入口清单，不直接采用材料中的 24 个端点计数。盘点 outbox/inbox/intent 的生产调用者、状态、恢复者和金额影响。
- **前置：**无。工时 1–2 人日。
- **验收：**每个后续工单绑定相同基线、实际源符号与启用范围；无法访问的环境列为缺口，不填通过。
- **回退/风险：**仅文档和清单；不改业务。不得更新他人工作区或拉旧私有历史进入公共仓库。

### WP01 自动架构约束和行为安全网

- **责任与范围：**测试/架构负责人拥有架构规则、精确违规基线、CI 集成；领域负责人提供最小业务夹具。候选位置 `ci/architecture/` 和现有测试目录，尚未创建。
- **实施：**先接入第 8 节规则；从现有业务测试补缺口，核心用例先红后绿。ArchUnit 为默认的测试依赖建议，须按仓库规则单独批准并验证 JDK/测试框架适配；未批准时先运行已有脚本可支持的清单/SQL/合同门禁，不自制复杂字节码框架。
- **前置：**WP00。工时 2–4 人日。
- **验收：**人为制造跨域写、依赖环、漏测试报告、基线增量等负例，CI 确实失败；删除负例后通过。现有违规逐项记录 owner/退出条件，不能大包忽略。
- **回退/风险：**测试规则可以独立回退，但不能修改 baseline 把新增业务风险消音。测试放哪一模块不是主要门槛，真实运行和断言才是。

### WP02 提现回补资格与资金证据

|---|---|---|
| A01 模块公开边界 | 字节码依赖检查；显式模块映射，初期支持旧技术包的 owner 清单 | 新增跨域 internal/Mapper 依赖，或新生产类没有 owner |
| A02 数据写权 | 解析 Mapper XML、注解 SQL；动态 SQL 的代表性渲染/真实 SQL 捕获补足 | 未声明写者；跨域字段写未经过公开命令；无法解析的新增写未登记审阅 |
| A03 依赖方向 | 模块图 SCC、注入图分别生成；Spring context 验证实际装配 | 新增模块环、扩大既有环；仅加 @Lazy 不算消除依赖 |
| A04 控制器职责 | 新增/修改命令入口须映射应用用例；存量精确基线 | 新业务事务/Mapper 编排绕过用例；不是全仓立即零违规 |
| A05 危险写契约 | 端点清单登记作用域、身份、前置条件、回执、恢复；行为测试 | 新危险写缺一项；不能以所有 POST 都有注解代替分类 |
| A06 资金原子性 | MySQL 故障点、并发、账本守恒测试 | 业务效果与终态回执分离、原身份被释放、重复经济效果 |
| A07 恢复与栅栏 | 领域处理器复用合同测试：claim、过期、接管、旧 owner 完成 | 旧 token 可写终态；UNKNOWN 自动重发；关键事件无持久恢复源 |
| A08 状态与错误合同 | 允许迁移/权限矩阵、状态 DTO 合同、拒绝后数据库读回 | 非法状态可写；业务失败仅由中文串判定；拒绝仍有副作用 |
| A09 客户端调用一致 | 方法/参数/错误结果/能力合同与当前调用者测试 | 新客户端可发送缺身份命令；超时自动换新键；旧响应覆盖新状态 |
| A10 SQL 和资源预算 | 热点 SQL 计数、执行计划、缓存容量、执行器队列压力测试 | N+1 随输入增长、无界缓存/排队、权限过滤在优化中丢失 |
| A11 迁移与数据真实状态 | 复用 ledger/checksum/schema/data assertions/UNKNOWN 阻断 | 改已有 migration、checksum 漂移、历史 UNKNOWN 未核对、实际结构不符 |
| A12 测试实际执行 | 复用 `ci/assert_it_ran.py` 等报告读回，按工单要求断言用例清单 | 必需测试缺失、skip、环境不可达却当成功；只看 mvn 退出码 |
| A13 候选一致性 | release manifest 校验源码 SHA/tree、JAR、配置版本、schema、客户端构建 | 不同分支/候选的绿项被拼接验收；源版本与运行版本未绑定 |
| A14 公私仓和环境边界 | 敏感信息/生产配置/runner 配置检查、部署权限门禁 | 旧私有历史或秘密进入公共仓库；新增生产部署/持久 runner 未批准 |
| A15 基线不可洗白 | 精确条目 ID、owner、理由、退出条件；CI 不自动 re-freeze | 用全包忽略/自动重建基线隐藏新增问题；无审阅扩大例外 |

ArchUnit 默认采用冻结存量、阻断新增。CI 禁止自动创建/重置冻结库；收缩 baseline 需要可审阅差分，不把 baseline 文件设成任意 PR 可随意覆盖的通行证。ArchUnit 检查 Java 依赖；MyBatis SQL 写权、反射配置和运行时调用需额外证据。

候选清单建议最少两份：`module-owners`（模块、API、写表/字段、例外）与 `command-contracts`（端点、owner、权限、动作身份、版本、原子事实、回读/恢复、测试 ID）。名称可顺应现有仓库风格，字段不能省略。不要另建与现有 action ledger 重复的一套小程序动作清单，应关联现有条目。

## 10 可观测性和资源目标

### 10.1 首轮目标与量测口径

| 项目 | 拟采用验收目标 | 量测与限制 |
|---|---|---|
| 经济效果重复/越权 | 0 容忍；任何一例立即停止相关新写 | 按业务唯一身份对账，不靠 HTTP 错误率 |
| 核心命令服务端延迟 | 建议 p95 ≤800ms；p99 与超时率一并记录 | 指定硬件、数据量、并发和端点；不含用户思考/渠道等待；未达标先定位，不能减校验 |
| 可自动重试通知/投影 | 建议 p95 延迟 ≤30s，最老待处理项有告警 | 延迟从业务提交到持久送达；UNKNOWN/人工态独立计量，不能剔除后称全部达标 |
| 已接受但未终态命令 | 每项有年龄、owner、下一步；超过领域期限告警 | 按 commandId/订单身份统计，进程重启不丢失 |
| 可用性 | 首先记录每域有效请求的成功/拒绝/系统失败/UNKNOWN；再制定 SLO | HTTP 200 中的业务系统错误也统计；合法拒绝/重复回放单列 |
| 故障发现 | 注入关键异常后建议 5 分钟内出现可定位告警 | 告警包含稳定 ID、候选、错误分类，不含敏感正文 |
| 缓存/连接/执行器 | 明确容量与饱和拒绝行为，无无界增长 | 项数和字节同时量测；资源总额必须满足 VPS 准入预算 |
| 备份恢复 | 首次演练量出实际 RPO/RTO，由业务 owner 确认可接受值 | 未实测不承诺固定恢复分钟数；包含恢复后的业务一致性 |

单纯 5xx 比例和日志数量不能反映资金正确性。所有告警必须有 owner、调查入口、允许重试条件和处置步骤。新建指标优先复用现有设施，不采购新的监控服务。

### 10.2 影子对照限制

新旧查询对照先在测试夹具和固定数据库快照执行；需要真实运行采样时另行按环境授权执行。候选查询必须无业务写、无外部计费、无锁定副作用；限流、超时、采样、返回大小和日志大小均有上限。

比较器固定排序、空值、时间精度和作用域；预期差异逐项登记理由，禁止宽泛 ignore。客户端无旧用户不影响用旧实现作测试 oracle，但旧实现本身可能错误，必须同时以人工确认的业务集合/规则断言判定，不能以“与旧错误一致”验收。

不把资金、奖励、核销、新建订单做双写影子执行。金额变更只能执行一次权威路径，候选只能读取事实或在隔离回放中验证。

## 11 验证与回归矩阵

测试层级必须匹配问题：纯函数/Mock 用于规则；MySQL 用于唯一约束、隔离、CAS、事务、故障恢复；真实 HTTP 用于安全过滤和协议；真机用于当前小程序实际交互与微信能力；供应商沙箱或经批准的真实业务测试用于外部最终结果。H2 或返回 JSON 存在不能替代 MySQL/业务读回。

本文件“拒绝无副作用”指业务实体、经济账本、权益和外部动作不得发生未授权变化；允许并应验证脱敏拒绝审计、限流和已登记的安全控制计数。不得为了测试零写入而删除安全审计。

### 11.1 关键故障矩阵

| 用例 | 注入/输入 | 必须证明的结果 |
|---|---|---|
| T01 提现未知结果 | 超时、PROCESSING、迟到 SUCCESS、渠道实际受理却返回 SYSTEM_ERROR、5xx、暂时 NOT_FOUND；执行双人复核 | 未知不可回补或改号重派；原身份可查；迟到成功不被覆盖；错误分类不能绕过事实门禁 |
| T02 自动回补原子性 | 回补余额写后事务失败、终态前故障、提交成功响应丢失 | 要么一起回滚，要么回读唯一既有回补；自动/人工竞争不加两次余额 |
| T03 扣款证明 | 未扣款、扣款事务回包丢失、冻结、身份不符；已扣款但有唯一执行者未提交证明 | 不凭 status 推定已扣款；合法未提交可唯一回补；无证明不回补；拒绝无业务副作用 |
| T04 四路支付身份 | 正确验签下错 appid/mchid/currency/amount/order/transactionId | 每路均拒绝且订单、权益、资金零变化；正确事实各生效一次 |
| T05 回调竞争 | 同回调并发、退款早到、成功后迟到失败、lease 接管、旧 owner 完成 | 终态单调符合合同；同事实一次生效；旧 fence 不能写入 |
| T06 正金额结算 | 合法订单/履约/快照；缺快照；不同 scope；退款后重算 | 合法案例真正增账且守恒；重复不增；不合法拒绝；冲销有原明细关联 |
| T07 章节意图 | 顺序重放、并发同键、不同键同 expected、过期 expected、首末章、队长移交 | 原意图只推进一步；不合法目标/缺字段拒绝；其他队伍无变化 |
| T08 玩法命令身份 | 同键异输入/改变 expected、新 attempt 同答案、缺键、执行后版本又变化 | 同键异参数拒绝；合法已执行回执仍可读；不重复事件、不吞合法尝试 |
| T09 客户端未知结果 | 提交后断网、页面/进程重建、迟到响应；A 未知后退出、B 登录 | 原意图原参数恢复；不自动造新 key；旧账号命令绝不以新账号重发 |
| T10 完成语义 | 经典/个人/团队共享/重玩/新版本/兜底/照片待审/未核销/离队退款 | 逐项事实、统计和奖励资格符合定义；不能全部写成一个 completed |
| T11 查询影子与回填 | 固定快照新旧查询、游标翻页、回填中断再启动 | 集合和作用域可解释；无重复遗漏；回填幂等且不触发经济效果 |
| T12 广播投递 | 模板缺失/false/异常/响应丢失/重复任务/部分通道成功 | 只按证明记送达；恢复未成功通道；未知授权不盲消耗 |
| T13 进程/租约故障 | 提交前、提交后派发前、外部成功本地 ACK 前、ACK 后分别终止任务进程 | 无丢失的已接受意图；无假成功；重启后原身份恢复；旧 worker 被栅栏拒绝 |
| T14 机械移动行为等价 | 同一夹具执行旧/新用例，覆盖权限与异常 | 响应语义和数据库效果一致；仅明确注册的不稳定时间/ID可归一化 |
| T15 三项变更演练 | 新玩法局部规则、新通知通道、新统计查询 | 所属域及公开适配范围内完成；其他域内部写侧零修改；依赖不恶化 |
| T16 资源有界 | 多于缓存上限的不同路线、长单项、并发淘汰、慢 provider、大列表 | 内存/线程/连接有界；降级不污染缓存；SQL次数符合预算 |
| T17 权限与租户 | 匿名、用户A/B、切号恢复、商家A/B、主理人/成员、app/admin token错入口 | 不可读/写他人数据；重放不泄露旧响应；业务效果零变化，安全审计可核验 |
| T18 审核/AI 未知 | 审核服务异常/违规/待审；模型启动前失败/启动后超时 | 分类稳定；保留已修输入失败退额度；已可能计费时原收据 UNKNOWN、不盲重试 |
| T19 故障隔离 | AI/地图长时间超时，消息毒任务，调度领导者失联 | 支付和状态读回不被耗尽；任务积压可见；恢复不重复经济效果 |
| T20 备份恢复 | 隔离库恢复时关闭外部派发；模拟备份后渠道已成功但本地意图丢失 | 核对备份点后的渠道事实/原编号/ID高水位，未查明保留UNKNOWN；对账后才恢复派发；RPO/RTO实测 |
| T21 迁移发布回退 | schema 前态、失败中断、重复执行、UNKNOWN、回退 JAR | ledger 和真实结构一致；原单可读可恢复；不用删除资金数据解决冲突 |
| T22 并行集成 | 两个不相交任务并行、共享合同单一合并、构建最终候选 | 无覆盖他人变更；冲突按业务语义处理；同一 SHA 验收完整 |

“终止进程”只允许测试所有者在精确任务资源上实施。不能将故障注入命令指向真实生产、其他任务的服务或整个 VPS；不得以全局 prune/清库/重启 Docker 替代实验隔离。

### 11.2 全业务覆盖清单

核心矩阵之外，WP17 按启用清单检查以下端到端闭环。每个入口覆盖正常、权限拒绝、重复请求、异常读回；未启用能力明确标记，不以“未测”填通过。

| 用例组 | 场景 | 读回和异常收场 |
|---|---|---|
| B01 内容与发布 | 草稿→保存→审批→发布冻结版本→用户读取；发布中编辑/撤回 | 发布快照不受未发布草稿污染；旧会话仍绑定原版本 |
| B02 活动与报名 | 创建→报名→名额占用→支付→取消/到期；满额并发 | 名额、订单、退款和权益一致；未知付款有查证入口 |
| B03 核销与商户 | 商户范围、票券/权益核销、重复扫码、离店后重放 | 归属正确、只核销一次、客户端不虚报成功 |
| B04 俱乐部治理 | 成员加入/退出、主理人移交、团队协作、角色切换 | 按已批准规则校验；移交前后权限一致，迟到命令不能越权 |
| B05 社区与审核 | 发帖/评论/媒体审核→发布→编辑→删除；迟到审核回调 | 回调绑定原内容版本，不能复活已删或覆盖新内容；投影可恢复 |
| B06 漫游与奖励 | 任务、徽章、成长/积分、重复领取、活动关闭 | 奖励唯一，失败可查；统计重建不重复发放 |
| B07 消息与已读 | 发送、分页、已读、发送和清未读并发、成员被移除 | 未读按授权语义正确；被移除者不可读取；禁用通道不丢已接受意图 |
| B08 账户和隐私 | 冻结/退出登录/注销条件、历史订单查询、撤权后重放 | 保留必须的资金审计，隐私数据按既有批准策略处理；不创造默认放行 |
| B09 后台运营 | 审核/人工复核/查询/导出/操作审计 | 操作范围、双人要求、敏感字段、审计和实际结果一致 |
| B10 商家订阅/语音等剩余能力 | 验证材料中的 upsert/续期/voiceId 恢复线索及当前实际调用 | 若确认缺陷：续期由唯一业务身份和到期规则控制；语音生成以原请求/供应商任务查回，未知计费不重发 |

对 B10 不先承诺“加唯一键即可解决”：新增唯一约束前必须确认重复历史数据、续期叠加规则和真实业务身份；voiceId 缺失也不能自动判为供应商未执行。

## 13 发布门槛与停止规则

| 门槛 | 必需证据 | 不能作为替代 |
|---|---|---|
| G0 基线 | 源码 SHA/tree、当前调用者、数据库目标、启用范围、工单 owner | 历史截图、另一分支测试结果 |
| G1 源码与合同 | 架构门禁、业务单测、端点/状态合同、依赖和影响审阅 | 行数、设计模式数量、代码生成成功 |
| G2 CI 与数据库 | 同候选构建、相关 MySQL IT 实际执行、权限/并发/恢复断言 | HTTP200、JSON 存在、被跳过的 IT |
| G3 VPS 运行 | 目标 JAR/hash/schema/config 独立读回；重启恢复/资源预算 | “进程在运行”、actuator 外层成功包装 |
| G4 当前客户端与外部能力 | 当前小程序联调/真机核心旅程、已登记其他端合同、渠道允许范围内结果读回 | 微信上传、单张截图、模拟供应商成功 |
| G5 发布和业务验收 | 用户批准的发布范围、部署/微信发布实际状态、业务验收签署及回退证据 | push/merge/CI 绿或只完成体验版 |

**立即 No-Go：**重复经济效果、金额不守恒、越权/租户泄露、UNKNOWN 被自动当失败重派、已接受关键命令不可定位、破坏原业务身份、候选/schema 不匹配、必需回归缺失。禁止通过关闭校验、删除台账、修改测试期望或扩大 baseline 规避。

**可以延期但须登记 owner 与验收期限：**未触及正确性的大类拆分、非热点读模型、包目录迁移、未启用组件清理、尚不需要的水平扩容。延期不能冒充已完成，也不能让有资金后果的统计误差混入普通性能债。

回退执行顺序：停止受影响新意图 → 保留读回/回调/对账 → 核对在途身份与外部状态 → 选择数据兼容的安全版本或前滚补丁 → 逐笔读回和恢复 → 解除开关。若涉及备份恢复，先关闭外部派发并核对备份点后的渠道事实及 ID 高水位，缺失区间未查明不得恢复派发。新旧消费者同时派发、清空 UNKNOWN、重建付款号都不是回退手段。
