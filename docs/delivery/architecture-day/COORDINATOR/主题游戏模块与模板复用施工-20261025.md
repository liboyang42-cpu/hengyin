# 主题游戏模块与模板复用：四项批准范围

用户最新要求是**全部游戏**复用及给各 agent 完整施工目的；总方案见[全游戏资源库与主题复用完整施工方案](全游戏资源库与主题复用完整施工方案-20261025.md)。本文件保留四项原合同和答题样例，不能将其当成全部游戏的交付清单。

## 授权与边界

用户在本聊天批准：把完整主题内容单元、发布与运行绑定、模板组件合同、发布前组合校验四项纳入施工；复用原 A–H 云端会话，root 唯一集成。特别要求复用已经完成的选项答题等玩法，不因新主题重新实现一套。

这是四个业务结果，不是批准新建四个框架。原完整 WP00–WP17／Q1–Q10／A01–A15／T01–T22／G0–G5 不缩减，`all_complete=false`。既有资金修补保留；新主题施工不继承旧候选绿色，全部必要源码、调用者、装配和测试收齐后统一验收。

## 1. 主题、模板和引擎的职责

| 单元 | 应拥有 | 不能据此新建或绕过 |
|---|---|---|
| 主题／游戏内容包 | 剧情、地图与节点、规则参数、道具与结局、实际模板绑定，以及经审核的发布内容 | 每主题一个 Maven 工程、数据库、Controller、支付或账号系统 |
| 玩法模板 | 复用已有机制的一份题目／选项／表现配置；发布时冻结实际配置 | 为每份新题目创建新的答题引擎；同名配置被当成代码插件 |
| 玩法能力 | 服务端已支持的输入、判定、完成证明、状态作用域和受控效果 | 作者脚本直接写余额、奖励或完成事实；自动加载未知代码 |
| 运行实例 | 引用其实际冻结版本，隔离个人／队伍进度、选择、道具及回执 | 主题更新时静默换规则；跨主题或跨局借用事实 |

模板配置在发布快照中复制并冻结，属于必要的数据隔离；复制判题代码或另造同功能渲染器，才是本轮要防止的重复实现。

现有落点：`cms_topic`／chapter／node → `cms_member_template`；`TopicBundleReviewService` 审核打包；`TopicRoutePublicationCompiler` 解析并冻结模板配置；`GameSession`、`GameRuntimeSession`、`GameStoryState` 承载不同粒度的运行状态。以上是源码落点，不是全主题已经实跑通过。

## 2. 四项工作：先核实已有，再补真实缺口

| ID | 批准结果 | 优先复用 | 交付和验收 |
|---|---|---|---|
| TG1 | 一套内容作为完整游戏发布 | 审核 bundle、现有 publication compiler、原发布门禁 | 明确内容／模板／资源边界和实际生产调用者；已实现的部分保留，不重复建包系统 |
| TG2 | 审核、发布、开局、运行身份可追溯 | 原 contentHash、冻结 JSON、published version、会话快照 | 沿完整事务与调用链核实；如有可达漂移，补最小修法及原身份并发／重放测试；不能用随机 UUID 或当前内核版本补造历史证明 |
| TG3 | 已有玩法成为可发现且强制复用的组件 | `GameplaySupportMatrix`、`GameplayTemplateRules`、现有客户端组件和判定服务 | 选项答题先给出编辑→绑定→编译→渲染→提交→判题→完成事实的真实链；两份不同主题配置须走同一机制，内容和运行状态仍独立 |
| TG4 | 组合错误在发布前拒绝且能定位 | 现有结构、引用、能力及可达性校验 | 坏配置通过真实发布入口被拒绝且无未授权业务副作用；不只检查按钮置灰，不复制第二套判断规则 |

TG3 的能力清单先由真实代码和调用者建立；能从原配置可靠导出的信息，不先新增 `capabilities` 数据库列。声明必须与实际使用一致且实际使用属于服务端支持范围，不能仅凭客户端声明放行。

## 3. 防止 AI 再造已有玩法

每份主题／玩法工单先列四项：现有能力 key、生产实现和直接调用者、可变的内容参数、对应回归用例。选项答题优先核对既有 `qaPick`／`qa` 的 `PICK` 模式及 `playkit-qa` 实际路径；名称相似不足以证明两条路径业务语义相同。

规则如下：

1. 已有机制可表达新内容时，只新增或修改题目、选项、剧情和绑定配置；不添加主题专属判题分支。
2. 外观可以变化，判定、次数、权限、完成证明及奖励资格继续由原权威路径负责。
3. 新需求若确实无法表达，交付具体缺失行为和失败用例，再扩展原组件；不先创建 `qaPick2`、主题专属 Controller 或复制整份引擎。
4. 复用测试应执行实际组件／服务：不同主题题目使用同一实现；错误答案、越权、重复提交和跨局重放仍由原规则拒绝；不能用复制算法的测试证明复用。
5. 不强行合并合同不同的普通答题、题组、剧情选择和偏好调查；先区分“内容不同”与“业务机制不同”。

“核心文件零修改”只是辅助检查；是否复用取决于实际调用链与行为测试。文件变少、注册表存在、grep 没有主题名，都不能单独签收。
