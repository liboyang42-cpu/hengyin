## 17 iOS 审计可复用方案与后端施工增补

### 17.1 来源、适用范围与证据边界

来源为用户提供的 `Chengyin_Ios_System_Architecture_Audit.md`，共 592 行，材料 SHA256：`4ff4af6f43ac833e72eba36c6a30a19ebc46b9ff15e7b3f9b9c0dfae0b7436f2`。重点参考其第 183–355 行职责、异步与错误分析，以及第 445–580 行构建和验收建议。

本次核读的是报告正文，没有独立审计其 iOS 仓库、编译产物或真机。804 个文件、6 个视图错误、重绘风暴和上传永久锁定均为报告作者的结论，不能直接升级为本轮后端的已证实缺陷。该材料未明确固定审计提交 SHA；如实际修改 iOS，须先补齐源码基线、真实调用者和 Apple 工具链证据。

以下增补并入 WP00–WP17、Q1–Q10、A01–A15、T01–T22 和 G0–G5，保留原完整范围，不另造一套架构平台，不新增依赖或扩大生产授权。

### 17.2 直接采用的施工合同

| 增补项 | 实际落地范围与 owner | 必须保持的合同 | 对应既有验收 |
|---|---|---|---|
| IR01 按职责和状态所有权拆大类 | C：游玩 HTTP/应用编排；A：共享场次；D：主题发布；E：冻结编译；G：高级玩法判定；F：依赖约束 | 规则及调用者随职责迁移；一个状态事实保留唯一受控写入口；父类保留明确的事务、锁和回执责任，不能拆出第二个竞争写者 | WP09/10；Q5/Q9；A01–A04；T14/T15/T22 |
| IR02 异步结果绑定原身份与代次 | C/F：当前小程序命令和起草恢复；后端对应 owner 校验原 actor、scope、session、epoch、版本 | 捕获原账号、登录代次、页面/任务代次、场次及动作身份；发送、回调、异常、finally、查回执和重试均校验归属；清理使用原账号原 key | WP05/12/16；Q2；A05/A09；T07/T08/T17 |
| IR03 持久业务身份与工作租约分离 | A/B：资金；D：投递；E：AI；各域维护原意图 | 租约到期只影响执行权，不释放原业务身份、不证明外部未执行；恢复按原号、语义指纹和实际渠道事实推进，旧 worker 写回须被 fence 拒绝 | WP02/03/08/12；Q1/Q3；A06/A07；T01–T03/T13/T18 |
| IR04 错误保留执行阶段及诊断关联 | B/E/F 与对应业务 owner；root 统一错误合同 | 分开记录业务结果、传输/受理证据、恢复动作与展示文案；关联原 requestId/commandId、供应商任务号和候选，敏感 token、正文和凭据不得进日志 | WP12/13；Q3/Q7；A08/A13；T12/T13/T18/T19 |
| IR05 命令与纯查询分开，读取不替换事实 | A/E：路线读取；C：Entry 与 Query；D：发布版本读取 | 兼容 GET 中已有初始化/刷新明确登记为入场命令；新增纯读不能 ensure、刷新零 HP、分配角色、领取任务或伪造 ACTIVE；区分“不适用、无记录、既有状态不可读” | WP06/09/10；Q2/Q5；A04/A05/A08；T07/T08/T11/T14 |
| IR06 工程和证据使用同一源码集合 | F/root：构建、所有权、CI、制品；业务 owner 提供实际调用者 | 新类实际纳入构建、被生产入口调用、装配成功；源码/测试/JAR/jdeps/数据库与当前候选绑定；静态扫描、编译、运行、业务读回分别验收 | WP00/01/15；Q6/Q9；A12–A15；T14/T21/T22 |

IR01 不采用固定“六个模块”或“主类少于 250 行”。禁止仅移动文件、建立服务大集合 Context、用几十个回调传回父类，或通过新接口隐藏反向依赖。应能够独立解释新 owner 的输入、输出、状态写权、外部副作用和失败出口。

IR02 不把任务取消等同于服务端撤销，不把单线程、锁或 actor 等同于跨 await 原子性。若保留全局忙碌指示，旧任务 finally 不能扣减新账号/新页面的计数；优先按具体操作和原代次登记任务状态，避免另建全局计数协调器。

IR04 在现有 AjaxResult/R 和领域错误内增补必要字段，不强制全仓换返回结构。401 按该身份的会话失效合同处理，403 保留权限拒绝语义，不能一律清理登录；数据库故障也不能被归为空数据。执行结果 UNKNOWN 与无法识别的原始状态码分开，后者保留原值并阻断需要确定事实的操作。

IR05 的组合约束：共享局已存在但缺 RUN 等权威记录时，必须明确返回不可用或抛稳定异常；不能把同一个 null 同时解释为“非共享局”，再返回旧个人局。发现这种情况不得补建 RUN 或伪造个人 ACTIVE 来使查询成功。需同时校验当前权限与冻结 TEAM 归属。

### 17.3 明确不采用的建议及替代方案

| 报告建议或推断 | 裁决与替代 |
|---|---|
| pending 超过固定时间即可覆盖；无时间戳的旧记录默认过期；超过重试次数标 Aborted | 禁止。保留原身份、原记录和原始证据；不能证明未提交或渠道终态时保持待核验。人工取消也不能宣称外部已取消；本地停止等待与外部业务终态分开 |
| 网络层统一生成 Idempotency-Key、对失败写请求自动重试 | 禁止每次发送换 key。幂等键在业务动作创建时产生，网络层只传递；服务端校验原归属、原参数与持久结果。是否重试由业务和供应商合同决定，GET 名称也不能证明无副作用 |
| 收到任意 2xx 即 Committed 并清理日志 | 不采用。校验响应结构、业务 outcome、原身份和持久终态；未知、已受理、业务完成及本地已展示分别记账 |
| Tree-sitter 报错即确认编译错误；Apple NOT_RUN 即业务故障 | 不直接定性。以真实编译器确认语法/类型错误；工具不可用记录验证缺口。解析器误报与真实构建错误分开，不用删除校验或改基线洗白 |
| 拆 extension/目录、迁移 Observable 框架即可解决耦合和性能 | 不采用自动结论。目录移动不能代替写权和依赖约束；性能结论须测量实际无关更新、主线程耗时或后端资源争用 |
| 统一 FeatureGateRegistry、城市精选目录、无限放宽点数和快照校验 | 暂不纳入当前后端关键路径。复用现有开关和资源上限；若以后优化点选，只在身份、版本和归属语义仍安全时缩小比较范围。精选城市属于另行确认的产品需求 |
| 固定两三天且极低风险 | 不作为承诺。成本按实际 caller、事务/存储变更、合并冲突和验收缺口估算；共享身份、资金或持久状态迁移按高风险处理 |

### 17.4 已批准业务规则与迁移回退

1. 同一未完成支付首次发起后锁定支付渠道；必须确认原支付关闭，才能新建支付尝试。不能因客户端切换、SDK 超时或一次查无记录直接换号、换渠道或回补。
2. AI 起草结果仍无法确认时，保留原记录及原额度占位；用户明确确认后可另起独立请求，新请求可能再占一份额度。页面明确区分查回原结果与另起请求，不自动重发。
3. 玩家起草只受专用起草额度限制，展示与实际扣减使用同一口径。不能以另一个额度池的较小值拦截合法起草。
4. 小程序无旧用户，不增加 N-1 兼容层；所有当前调用者仍须同步迁移。原业务数据、未知请求、资金记录及服务端回执不能清空。

纯职责迁移先保留旧 facade 作为受控适配，确保原 caller、异常、事务传播及锁序不变，再按实际收益迁移调用者。Facade 不新增业务规则，不允许新 owner 反向调用旧 God Service。每片可独立回退，但存在新持久状态时必须先核对旧版本能否安全读取和恢复；不能承诺一条 git revert 就完成数据回退。

本增补不预设新表、新索引或新的 journal 存储格式。确有缺口时先复用现有领域存储；需要结构变更则另交精确迁移、历史值处理、前后置断言及回退条件，按现有授权执行。新增时间戳为空时保留未知证据，绝不默认“已经过期可覆盖”。

### 17.5 必须纳入统一回归的场景

下表为既有 T 矩阵的细化，不新增平行验收体系。源码批次收齐后按受影响范围统一执行；编写必要场景随实现进行，不为每个小片重复启动全套 CI。

| 场景 | 对应原矩阵 | 通过标准 |
|---|---|---|
| IR-T01 A 请求挂起，退出并登录 B，再释放 A 的成功/失败/finally 回调 | T07/T17 | B 的 UI、busy、pending、缓存和传输层均不被 A 改写；仅允许按原 A 身份受控查回，不能跨号迁移命令 |
| IR-T02 外部已成功、本地响应丢失，跨进程重启并推进超过 lease | T03/T13/T18 | 原身份仍可定位，至多一次经济效果；不自动释放占位或重发；接管后旧 fence 写回失败 |
| IR-T03 同 key 不同输入、不同 expected、不同账号重放 | T02/T05/T17 | 稳定冲突或授权拒绝，业务数据和原回执不被覆盖；合法原回执仍能读取 |
| IR-T04 共享局存在但缺权威 RUN，且该账号保留旧个人局 | T08/T11 | 明确不可读/不可用；不回退旧个人 ACTIVE、不补局、不分配角色，零写入 |
| IR-T05 两个并发任务先后完成，期间切账号/页面代次 | T07/T17 | 各自加载状态正确结束；旧任务 cleanup 不影响新代次，也不令尚在执行的当前任务提前解锁 |
| IR-T06 超时、确定未提交、已受理、权限拒绝、业务失败、数据库错误 | T12/T18/T19 | 错误分类、展示和恢复动作一致，日志能通过原 ID 串联；无 token/敏感正文泄露，403 不被当全局登出 |
| IR-T07 拆分 owner 后从真实 HTTP/Job/callback 入口执行 | T14/T22 | 新 owner 确实参与调用，原业务效果、回执、异常、事务/锁序保持；业务与终态一起回滚；每次死锁重试进入新事务 |
| IR-T08 构建源码遗漏、伪造制品来源、缺报告或新增反向依赖 | T14/T21/T22 | 各负例必须被对应门禁拒绝；恢复正确候选后通过，不能修改存量 baseline 或借另一分支绿项放行 |

上线处理仍依第 13 节：跨账号污染、重复经济效果、未知外部动作被自动重发、读取绕过权限或无法定位已接受关键命令属于相关功能阻断；目录整理、固定行数指标、未启用适配器清理与精选城市不作为本批上线前置条件。

### 17.6 执行与验收记录要求

每项增补在对应原工单中记录 owner、最终源码 SHA、受影响入口/调用者、状态写权、风险、回滚和上述场景的实际结果。root 将跨 A/E 等共享合同的修正串行集成，H 独立复核；F 只对已明确的新 owner 加入可执行增量约束，缺图、缺类或缺实际产物仍标未知。

本节完成代表材料已转化为施工要求，不代表 iOS 已修改、后端已通过或 G0–G5 已关闭。源码集成、Java/真库、当前客户端、供应商和生产发布的完成状态继续分别记账。
