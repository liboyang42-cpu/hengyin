# 五项业务规则与公开方案对照

本轮由用户明确要求核对美团及其他平台。这里只对照公开合同、账单和供应商协议，不是新增全仓库代码审计；没有操作其他 App 的真实订单、资金或声音创建。以下建议结合 Hengyin 当前尚未开放使用、预算受限及需支持多人并行开发的阶段，不宣称存在脱离业务条件的唯一最优方案。

## 结论与施工约束

| 规则组 | 判断 | 本项目采用方式与必要边界 |
|---|---|---|
| 原分项分币 | 保留，适合冻结初始计划 | 原现金权重、最大余数、同余数按报名 ID 稳定排序；原分项总额必须严格守恒，保存计算版本和原分项，不随查询顺序或后续退款重算其他订单。没有查到美团公开其内部使用同一算法的证据。 |
| 部分退款与尾分 | 保留，但区分三种金额 | 原订单、累计差额、每次原分项调整合计等于实际成功退款、全退清余分均已获批准。客户退款、合作方冲回、平台/渠道成本分别记账；不能把某个商家的扣回金额直接当作客户退款金额，也不能未经费用合同就默认所有费用同比退还。 |
| 实际核销席位费与负利润 | 按履约计费合适；人工处置适合当前阶段 | 仅真实核销席位计一次，仍需冻结原费率与收款人。负利润保存原订单/席位/费用/原因及处理状态，禁止夹成零额成功、自动扣余额或押金。人工状态需有可查询记录、处理人和处理结论；它不是永久免除责任，也不等于客户退款未发生。规模扩大后的抵扣/追偿需要另有业务授权。 |
| ASR 与同次 NPC 额度 | 单次用户额度合适；供应商成本口径另算 | 识别前持久预占、只对已证明 NOT_SENT 自动释放、UNKNOWN 保留、同次文本交接不二扣，shop gen 池不变。用户功能额度不能被解释为供应商只产生一次计费；处理中要显示占用状态并保留原身份恢复，不得当作已成功交付或无限期无记录吞额。不新增第二套额度池。 |
| 声音 UNKNOWN 后另起 | 保留为最后的显式选择，先恢复原结果 | 有原 voiceId 时优先查询；没有可靠唯一关联时不能从音色列表猜认原结果。确认新建后使用独立稳定身份，原 UNKNOWN 及回读保留，迟到原结果不能覆盖新选择。提示必须符合实际模型，不能写死“创建必定收费”。 |

以上不变更用户已经批准的金额责任、额度政策和新意图授权；涉及未确认费用可退性或自动追偿的新规则，仍只冻结该依赖点并向用户确认。

## 可直接借鉴的公开证据

1. **美团账单按来源分项，不把收款、服务费、结算与退款混成一个数。** 官方团购账单分别定义 `salePrice`、`serviceFee`、`settlementAmount` 和 `bizRefund`；并区分核销实收与扣手续费后的结算。它支持本项目保留逐单原分项与独立冲回流水，但不能证明美团采用我们选择的分币算法。[美团：分页查询账单流水](https://developer.meituan.com/docs/api/dishconnect-settle-queryByPage)

2. **退款与分账回退是两个相关流程。** 微信支付说明两者没有强耦合，回退以原分账为依据；商户文档也要求累计回退不得超过该接收方原分账额。因此不能用退款成功代替分账回退成功，或因为某次回退未完成就改写客户已退款事实。[微信：补差与分账常见问题](https://pay.wechatpay.cn/doc/v3/partner/4012525463)、[微信：分账常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4014547102)

3. **成熟平台的自动追偿依赖明确合同。** 美团特定卖家责任退款规则允许从后续待结算款中扣除。这证明其采用过有约定的追偿机制，不意味着 Hengyin 当前已经具备相同授权；所以现阶段“持久人工处置、没有授权不自动扣款”合理，不能直接复制大平台的自动扣款。[美团：交易纠纷规则](https://rules-center.meituan.com/m/detail/guize/334001?activeRule=1)

4. **新意图与重试必须区分。** AWS 的幂等设计要求同一请求身份绑定同一语义，参数改变不能静默冒充原请求；这支持原身份查回、明确另起新身份的区分，不能据此宣称第三方声音创建已经支持调用方幂等键。[AWS：Making retries safe with idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)

5. **声音创建不能统一描述为付费。** 阿里云当前公开实践文档说明 CosyVoice 创建音色免费，而 Qwen 系列创建收费；语音合成又有自己的计费。Hengyin 源码 `AiVoiceConfig` 的默认 target/synth model 是 `cosyvoice-v2`，但本轮没有读取运行环境覆盖值，不能据默认值断言线上实际模型。原“可能重复费用”告知应结合实际模型，默认至少说明可能生成重复音色或占用服务资源。[阿里云：声音复刻及声音设计实践](https://help.aliyun.com/zh/model-studio/voice-cloning-and-voice-design)、[阿里云：模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)、[阿里云：声音管理与恢复查询](https://help.aliyun.com/en/model-studio/voice-cloning-user-guide)

## 不能省略的实现边界

- 最大余数用于初始分配后应冻结。退款不能每次对累计金额做一次没有历史下界的全量重排：权重为 5:3:1 时，累计 4 分的最大余数分配是 2/1/1，累计 5 分变为 3/2/0，第三项会从 1 分倒退到 0 分。本次冲回必须尊重已冲回下界、原冻结上界及每次实际退款总额，不能产生负冲回。这是算术反例，不是对美团内部实现的判断。
- 商品/服务费是否可退、实际已履约成本由谁承担，要以原冻结费用合同为依据。不得因当前最大余数算法方便而新增成本承担者，或把已履约成本抹掉。遇到尚无合同的费用类型保留原事实并明确处置。
- UNKNOWN 代表原请求结果待确认，不是已证明失败；不能靠换号、删除记录或自动释放占用来假装恢复。查询和人工处理的结果仍绑定原身份。
- 能查音色列表不等于能够安全认领某一条音色。当前源码默认共享 prefix 为 `chengyin`；仅按这个前缀或相近创建时间匹配，不足以证明归属原意图。
- 这些是规则与实现建议，不是代码、真库、供应商或业务验收通过记录。最终仍绑定同一候选完成原定集中验收。

## 本轮限制

美团公开 API 的部分内容通过官方索引可读取，直接正文抓取存在空页；没有访问其私有算法或内部数据库。迪卡侬相关分币页面抓取返回 403，未将其作为已核验案例。没有读取本项目线上有效配置、真实商户合同或供应商账单；没有执行回归、生产 DDL、真实退款或付费生成。
