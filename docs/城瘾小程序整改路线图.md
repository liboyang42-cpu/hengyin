## 1. 项目总体评价

城瘾已经具备一个完整城市探索小程序的业务骨架：有首页、广场、模板、达人、活动、主题、商家、俱乐部、会员中心、订单、优惠券、提现等模块。产品方向具备潜力，尤其是“探索城市 + 玩家共创 + 商家/俱乐部参与”的组合，适合做本地生活、活动运营和轻游戏化任务平台。

当前最大问题不是功能数量不足，而是功能已经铺得很广，但生产级收口还不够：

- 身份体系复杂：普通玩家、会员、商家、俱乐部、达人之间的边界需要进一步统一。
- 审核风险较高：UGC、评论、图片/文件上传、活动发布、优惠券、商家能力都涉及微信审核重点。
- 权限边界原先不够严：部分接口存在按 id 操作他人数据的风险。
- 开发期 mock 数据混入生产体验：会掩盖接口异常，也会误导用户和审核。
- 产品表达仍不够聚焦：“探索城市 × IP世界观 × 玩家共创”的价值在首页和主流程里还没有完全讲清楚。
- UI 有视觉野心，但新旧页面风格不统一，部分文案还偏“模板/插件市场”，与城市探索产品调性有冲突。

验收标准：

- 后端 `mvn -pl chengyinhub-admin -am -DskipTests compile` 通过。
- 小程序关键 JS 文件 `node --check` 通过。
- 游客/普通用户不能操作商家/他人内容。
- 商家不能核销非自己发布的优惠券。
- 用户不能查看/删除/编辑他人地址。

### 第 2 周：核心流程可用

目标：让普通用户、会员、商家、俱乐部四类角色主流程跑通。

- 普通用户：登录、浏览、搜索、收藏、点赞、发布、报名、退出。
- 会员用户：权益展示、额度限制、续费入口。
- 商家用户：申请、审核状态、资料编辑、优惠券、核销、数据看板。
- 俱乐部用户：申请、加入、成员、发布活动/主题。
- 补空状态、失败提示、重复点击保护。

验收标准：

- 每个角色至少一条完整冒烟路径。
- 所有失败态有 Toast 或页面级空状态。
- 发布/报名/支付不会因重复点击产生重复订单。

### 第 3 周：产品表达和体验升级

目标：让用户看懂城瘾是什么，并愿意继续玩。

- 首页重构为“城市探索任务流”。
- 模板文案改成“任务/玩法/路线/挑战”语言。
- 强化 IP 世界观入口。
- 发布流程拆分为轻量模式和完整模式。
- 俱乐部和商家入口重新分层。

验收标准：

- 新用户 10 秒内能理解产品价值。
- 首页第一屏能表达“探索城市 × 玩家共创”。
- 发布主题/活动步骤减少或分段清晰。

### 第 4 周：商业化和增长基础

验收标准：

- 会员、商家、活动、优惠券有明确商业路径。
