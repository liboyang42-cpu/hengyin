# 全产品修复：用户产品决策（2026-09-13）

来源：本轮用户明确授权。覆盖旧建议和旧待答记录；实现状态以源码、测试与独立验收为准，本文件不是完成证明。

1. 免费自办活动：作者提交时可选择审核通过后开放报名；审核通过且报名时间、名额等满足才自动开放，保留暂停、满员、过期限制。
2. 商家主题合作池：招募信息审核通过且在招募期即可申请和邀约；玩家报名另受开售条件控制。
3. 商家工作包：明确权益或任务、接待时间、容量、核验方式、费用、责任人，由商家确认。履约相关修改重新确认；已有订单保留原合同版本，变更走通知与处理流程。
4. 必须承接的商家退出：暂停新增报名、保留原订单并允许补位；替代商家确认后主办恢复。无法履约由主办取消及退款收尾，不自动取消整场。
5. 提前核销：核销仅记录履约事实，资金按约定履约完成及结算周期释放；误核销走纠错，历史提前核销单独核对，不自动扣回或重发。
6. 售后凭证：绑定具体商家及案件。店主、有案件处理权限的员工可查看和接手；员工离岗立即失权，不对全店员工开放。
7. 历史无归属凭证：可靠案件或上传事实证明归属后核验补登记并留审计；无法证明要求重传，显示待补材料，不猜归属。
8. 玩家等级：主页与成长中心统一服务端玩家成长体系。创作者等级、信用等级使用明确不同名称；历史积分和经验不清零。
9. 创作者驳回：允许修改重报、新审核轮次，保留原因和历史；重复点击不能重复申请。
10. 模板使用：含义是使用模板提供的游戏，遵守可编辑与不可编辑边界。优先查现有模板合同，缺字段规则再问。未授权拆成续编原稿和复制新作品。
11. 竞猜揭晓后新玩家：显示本轮结束及公开结果，不再下注或承诺本轮奖励；允许继续不依赖竞猜奖励的基础路线。原合法参与且未结算记录按事实处理，不清除。
12. 反应挑战：创建、编辑、服务端统一支持120–3000ms；旧2500ms正常编辑，不静默截断。
13. 商家与俱乐部主理人互斥。**用户最后追加已决定时点：正式启用商家身份前先完成主理人移交；移交完成后清除其主理人身份，再启用商家身份；无接任人暂不完成切换。** 俱乐部不删除，原订单、资金、历史记录及责任保留，不清空、不免除。旧身份隔离并存方案作废。
14. 玩家现金补偿（历史处置规则，须同时遵守第18条）：此前用户允许有明确来源记录的现金补偿提现，沿用收款信息校验、审核和到账跟踪；仅开放该资金能力，不赋予商家/财务权限，积分另算。不能据此推定未来客诉由平台先行垫付，也不能据本地测试样板推定生产已有赔付；历史余额、明细保留核验。
15. 同场多队：同一人同场只能一个有效队伍；允许明确换队，保留个人权益和记录；团队任务归属遵守活动规则。
16. 路线下架：停止新发现和新报名；历史参与者可查看订单及履约必需内容；普通公开旧链接显示下架。删除、违规处置与下架分开。
17. 主动中途离场不退款。其他离场资格、操作和团队影响查既有合同；不得扩展到主办取消，不把暂停、返回页面或断网认定主动离场。
18. **客诉退款资金顺序（用户后续明确）：平台不先行垫付现金。应由责任方直接退给玩家；若因支付通道设计必须经平台处理，应先由责任方将资金退到平台，再由平台退给玩家，属于同一售后流程，不先付后追。** 实现必须先核对原订单实际收款与资金归属，避免重复扣责任方或重复退玩家；资金未实际落实、玩家退款未成功时不得显示成功。此规则替换旧代码的“客诉先行垫付后追偿”设计，不新增哪些情形应额外赔偿、赔偿金额或责任比例的规则；不删除售后入口或保留无恢复路径的禁用状态。

19. **补位商家只按一次合同计费（用户明确回复）：同一玩家在同一工作包已由商家 A 接待，A 退出后由 B 补位再次接待，保留 A 已履约应收，B 不再从原票重复计费，不新增主办补足费用。** 两次真实接待事实与责任记录均保留；计费人数及保底计算不得重复计入同一份履约权益。此决定不裁定“主办责任退款时，其他已正常履约商家的固定服务费与保底是否保留”这一独立待答问题。
