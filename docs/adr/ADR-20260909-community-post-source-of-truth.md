# ADR-20260909：以 `community_post` 作为专业广场唯一写入真源

## 状态

已接受（本地实现，待迁移与发布验证）。

## 背景

旧 `UmsCreativeSquare` 足以承载简单图文动态，但无法可靠表达草稿与复审、受众、评论权限、媒体归属、编辑历史、推荐/搜索资格、规范版本、梯度处置和申诉。继续在旧表和控制器上叠加条件会让列表、详情、审核和 App 各自形成不同事实。

## 决策

新版 App 的广场帖文写入和读取统一使用 `/api/v1/community` 与 `community_post` 聚合。旧广场接口保留为迁移期兼容面，不再承接新能力，也不与新表做双写。

帖文生命周期由 `ICommunityPostService` 单一入口执行，使用 `version` 乐观锁；内容安全门禁和平台审核仍复用现有 `AuditTask`，通过 `COMMUNITY_POST` 类型回写新版生命周期。举报复用既有 CommunityTrust 案件真源，处置与申诉使用新版可逆记录。

## 后果

- 好处：写入真源唯一，审核不会绕过；Feed、详情和关系屏蔽共享同一 SQL 可见性策略；编辑、删除和处置均可审计。
- 代价：上线前必须冻结旧写入并先执行新迁移；迁移脚本一次性回填旧帖、互动、评论和附件，回读不过不得切源，不能靠运行时双写补齐。
- 非目标：本决策不包含生产执行、部署、视频转码或推荐模型训练。

## 验证

以生命周期单测、真实 MyBatis/H2 可见性测试、API surface 契约、迁移结构与 readback 契约作为仓库内证据；生产是否可用仍必须由迁移回读和部署制品自报分别确认。
