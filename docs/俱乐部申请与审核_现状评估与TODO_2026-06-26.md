## 0. 结论速览(TL;DR)

- **闭环已通(但口径要改)**:现有代码是 `小程序申请 → club.status=0 → 后台通过/驳回 → role 升/降`,三端齐全。**按新决策(填完即有)要改成**:`申请提交 → 直接 status=1 + role→club → 后台异步定 L1–L5`,不再有"待审/驳回"闸。
- **真正缺的是「评估层」**:你设想的 8 大板块里,**基础身份/成员/定位**已覆盖约 30%,而**能力评估(L1–L5 依据)、商业合作、安全保障、自动标签、等级**——后端表无字段、后台无 UI、小程序无采集,**完全空白**。
- **拆成两个流程(本次新增)**:A「成为俱乐部主理人」=身份资格(重档案,L1–L5 挂这里)+ B「创建自己的俱乐部」=实体(轻量,一人可建多个)。现 `pages/club/apply` 把两者混在一个表单,需拆开。能力档案/等级挂**主理人**,俱乐部继承展示。
- **不要一次做全**。三层切分(申请人填 / 系统自动 / 后台人工定级);A+B 同期做,认证/商业/安全(M3)后置。
- **两个一上来就该补的硬伤**:① 申请表**没有「城市」必填**(城瘾是地理强相关产品);② 等级/标签字段在 DB 里不存在,后台审核员现在**只能通过/驳回,无法定级打标**。

## 3. 设计要点(动手前先对齐)

### 3.0 两表单结构(决策①:身份 vs 实体 拆开)
| | **A. 成为俱乐部主理人(达人身份)** | **B. 创建自己的俱乐部** |
|---|---|---|
| 性质 | 身份资格,一人一次 | 实体,一人可建多个 |
| 重量 | **重**——能力/信誉档案 | **轻**——填完即有 |
| 字段 | 实名、身份说明、联合创始人、过往组织经验、**能力评估(最大人数/路线设计/带NPC/商家合作/导游证·旅游资质)**、(M3)商业/安全 | 名称、Logo/封面、**城市(必填)**、类型(单选大类)、简介、关键词、风格、活动方向 |
| 产出 | 达人身份 + **L1–L5 定级**(挂此) | 一个俱乐部(`status=1`) |
| 落库 | **新表 `club_leader`**(member_id 唯一) | `club` 表(member_id **1:N**) |
| 审核 | 填完即有,L1–L5 异步定级 | 填完即有 |
| 入口 | 玩家:"成为俱乐部主理人"(一次) | 达人:"创建俱乐部"(可重复) |

> 要点:能力档案/等级收在**主理人**,俱乐部只继承展示 →「质检一次,建团随便建」,与「达人可建多个俱乐部」一致。现 `pages/club/apply` 一个表单**混了这两件事**,需拆开。

### 3.1 三层数据,不要堆成一张大表
| 层 | 谁产生 | 落点 | 例子 |
|---|---|---|---|
| ① 申请人自报 | 小程序填 | club(实体) / **club_leader(能力档案)** | 名称、城市、类型、关键词、风格、能力自评、资质上传 |
| ② 系统自动 | 规则算 | club.tags(可改) | 🟢校园 / 🔵商业 初判(由 club_type 映射) |
| ③ 后台人工定级 | 审核员敲 | **club_leader**.level + audit_by/time | **L1–L5**、最终标签(挂主理人) |

> **铁律**:L1–L5 与能力档案里的"是否能带NPC/最大人数"等,自报只作**证据**,**等级一律由审核员看完案例后人工敲定**(已与你确认:纯人工后台)。

### 3.2 L1–L5 人工定级量表(后台审核员参照)
| 等级 | 含义 | 人工判定参照(看申请材料) |
|---|---|---|
| **L1** 新手组织 | 真实存在,尚无成熟活动 | 资料真实、无/极少案例 |
| **L2** 稳定活动 | 能稳定办轻活动 | 有过往活动证据(caseImages)、experience≥1-5场 |
| **L3** 成熟路线 | 有路线+任务设计能力 | 案例充足,具备固定路线/任务设计(能力字段或案例佐证) |
| **L4** 城市运营者 | 多场次、可带角色/NPC、可商家联动 | 能带NPC、能与商家合作、活动规模可观 |
| **L5** 区域策划方 | 商业执行+资质+安全保障 | 商业任务+品牌经验+导游/旅游资质+保险/应急机制 |

落库:`club.level TINYINT 默认0(未定级)`,审核通过时由后台下拉选择。

### 3.3 类型字段(决策③:合并为一个)
不再维护 org_type / clubTypes 两套。统一为**单一「俱乐部类型」字段族**:
- **主字段 `club_type`(单选大类)**:校园社团 / 旅行组织 / 兴趣社群 / 商业活动组织方 / 内容创作团队 / 其他 —— 既是分类,也是**自动标签来源**。
- 现有多选项(社交/城市探索/户外运动/摄影…)**降级并入**为该类型下的「活动方向/兴趣标签」,不再作为独立"类型"字段。
- 迁移策略:复用现有 `club_types` 列承载活动方向,新增 `club_type`(单选大类)承载主分类;DB 不留两套"类型"语义。

### 3.4 自动标签(初判,审核员可改)
提交时按 `club_type` 单选大类映射初始 tag:校园社团→🟢 / 兴趣社群→🟡 / 商业活动组织方→🔵 / 内容创作团队→🟣;存 `club.tags`,后台可覆盖。

### 3.5 等级对外展示(决策⑦:继承主理人等级)
L1–L5 挂在主理人(`club_leader.level`),俱乐部卡片/详情**继承展示其主理人的等级**(同一达人名下多个俱乐部显示同一等级)。需定**对外文案口径**(建议:L1 新手 / L2 稳定 / L3 成熟 / L4 城市运营者 / L5 区域策划方,或星级 ★),`level=0`(未定级)时不显示徽标。

### 3.6 转化率红线:申请轻、认证重
- **申请阶段(小程序,≤10 项)**:够审核员判断"真不真、值不值得聊"即可 → 加 **城市(必填)、风格、关键词、能力自评(几个是/否)、资质上传**。
- **认证阶段(通过后再补)**:商业合作、安全保障、保险、品牌经验 → 引导到"申请成为官方认证俱乐部"二级门槛,别堵在首次申请。
