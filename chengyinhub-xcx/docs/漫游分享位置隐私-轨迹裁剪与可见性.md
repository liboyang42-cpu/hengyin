# 漫游分享位置隐私:轨迹裁剪 + 发布可见性

2026-08-27 · 小程序(chengyinhub-xcx)· 参考 Any Distance「Clip route for sharing」/ Slopes「Always Keep Location Private」/ Strava「Visibility」

## 为什么做

漫游足迹卡把 `track` 原样画出来。轨迹的**第一个点是用户按下 GO 的位置**,通常是家门口;
最后一个点通常是回到家。分享到广场 = 把住址发到广场。

这不是美观问题,是位置隐私事故 —— 而且是**默认发生**的:用户不做任何操作就会泄露。
所以裁剪默认**开启**,要泄露必须用户自己去关。

## 默认值(改这里之前先想清楚后果)

| 项 | 默认 | 范围 | 存储 |
|---|---|---|---|
| 裁剪开关 `clipEnabled` | **开** | 开 / 关 | `wx.storage` key `roam_share_privacy` |
| 裁剪比例 `clipPercent` | **10%** | 1% – 40%(超界一律夹回) | 同上 |
| 发布可见性 `visibility` | **公开** | `public` / `friends` / `private` | 同上(分享 sheet 里的临时切换不落盘) |

- 「没设置过」和「存储读不出来」都退这套默认值 —— 隐私闸不因存储故障而失效。
- 比例按**点数**裁,不按里程。漫游按固定节奏采点,起终点附近停留久、采点密,按点数裁对「家门口」这一段裁得更狠,方向是对的。
- 裁完剩不下 2 个点时返回**空轨迹**(卡上显示「这次没有记录到轨迹」),**绝不回退成完整轨迹** —— 回退就是把隐私闸变成恒绿的假保证。

## 影响面(哪些图会变)

裁剪只作用在**分享产物**上,自己回看的完整轨迹不动。

| 位置 | 谁算的 | 变化 |
|---|---|---|
| 漫游结算 → 分享 sheet 预览 + 导出 canvas + **广场发帖那张图** | `pages/roam/index.js` `_calcArch()` | 首尾各裁 `clipPercent%` |
| 本次漫游回看 → 分享足迹卡预览 + 导出 canvas | `subpackageRoam/session/index.js` `_route()` | 同上 |
| 漫游正文里的路线回放(`cy-scene-roam-session`) | `components/cy/scene-roam-session/route-replay.js` | **不裁**。那是自己看自己的记录,裁了没有意义 |
| 漫游历史列表 / 地图揭雾 / 打卡上报 | — | 不涉及,本次没碰 |

两条分享链路各自缓存过 segs,所以打开分享时都**重算一次** —— 否则用户刚在设置里调完比例,
分享出去的还是上一次设置下的那条轨迹。

## 发布可见性:只做客户端真能兑现的三档

后端 `/api/creativesquare/action` **没有可见性字段**(`UmsCreativeSquare` 只有 `status 1显示/2隐藏`,
由机审写)。往请求里塞一个 `visibility` 后端会直接丢掉 —— 那就是个假保证,比没有开关更坏。
所以这三档做成**渠道闸**,每一档只放行它真能兑现的东西:

| 档位 | 放行渠道 | 用户读到的承诺 |
|---|---|---|
| 公开 | 广场 · 朋友圈 · 小红书 · 保存 | 发到广场,全站可见 |
| 仅好友 | 朋友圈 · 保存 | 不进广场,只通过微信转发给好友 |
| 仅自己 | 保存 | 只存到相册,不发布到任何地方 |

- 置灰只挡手指;真拦截在 `shareTo()` 里(`isChannelAllowed`),automator/深链直接调也拦得住。
- Strava 的「Mute Activity:不进 feed 但保留在主页」在城瘾没有对应物 —— 广场就是 feed,
  而漫游记录本来就永久留在本机的「我的漫游历史」,不受分享影响。这一层用「仅好友/仅自己」
  + sheet 里那句「本次漫游记录始终保留在『我的漫游历史』,不受这里影响」承接。
  要做成后端可见性(真·仅好友可见的广场帖),得先给 `ums_creative_square` 加可见性列 + 好友关系过滤,
  那是③迁移 + 后端改动,不在本次范围。

### 一个真踩到的坑

第一版把置灰写成 `{{share.channels.indexOf('广场') >= 0 ? '' : 'is-off'}}`。
data 层断言全绿,但**四个渠道一起置灰** —— WXML 表达式里带中文字面量的 `indexOf` 恒返回 -1。
只有 automator 回读渲染出来的 `class` 才抓得到。现在判断留在 JS(`channelFlags`),模板只读布尔,
并有一条契约测试钉死「分享 sheet 的置灰不许再用 WXML indexOf」。
