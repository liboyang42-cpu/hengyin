# 玩法段配置页 · 设计手册

`pages/publish/temp` —— 商家配玩法模板的那一页。选择器统一展示 32 个主玩法和 10 个可叠加玩法，不再单列“高级玩法”。主玩法共用 27 个配置段；九宫格在主题级配置。可叠加玩法在现有分类中添加，配置留在玩法模块内，关闭开关即移除；添加时保留主玩法及其他已选配置。相册暂不支持叠加，限时挑战仅供支持计时的主玩法添加。
这份手册只讲「一个新段该长什么样」。

> **手册会烂，门禁不会。** 强制判据在
> [`tests/unit/temp-editor-section-shape-contract.test.js`](../tests/unit/temp-editor-section-shape-contract.test.js)，
> 与本文冲突时以门禁为准。本文只回答门禁不会告诉你的那一半：**为什么**。

## 先看这个骨架

新段从这儿复制，别从最近改过的那一段复制 —— 你不知道那一段是不是刚好欠着债。

```wxml
<view class="cg-gcfg" wx:if="{{gameSection === '你的段名'}}">
  <view class="cg-adv-body">
    <view class="cg-cfg-label">标题</view>
    <input class="cg-cfg-input" value="{{advanced.你的段名.title}}" placeholder="例如 …"
           data-section="你的段名" data-field="title" bindinput="onAdvancedField" />

    <!-- 两个数字字段凑一行;只有一个就别用栅格,按整行写 -->
    <view class="cg-adv-grid">
      <view><view class="cg-cfg-label">甲（范围）</view><input class="cg-cfg-input" type="number"
            value="{{advanced.你的段名.a}}" data-section="你的段名" data-field="a"
            data-numeric="1" bindinput="onAdvancedField" /></view>
      <view><view class="cg-cfg-label">乙（范围）</view><input class="cg-cfg-input" type="number"
            value="{{advanced.你的段名.b}}" data-section="你的段名" data-field="b"
            data-numeric="1" bindinput="onAdvancedField" /></view>
    </view>

    <view class="cg-cfg-hint">这个玩法整体是什么。105 字以内。</view>
  </view>
</view>
```

## 六条规则，和它们各自的事故

每条后面那句不是设计偏好，是已经发生过的事。

**R1 · 外壳固定 `cg-gcfg > cg-adv-body`。**
自造结构 = 这一段的留白、分隔、滚动全都各走各的，商家在段之间切换时界面会「跳」。

**R2 · `cg-adv-grid` 是两列，不准只放一个字段。**
它是 `repeat(2, minmax(0,1fr))`。只放一个，右半边就是空的。2026-09-22 取景轮廓那一段
把「轮廓浓淡」单独塞进去，整段竖着看成了 **半幅 → 两列 → chips → 半幅**，用户的原话是「很乱」。
只有一个字段就按整行的 `label + 控件` 写。（比值该用滑块这条已独立成 **R7**，见下。）

**R3 · 单条 hint ≤ 105 字，解释某个控件的话放那个控件正下方。**
同一段里 photoCheck 的 hint 一度攒到 128 字，而它开头解释的「取景轮廓」在 5 个字段之外 ——
读到那句时早忘了在说哪个。段末的 hint 只留「这个玩法整体是什么」。

**R4 · 只放一个媒体位的 `cg-qmedia` 必须带 `--one`。**
`.cg-qmedia` 的子项是 `flex:1`，那是给「配图 + 音频」**两个位并排**设计的（题干附件那段）。
单个位套上去 = 一整行 160rpx 的灰块，视觉重量压过它上下所有单行输入。
一个「位」= 一对 `wx:if` / `wx:else` 孪生节点，不是两个位。

**R5 · 「选填」只有一种写法：`· 选填`。**
原型真源 `docs/design/节点玩法模板_模板编辑页v2.html` 写的是 `lab('拍完给一张贴纸 · 选填')`。
现有配置标签已统一为间隔号，新增段也沿用这一写法。

**R7 · 归一化比例量（百分比 / 浓淡 / 透明度 / 占画面宽）必须用 `<slider>`，不能用数字输入框。**
比值的具体数字对商家没意义，只有手感 —— 让人为了调个透明度去敲数字键盘是反直觉的。
`slider` 的 `bindchange` 同样给 `e.detail.value`，`onAdvancedField` 原样能收，**不用加 js**。

⚠️ **判据是「这个数对商家有没有独立意义」，不是数值跨度。**
2026-09-23 量过现码 54 个 `type="number"`：跨度最大的三个是 `目标步数`（99900）、
`允许误差（毫秒）`（4950）、`倒计时长（秒）`（3595）—— 它们**天然就该是数字框**
（你得敲 10000 步，拖滑块拖不出来）。按跨度卡会把这批全误伤，而真正该抓的
「占画面百分比」（跨度 80）正好夹在中间。所以门禁认的是**词**不是**数**：
`百分比 / ％ / % / 浓淡 / 透明度 / 不透明度 / 占画面 / 占屏 / 比例`，外加「0 至 100」这种百分制区间。

**R6 · 段里必须真的有 label + 至少一个可填控件。**
段名进了 `gameSection`、玩法单子上点得进来、进来却什么都配不了 ——
本仓最爱踩的「一端建好、另一端没接」在编辑页的样子，**而且不报错**。

## 长相之外：新段还要接的线

门禁 R1–R6 只管长相。下面这些是**数据**，各有各的门禁，漏了同样不报错：

| 要接的 | 在哪 | 谁在看 |
|---|---|---|
| 段进 `parse` / `normalize` / `defaultConfig` | `pages/publish/utils/publish/advanced-game-config.js` | `advanced-game-config-v51` |
| 存 → 读回不丢字段 | 同上 | `publish-temp-v51-roundtrip`、`advanced-game-config-roundtrip` |
| 呈现方式默认档（内嵌 / 整屏） | `PRESENT_INLINE_DEFAULT` / `PRESENT_FULLSCREEN_ONLY` 两端各一份 | `publish-present-choice-contract` |
| 服务端校验 | `AdvancedGameConfigValidator.java` | 后端单测 |
| 运行时投影 + 公开投影 | `AdvancedGameRuntimeServiceImpl` / `AdvancedGamePublicProjection` | 后端单测 |
| 新控件进台账 | `npm run audit:actions:update`（**commit 前最后一步**） | `action-ledger` |

⚠️ **呈现方式那一栏别漏，而且两条路都要想清楚。**
故事流的每一段都恒带 `transform: scale()` + `filter: blur()`（值永远是数字、不是 `none`），
非 `none` 就是 `position: fixed` 后代的**包含块** —— 内嵌时，任何整屏浮层都会被圈进那
190rpx 的段落里，还跟着一起被缩放和模糊。

所以整屏浮层类的段有两个选择，二选一，**不能两个都不选**：

1. 进 `PRESENT_FULLSCREEN_ONLY`（`reaction` / `ballShake` / `countdown` / `stopwatch` /
   `quietHold` / `coinFlip` / `hiddenObject` / `scan` / `steps` / `compass` 走的是这条）；
2. 组件自己收 `inline` 属性，内嵌时降级成不需要整屏的那条路
   —— `photoCheck` 走的是这条：内嵌时不进页内取景，直接走选图，玩法照常能完成。

2026-09-22 实测：`photoCheck` 两条都没做，而 `.pcv` 写死了 `position: fixed`，
作者配一个 `present: 'inline'` 的拍照节点就会撞上。
仓里 `play-stage` 早为同一件事开了 `--pk-stage-pos` 注入点，新写的浮层绕过了那套机制。

## 统一后的约束（2026-09-26）

单字段半行、括号版选填标签、百分比数字框三项欠账均已清零，测试上限同步归零。
多行输入统一使用 `cg-cfg-textarea`，不能套单行的 `cg-cfg-input`。
开关行的名称和开关左右对齐；重复项统一标题行、右侧删除图标、下方字段和虚线添加按钮。
输入、下拉和多行文本在同一配置面板内使用相同底色；重复项用 `gap` 控制间距，不叠加输入框下外边距。
两列布局仅用于适合并排填写的字段；一个字段或开关行使用整行布局。
九宫格保留主题级说明面板，不增加本来不存在的节点配置。

全目录覆盖由测试从 `node-game-catalog.ALL` 动态枚举，不以抽查几个玩法代替全部入口。
