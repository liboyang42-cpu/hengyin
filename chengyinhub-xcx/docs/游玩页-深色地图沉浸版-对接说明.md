## 0. 视觉 token(全站统一,严格使用)

- 唯一橙 `#FC4C02`(图钉/路线/主 CTA 全站只用这一个橙)。
- 深色面:底 `#0a0300` / 面 `#1c1310` / 面2 `#251b18`;地图底 `#15100d`、街道 `#241a15`。
- 文本:`#ffffff` / 次 `#a08a82` / 正文 `#c9b8b0`;发丝线 `rgba(255,255,255,.08)`。
- 字重只用 400/500;主 CTA 圆角 24px 实心橙;禁渐变/重投影/霓虹/纹理。
- 手记自有暖色阅读系:正文 `#d8c9c1`、轻标签 `#a08a82`、沉降渐暗 `#8a7872→#3f342f`、焦点橙标 `#FC4C02`。

## 结构总览(单页多屏叠加)
- 常驻:深色 `<map>` + cover 浮层(章节条 / 模式切换 / 缩放回中 / 左下手记浮窗 / 底部下一站卡 / 通关 banner)。
- 叠加全屏 `view`(wx:if 切换):章节过场 intro、节点半屏卡 sheet、游戏启动页 A、游戏进行 B、徽章颁发、券 toast、手记文字流 journal、通关足迹卡 finish。
- map 上唯一能盖住的浮层用 `cover-view`/`cover-image`;半屏卡/全屏屏用普通 `view` 盖在 map 之上(可用全部动效)。

## 双模式(共用骨架,只改解锁规则 + 图钉态)
- mode=1 城市定向:线性,按 sortId;上一站未完成 → `pin_lock`,点击弹叙事浮层「这扇门还没向你敞开…」;下一站=下一个未完成 sortId。
- mode=2 自由探索:无锁,全 `pin_go`/`pin_done`;下一站=离玩家最近未完成节点;任意图钉可展开。

## 四层结构与游戏
- 主题 → 章节(name/description/imgArr,有的只有文字)→ 节点(name/description/坐标/imgUrl/checkinCode/templateId 可空)→ 游戏模板 CmsMemberTemplate。
- 有 templateId 的节点 = 一个游戏;无模板节点 = 纯文字停靠点(读完即到达完成)。
- 游戏完成方式来自模板 `validationMethod`:4 扫码 / 1 文字题 / 3 选项题 / 拍照(photoRequireDesc)。
- 游戏启动页 A:封面 imgUrl/storyImg + title + chips(⏱duration ◇difficulty 👥players)+ storyText 引文 + 可折叠 ruleInstructions + requiredMaterials + 「开始游戏」。
- 游戏进行 B:按 validationMethod 分支;hint1/hint2 逐级解锁;答错给 feedbackText(橙字);连错≥2 且有 answerReveal → 「揭示答案」兜底;audioUrl 作线索 chip。
- 完成:advanceProgress(幂等+发分)→ 盖章 + 「+N 分」飞入 + 震动 → medalName/medalImg 徽章颁发层 → couponId 券到账 → 回地图点亮、解锁下一步。

## 旅程手记(Tesseract 纯文字流)
- 入口:左下浮窗(与右下缩放镜像)。整屏纯文字流,无卡片/边框/列表,只有文字+留白+极淡分层。纵轴=旅程进度。
- 三态:沉降的过去(完整叙事按离焦点距离渐暗)/ 焦点的此刻(最亮+橙标+「前往此站」)/ 雾中的前路(mode1 实文模糊 + 远段 ░ 遮蔽防剧透;mode2 「尚未书写」淡色可点)。
- 重惯性 + 弱吸附(停滚 ~130ms 后向最近段心移动仅 30%,允许停半段,不强制分页)。
- 纵深视差:bindscroll 按段心与视口心距离实时算 opacity/scale/blur。
- 写入融入动画:地图完成节点 → 手记对应段 `解雾+fade-in+slide-up`(writeIn 0.9s),进度条 +1。
- 顶部仅章名+进度条;返回是流末端一行文字。长流虚拟渲染,blur 仅少数雾段,视差 setData 节流到一帧一次。

## 接口对接点
| 动作 | 接口 | 入参(gcj02) |
|---|---|---|
| 进入主题 | `GET /api/play/detail` | `themeId` → 返回 mode/chapters/nodes/total/doneCount/chapterSeen + 模板呈现字段 |
| GPS 到达 | `POST /api/play/arrive` | `themeId,nodeId,longitude,latitude` |
| 扫码到达 | `POST /api/play/checkin` | `themeId,nodeId,code` |
| 答题 | `POST /api/play/answer` | `themeId,nodeId,templateId,answer` |
| 通关分享 | `wx.shareAppMessage` / 发广场 | 足迹卡参数 |

安全:敏感答案 `questionAnswer/correctAnswer/checkinCode` 不下发前端,校验全在后端;`/api/play/nodes` 随节点下发模板**呈现字段**供启动页渲染。

## 容错
- getLocation 失败/拒授权 → `gpsOk=false`,下一站按钮变「扫码到达」,围栏停用,不白屏。
- 断网 → 用本地缓存的 nodes/章节图仍能看图走位;到达请求进重试队列。
- 节点多 → marker 聚合。

## 动效清单(替换所有 wx.showToast 灰字)
图钉盖章 stamp 0.32s / 进行中 pulse 1.6s / 飞分 fly 1.1s / 到达震动+sheetUp 0.4s / 章节过场 Ken-Burns + 文案上浮 / 扫码 scanline 1.3s / 徽章 stamp+glow / 手记 writeIn / 通关 confetti 30 片 + 足迹卡(route-map 截图)。全程零 system toast,反馈用 震动/盖章/飞分/叙事浮层。

## 上线前置 / 运维清单(定位相关)

1. **mp 后台开通「地理位置接口」**:开发 → 开发管理 → 接口设置 → `wx.getLocation`(精确地理位置)申请开通。用途文案:用户参加城市探索活动,游玩页需实时显示自身位置并在走到节点 50m 内自动到点打卡,故需 `wx.getLocation` + `wx.onLocationChange`/`wx.startLocationUpdate`。仅授权后使用、不上传第三方、不留存轨迹。审核通过后账号级生效,**无需重新发版**。
2. **用户隐私保护指引加「位置信息」**:开发管理 → 用户隐私保护指引,必须含「位置信息(用于活动推荐与到点打卡)」一项。缺项时即便接口已开通,`wx.getLocation` 仍会被隐私协议拦截。
3. **坐标系全链路 gcj02**:代码取 `type:'gcj02'`,后台录入节点经纬度也必须 gcj02(高德/腾讯系地图选点)。任一环节用 wgs84/bd09,50m 围栏会整体偏移 100–500m,表现为"站在门口却判定没到"。
4. `app.json` 已声明:`requiredPrivateInfos` 含 `getLocation`/`onLocationChange`/`startLocationUpdate`,`permission.scope.userLocation` 已带 desc(代码侧完成,无需再改)。
