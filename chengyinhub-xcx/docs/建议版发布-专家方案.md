# 城瘾「建议版发布」完整专家方案

> 目标:在现有专业版发布流之外,新增一条**单页、低门槛**的"建议版"发布流。
> 点【发布主题】→ 弹窗二选一(专业版 / 建议版)。建议版面向普通玩家,数据预填、一屏完成。
> 决策已定:① 可减站不可加站 + 允许加 1 个文字集合点;② 路线库由运营从 web 后台人工录入。
>
> 本方案所有"现状"结论均来自当前代码核对(标注文件:行),不是推断。

---

## 0. 现状盘点(代码实证,先看 6 个事实,否则会重复造轮子)

| # | 事实(代码位置) | 对建议版的意义 |
|---|---|---|
| 1 | **创建主题只有一个出口**:`POST /api/topic/create`,payload = `{name, subtitle, description, startDate, endDate, imgUrl, imgArr, categoryIds, chapters[], collaboratorIds, tickets[], openMerchantPool}`(`pages/publish/fabu/index.js:1832`) | 建议版**不新建创建接口**,只在前端把"选择结果"拼成这个结构提交 → 后端创建逻辑零改、详情页零改 |
| 2 | 后端 `createTopic`(`CmsTopicServiceImpl.java:848`)对**自办主题**(`openMerchantPool!=1`)调 `generateSelfHostActivity`,自动生成 `status=1/publishStatus=1` 的**已上架可玩活动** + 复制票(`copyTopicTicketsToActivity`,ownerType=2) | 建议版固定自办 → **发完即生成可报名/可游玩的活动**,报名/支付/核销/游玩链路全部零改动 |
| 3 | 保存节点时自动写 `node.checkinCode = UUID`(`CmsTopicServiceImpl.java:1017`) | 建议版的站点天生带扫码打卡码,**扫码通关闭环自动成立** |
| 4 | **已有"公共模板库"**:`CmsTemplateLibrary` + `ApiTemplateController`(`/api/template/list`、`/my-list`、`/homeData` App Store 风格)。但它是**节点级玩法模板**(验证方式 扫码/问答/反馈、优惠券、时长、难度、人数) | 这是"运营预置共享内容库"的**现成先例**,但层级是**玩法**,不是**路线**。玩法库可复用,**路线库要新建** |
| 5 | 章节带 `routeGeometry`(`TopicChapterVO.java:18`),前端用各章节 geometry 现拼路线(`topic/index/index.js:911+`,无后端 polyline 字段) | "路线几何"算法已存在可迁移;但**减站后需要重算 geometry**,这是后端真实缺口 |
| 6 | 已有 RBAC + 配额:发布入口 `onHeroTap`(`talent/list/index.js:173`)先查 `/api/role/info` 校验 `canCreateTheme`、`maxThemes` vs `usage.themes`;`roleGuard.js` 是单一权限事实源 | 建议版**直接挂这套 RBAC + 配额**,不另起权限系统 |

**一句话**:建议版在工程上 = **前端一个新单页 + 一个分流弹窗 + 后端一套"路线预设 CMS"**。创建链路、详情页、报名、游玩、权限、审核全部复用。真正的新增成本在**后端路线预设库 + web 后台录入工具**。

## 1. 当前为什么"太复杂"(客观数字)

`pages/publish/fabu/` = 2526 行 JS + 913 行 WXML,3 个 Tab,要求普通用户在一页里同时扮演 5 种角色:

| 角色 | 要填 | 字段量 |
|---|---|---|
| 活动策划 | 主题名/副标题/简介/故事/起止时间/分类/封面/图集 | ~8 |
| 路线设计师 | 章节 → 节点(名称/描述/**地图选点经纬度**/图片/停留时长/营业时间) | 每节点 ~13 |
| 游戏设计师 | 给节点绑互动模板(扫码/问答/反馈) | 另一套表单 |
| 票务经理 | 多票种(名称/价格/库存/4 个时间选择器/集合点/退款/同步) | 每票种 ~10 |
| 商务 | 合作者 / 商家池开关 | ~3 |

> 一条最朴素主题(1 章节 + 3 站点 + 1 票种)≈ **60+ 个离散输入项**。普通用户在"第二个站点地图选经纬度"时大概率放弃。

**核心矛盾**:发布流是专业工具,却把入口摆在了所有玩家面前。解法不是砍功能,是**分流人群** —— 专业版一字不删,建议版把"创作结构"降维成"做选择题"。

## 2. 建议版产品定义

- **入口**:点【发布主题】→ 弹窗二选一。建议版默认高亮推荐,专业版给主理人/商家。
- **形态**:**单页**,从上到下一屏滚完(非多步向导)。
- **预填**:进页即带默认风格 + 默认路线 + 默认文案,**用户什么都不改也能直接发**。
- **第一性原理**:普通用户**不创造结构,只做选择题**。结构(路线/站点/玩法)由运营预置,用户只填"我的那一份"。

### 单页结构(从上到下)

```
┌────────────────────────────────────────────┐
│ ① 主题风格   [卡片横滑] 选 1(默认已选第一个)      │
│ ② 城市路线   [路线卡 + 地图缩略] 选 1(默认已选)    │
│              展开站点清单,每站可 [✓/✗] 减站       │
│              [+ 添加我的集合点] 仅 1 个文字地址     │
│ ③ 我的信息   标题(预填可改)                       │
│              活动时间(唯一必填)                    │
│              票:○ 免费   ○ 一口价 [¥__  名额__]   │
├────────────────────────────────────────────┤
│            [ 预览 ]          [ 发布 ]             │
└────────────────────────────────────────────┘
```

> **用户最少必做动作 = 1 个(选活动时间)**,其余全有默认值。预览页直接复用现有主题详情 UI。

## 3. 权限设计

| 维度 | 专业版(现状) | 建议版(新增) |
|---|---|---|
| 准入角色 | merchant / club / 达标 player | **全部登录用户**(含普通 player)—— 降门槛是建议版全部意义 |
| 发布配额 | 走 `maxThemes` | **同一配额池**(计入 `maxThemes` 防刷;如需可单设更宽松上限) |
| 节点上限 | `maxNodesPerTheme`(玩家 Lite=2) | 建议版站点来自路线库,**不受单主题节点配额拦截**(由路线决定);仍可设软上限 |
| 内容来源 | 用户自创 | **仅能选运营预设**(风格/路线)+ 自填标题/时间/票/1 集合点 |
| 审核 | `status` 走后台审核 | 建议:**免审或秒审**(主体是运营已审的预设),仅对标题/集合点做敏感词过滤 |
| Web 后台权限 | — | **新增运营角色:路线预设管理员**(CRUD 风格/路线),与小程序用户权限隔离 |

**权限原则**:建议版用户只有"选择权",没有"结构创造权"。这既是 UX 简化,也是内容安全护栏 —— 用户改不了路线/玩法,平台内容可控。

> 落点:`onHeroTap` 的 `/api/role/info` 预检对建议版放宽(`canCreateTheme` 对 player 也放行),专业版维持原校验。

## 4. 功能清单

**P0(Must-have)**
1. 发布弹窗分流(专业版 / 建议版)
2. 主题风格选择(读预设)
3. 城市路线选择 + 减站 + 加 1 个文字集合点(读预设)
4. 标题 / 活动时间 / 票务(免费 or 一口价)
5. 预览(复用现有详情 UI)
6. 提交 → 映射成 `/api/topic/create` payload

**P1(可延后)**
- 风格 = 视觉换肤(接已有 `--cy-` token 主题机制,选风格即切 token 组)
- 给预设站点绑**已有玩法模板库**(复用 `CmsTemplateLibrary`,用户只做开/关)
- 埋点区分:`analytics.track('topic_publish_success', {publishMode:'simple'})`
- 运营提效:把爆款专业版主题"一键沉淀为预设路线"

## 5. 前端还差什么 & 怎么改

| 缺口 | 现状 | 怎么做 |
|---|---|---|
| 发布分流弹窗 | `onHeroTap` 直接跳 `topicadd→fabu` | 在 `talent/list/index.js:onHeroTap` 角色预检**通过后**,弹自定义二选一层;建议版走新路由,专业版走旧路由 |
| 建议版页面 | 无 | 新建 `pages/publish/simple/index`(单页);**不碰 `publish/fabu`** |
| 读预设接口 | 无 | 新增 3 个调用:风格列表 / 路线列表 / 路线详情(站点),见第 6 节 |
| 选择态 → 提交体映射 | 无 | 写 `buildTopicPayload()`:把 风格/路线/减站结果/集合点/标题/时间/票 拼成现有 create payload,见第 7 节映射表 |
| 视觉换肤(P1) | token 机制已就绪 | 每个风格挂一组 `--cy-`,选中即给页面根加 `.theme-xxx` |

**前端工作量级**:1 个新单页 + 1 个弹窗 + 3 个只读接口 + 1 个映射函数。**不动后端创建逻辑、不动详情页/报名/游玩。**

## 6. 后端还差什么 & 怎么改(核心增量在这里)

建议版真正成本 = 后端一套**路线预设 CMS**(3 张表 + web 后台 CRUD + 小程序只读 API)。

### 6.1 新增数据表

```
preset_theme_style    主题风格
  id, name, cover_img, tone_tokens(JSON:一组 --cy- 色值),
  default_title, default_subtitle, default_desc, default_category_ids,
  sort, status

preset_route          城市路线(运营录入)
  id, city, name, preview_img, route_geometry(沿路坐标 JSON),
  total_distance, total_time, default_category_ids, sort, status, created_by

preset_route_node     路线站点(隶属 preset_route)
  id, route_id, name, address, longitude, latitude, img_url,
  node_time(建议停留), sort, play_template_id(可选,绑已有玩法模板库)
```

> 站点经纬度 / route_geometry 与现有 `CmsTopicNode` / `TopicChapterVO.routeGeometry` 同形,几何算法可直接迁移复用。`play_template_id` 复用现有 `CmsTemplateLibrary`,**不新建玩法表**。

### 6.2 新增 API(小程序只读)

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/preset/style/list` | 风格卡片列表 |
| GET | `/api/preset/route/list?city=` | 路线卡片列表 |
| GET | `/api/preset/route/info?id=` | 单条路线含站点(供减站) |

### 6.3 复用现有 API(关键:别改创建链路)

- 创建仍走 `POST /api/topic/create`。**唯一需要改的现有接口**:加一个可选字段 `publishMode = simple|pro`,用于 ① 建议版走免审分支 ② 配额/分析区分。后端在 `createTopic` 里据此决定 `status`(simple→秒审通过)。
- 自办活动自动生成(`generateSelfHostActivity`)、节点 `checkinCode`、票复制 —— **全部已有,无需动。**

### 6.4 Web 后台(运营端,最大开发项)

新增模块「建议版内容管理」:
- 风格 / 路线 / 站点的增删改查、上下架(`status`)、排序;
- **路线录入需地图打点工具**:运营在 web 上点出站点 → 存经纬度 → 调路径规划生成 `route_geometry`;
- 减站重算:小程序端减站后,要么后端提供"按保留站点重算 geometry"能力,要么前端退化为**节点直连**兜底(画直线)。

## 7. 数据映射表(建议版选择 → `/api/topic/create`,工程对接直接用)

| create 字段 | 建议版来源 |
|---|---|
| `name` | 用户填(默认 = 风格 `default_title`) |
| `subtitle` / `description` | 预设默认(风格/路线文案),不改即用默认 |
| `startDate` / `endDate` | 用户选的活动时间(`endDate` 可由 `start + 路线 total_time` 推算) |
| `imgUrl` / `imgArr` | 路线 `preview_img` / 风格 `cover_img` |
| `categoryIds` | 预设带默认(风格/路线 `default_category_ids`),用户不选 |
| `chapters[]` | 由选中路线生成**单章节**:`nodes` = 勾选保留的 `preset_route_node`(带坐标),`routeGeometry` = 减站后重算或直连兜底;加的集合点作为第 1 个 node |
| `tickets[]` | 免费 → 单张 0 元票;一口价 → 单张 `{name:'报名', price, totalStock}`,`mode=2`(自由前往) |
| `collaboratorIds` | 固定 `[]` |
| `openMerchantPool` | 固定 `0`(自办)→ 触发自动生成可玩活动 |
| `publishMode`(新增) | `'simple'` |

> **结论**:建议版产出的就是一条标准 topic,后端自动补出可玩活动,详情页/报名/支付/核销/游玩/我的发布**全部无感复用**。

## 8. 落地路线图(分期)

- **第 0 期(前置 · 运营+后端,关键路径)**:建 3 张预设表 + web 后台 CRUD + 地图打点工具 → 先人工录 1~2 个城市 × 各 3~5 条路线 + 4~6 个风格 + 配套文案。**没有这一步建议版就是空壳。**
- **第 1 期(前端 MVP)**:发布弹窗分流 + `publish/simple` 单页 + 3 只读接口 + `buildTopicPayload` 提交;`create` 加 `publishMode`;建议版走免审。
- **第 2 期(打磨)**:风格视觉换肤接 token 机制;埋点区分 simple/pro;减站后路线重算优化。
- **第 3 期(运营提效)**:专业版爆款主题"一键沉淀为预设路线";给预设站点绑玩法模板库。

---

## 9. 风险与边界

1. **预设内容是命脉**:库太空 → 没东西可选;路线质量差 → 体验崩。运营产能 = 建议版上限,需先评估录入人力。
2. **减站后路线连贯性**:减掉中间站,`route_geometry` 要能重算,否则地图断线。后端需提供重算能力或前端直连兜底。
3. **配额防刷**:门槛低,务必计入 `maxThemes` + 标题/集合点敏感词过滤。
4. **免审边界**:用户可填自由文本(标题/集合点)是风险点 → 机器敏感词 + 事后抽审。
5. **两版数据一致**:都落同一张 topic 表,报表用 `publishMode` 区分,否则分析失真。
6. **自办双重曝光(遗留)**:自办主题在主题列表 + 活动列表都出现,建议版会放大此现象,需产品定调展示口径(见业务链路记忆)。
