# 小程序 UI 全量复查方法

目标是发现问题并留下可复现证据，不把“脚本通过”写成“页面无 Bug”。

## 1. 固定基线

- 记录 commit、分支、开发者工具版本、后端地址、测试账号和数据库填桩批次。
- 重新生成 `scripts/fixtures.json` 与 `scripts/selectors.json`；生成后再次运行生成器，结果必须稳定。
- 运行单元测试、`ci/xcx-check.sh` 与 `git diff --check`。

## 2. 296 状态矩阵

- `scripts/shot-matrix.js` 是截图场景真源。
- 正常、加载、空、错误、权限、长值、弹层和滚动深层分别取证。
- 内容态不能只断言页面根节点。关键名称、金额、状态和按钮使用 `textIncludes` 验证可见文字。
- `forbid` 验证不应同屏出现的空态、错误态或骨架。
- 夹具字段必须来自页面或目标组件真实消费字段；被列入 `dropped` 的字段不算证据。

截图结果只允许：`ok`、`state-unmet`、`blank`、`near-blank`、`stale`、`frame-defect`、`error`。任何非 `ok` 都进入问题台账，不通过降低断言消除。

## 3. 人工视觉复核

逐图核对：

- 主题、导航、标题、返回出口与安全区
- 对齐、间距、截断、重叠、滚动位置和弹层遮挡
- 图片比例、加载失败、空值、长名称和小屏
- 按钮优先级、禁用态、提交中、结果未知和恢复动作
- 是否出现工程术语、测试词、蓝色开发提示或与用户无关的解释

## 4. 业务走查

按游客、玩家、商家、俱乐部主理人、协作者分别实跑主链和异常链。资金流程至少覆盖报价、建单、支付结果未知、取消、退款申请和结果查询；本地填桩只能证明非生产链路。

账号切换后检查缓存、草稿、分析队列和敏感数据是否串号。上传失败后确认本机临时路径不会进入请求。

## 5. 真机边界

定位、地图底图、相机、扫码、手机号、微信支付、退款、订阅消息和系统权限必须真机验证。没有真机证据时在台账标为 `unverified`，不得改写为通过。

## 6. 闭环

每个问题记录：编号、角色、页面、复现步骤、期望、实际、证据、修复 commit、自动测试、开发者工具复测和真机状态。修复后重跑负控，证明门禁在故障重新出现时会变红。
